# Responses API 概览

Responses API 目前是 Crazyrouter 上较新 GPT 能力的主要接口之一。

本页面仅记录了在 `2026-03-22` 上与生产环境再次验证的结论。

<Note>
  在当前经生产验证的适用范围内，Claude 仅支持 `POST /v1/messages` 和 `POST /v1/chat/completions`，不支持 `POST /v1/responses`。Responses 页面以 GPT 为主要指导对象。
</Note>

## 当前适用场景

- 如需可检查的推理输出，优先选择 `/v1/responses`
- 如需类似 OpenAI 的网页搜索，优先选择 `/v1/responses`
- 如仅需普通聊天或希望保持现有集成，`/v1/chat/completions` 依然可用

## Responses API 与 Chat Completions API 对比

| 维度 | Responses API | Chat Completions API |
|-----------|---------------|----------------------|
| 接口终点 | `/v1/responses` | `/v1/chat/completions` |
| 输入结构 | `input` | `messages` |
| 输出结构 | `output[]` 项列表 | `choices[].message` |
| GPT 推理 | 已验证 `reasoning` 项 | `reasoning_effort` 可用，但 `reasoning_content` 不稳定 |
| OpenAI 风格网页搜索 | 已验证 `web_search_preview` 路径 | 旧版 `web_search` 结构在本轮测试中未产生稳定可验证触发 |
| 流式输出 | 更丰富的事件类型 | 传统增量 SSE |

## 最小有用示例

```python Python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="https://api.crazyrouter.com/v1"
)

response = client.responses.create(
    model="gpt-5.5",
    input="Explain what a REST API is in one sentence."
)

print(response.output_text)
```

在本次生产环境复查中，这样的最简请求返回了：

```json
{
  "object": "response",
  "output": [
    {
      "type": "message"
    }
  ]
}
```

## 何时优先选择 Responses

- 你需要 `gpt-5.5` 推理摘要
- 你需要验证模型实际是否触发了 `web_search_call`
- 你想获取更丰富的 SSE 事件

## 何时保留 Chat Completions

- 你已有稳定的 Chat Completions 集成
- 你只关心最终答案，不关注 `reasoning` 项
- 你在集成 Claude、Gemini 或其它 OpenAI 兼容模型

<Note>
  两个 API 可以在同一个项目中共存。实际应用中，更好的方式通常不是完全迁移，而是仅将需要新能力的请求迁移到 `/v1/responses`。
</Note>
