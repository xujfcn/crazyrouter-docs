## 基本用法

<CodeGroup>

```bash cURL
curl https://api.crazyrouter.com/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-5.5",
    "input": "Which is larger, 9.11 or 9.9? Explain briefly.",
    "reasoning": {
      "effort": "high",
      "summary": "detailed"
    }
  }'
```

```python Python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="https://api.crazyrouter.com/v1"
)

response = client.responses.create(
    model="gpt-5.5",
    input="Which is larger, 9.11 or 9.9? Explain briefly.",
    reasoning={
        "effort": "high",
        "summary": "detailed"
    }
)

print(response.output_text)
```


## 验证回应结构

已验证的 `output.type` 值：

```json
["reasoning", "message"]
```

典型的 `reasoning` 项结构：

```json
{
  "id": "rs_xxx",
  "type": "reasoning",
  "encrypted_content": "...",
  "summary": [
    {
      "type": "summary_text",
      "text": "..."
    }
  ]
}
```

最终答案通过 `message` 项返回：

```json
{
  "type": "message",
  "content": [
    {
      "type": "output_text",
      "text": "..."
    }
  ]
}
```

---

## `reasoning` 参数

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `effort` | 字符串 | 推理强度。已验证的值包括 `low`、`medium` 和 `high` |
| `summary` | 字符串 | 摘要粒度。`concise` 和 `detailed` 已重新验证 |

### 实用规则

- 如果您只需要更强的推理，请发送 `effort`
- 如果需要可检查的推理摘要，请同时发送 `effort` 和 `summary`

在当前重新检查中：

- 仅使用 `effort` 时，`reasoning` 项存在，但 `summary` 可能是空数组
- 使用 `summary: "detailed"` 时，`summary_text` 返回稳定

## 提取思考摘要

```python Python
response = client.responses.create(
    model="gpt-5.5",
    input="Design a high-concurrency message queue architecture.",
    reasoning={
        "effort": "high",
        "summary": "detailed"
    }
)

for item in response.output:
    if item.type == "reasoning":
        for part in item.summary:
            if part.type == "summary_text":
                print("Thinking summary:", part.text)
    elif item.type == "message":
        for content in item.content:
            if content.type == "output_text":
                print("Final answer:", content.text)
```

## 思考流式输出

以下 Responses SSE 事件名称已在生产环境重新验证：

- `response.reasoning_summary_part.added`
- `response.reasoning_summary_text.delta`
- `response.reasoning_summary_text.done`
- `response.output_text.delta`
- `response.output_text.done`
- `response.completed`

示例：

```python Python
stream = client.responses.create(
    model="gpt-5.5",
    input="Explain briefly why 9.9 is larger than 9.11.",
    reasoning={
        "effort": "high",
        "summary": "detailed"
    },
    stream=True
)

for event in stream:
    if event.type == "response.reasoning_summary_text.delta":
        print(f"[Thinking summary] {event.delta}", end="")
    elif event.type == "response.output_text.delta":
        print(event.delta, end="")
```

## 当前推荐

- 如果需要可见的推理字段，优先选择 `gpt-5.5` 与 Responses API
- 不要将 `gpt-5.5` Chat Completions `reasoning_content` 作为当前主要协议
- 如果您只关心最终答案，Chat Completions 搭配 `reasoning_effort` 仍可用

<Warning>
  推理模式会增加延迟和 token 用量。更高的 `effort` 通常费用更高。
</Warning>
