## 適用シーン

お客様が各API Keyごとにモニタリングしたい場合は、業務側の`sk-xxx`を直接照会するのではなく、Crazyrouterの管理インターフェースの組み合わせを使うことをおすすめします：

- 現アカウント配下のAPI Key一覧を取得
- 時間範囲、Key名称、モデル名称で呼び出しログを照会
- 特定のKeyの合計消費量を集計
- システムの為替パラメータに基づき米ドル費用に換算

<Note>
  管理インターフェースはユーザー認証を使っており、モデル呼び出しで使う業務トークンとは異なります。
</Note>

<Warning>
  このページのすべてのアカウントや管理インターフェース（`/api/token/*`、`/api/log/*`、`/api/user/self`含む）は、必ず`https://crazyrouter.com`へのリクエストが必要です。`https://api.crazyrouter.com`はモデル/メディアAPI専用で、間違って使うと`404 api_only_endpoint`が返ります。
</Warning>

## 認証方法

管理インターフェースのリクエスト時は、次の2つのリクエストヘッダーが必須です：

```text
Authorization: Bearer {access_token}
New-Api-User: {user_id}
```

- `access_token`：ユーザーログイン後発行されるアクセストークン（コンソール/管理インターフェース認証用）
- `New-Api-User`：現ユーザーID、`access_token`に対応したユーザーであること
- `sk-xxx`：業務呼び出し用トークン、モデル呼び出しにのみ使い、`/api/token/*`・`/api/log/*`など管理インターフェースでは使用不可

## 推奨利用フロー

下記の順序で利用することをおすすめします：

1. `/api/token/`を呼び出して現アカウント配下のKey一覧を取得
2. `token_name`に従い`/api/log/self`を呼び出し、特定Keyの明細ログを取得
3. `/api/log/self/stat`を呼び出して同条件での合計使用量を取得
4. `/api/status`を呼び出して`quota_per_unit`を取得
5. `quota / quota_per_unit`を使って米ドル費用を換算

## 1. API Key一覧の取得

```bash cURL
curl "https://crazyrouter.com/api/token/?p=1&page_size=100" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 485"
```

レスポンス例：

```json
{
  "success": true,
  "message": "",
  "data": {
    "page": 1,
    "page_size": 100,
    "total": 1,
    "items": [
      {
        "id": 409,
        "name": "gptai",
        "key": "sk-xxxxxxxxxxxxxxxx",
        "status": 2,
        "used_quota": 16605808,
        "model_limits_enabled": true,
        "model_limits": "kimi-k2.5"
      }
    ]
  }
}
```

お客様側では以下の項目を保存し、モニタリングに使うことをおすすめします：

- `id`
- `name`
- `status`
- `used_quota`
- `model_limits_enabled`
- `model_limits`

## 2. Keyごとの呼び出しログ照会

`/api/log/self`を通じて現ユーザーの消費ログを照会できます。最低でも以下の項目を指定することを推奨します：

- `type`
- `token_name`
- `start_timestamp`
- `end_timestamp`
- `p`
- `page_size`

例：

```bash cURL
curl "https://crazyrouter.com/api/log/self?type=2&token_name=gptai&start_timestamp=1771334901&end_timestamp=1772309095&p=1&page_size=5" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 485"
```

レスポンス例：

```json
{
  "success": true,
  "message": "",
  "data": {
    "page": 1,
    "page_size": 5,
    "total": 4988,
    "items": [
      {
        "created_at": 1772308747,
        "token_name": "gptai",
        "model_name": "deepseek-chat",
        "quota": 3188,
        "cost_usd": 0.006376,
        "prompt_tokens": 884,
        "completion_tokens": 397,
        "use_time": 16.48,
        "is_stream": true,
        "ip": "203.0.113.10",
        "other": {
          "client": "openai-python",
          "request_id": "req_xxx",
          "request_method": "POST",
          "request_path": "/v1/chat/completions",
          "http_status": 200,
          "discount": 0
        }
      }
    ]
  }
}
```

### 主要項目の説明

| 項目 | 説明 |
|------|------|
| `token_name` | ヒットした業務Key |
| `model_name` | 実際に課金されたモデル |
| `quota` | 今回のリクエストで減算されたシステム使用量 |
| `cost_usd` | 今回のリクエストで換算した米ドル費用 |
| `prompt_tokens` | 入力トークン数 |
| `completion_tokens` | 出力トークン数 |
| `use_time` | リクエストの所要時間（秒単位） |
| `other.request_id` | リクエストID（追跡用） |
| `other.client` | クライアント識別子 |
| `other.request_path` | 実際にヒットしたAPIパス |
| `other.http_status` | アップストリーム応答ステータスコード |

<Note>
  `cost_usd`はシステムの換算基準による米ドル費用を返します。計算方法は`quota / quota_per_unit`です。ご利用環境でまだこの項目が無い場合は、とりあえず合計使用量で換算してください。
</Note>

<Warning>
失敗した単一リクエストは課金されません。ログ上の`quota`／`cost_usd`は0であるべきです。ただし、Agentモードやワークフロー、チェーン呼び出しやIDE自動プログラミングなど、1回の操作が複数モデルリクエストに分割される場合、前段が正常終了済みで後続で失敗した場合は、前段分は実際のトークン消費通り課金されます。異常消費の確認時は、最終タスクの成否だけでなく、ログに載っている全リクエストを個別に突合してください。
</Warning>

## 3. 合計消費量の照会

個別のログが不要で監視パネルや日報に使いたい場合は、合計集計インターフェースの呼び出しをおすすめします：

```bash cURL
curl "https://crazyrouter.com/api/log/self/stat?type=2&token_name=gptai&start_timestamp=1771334901&end_timestamp=1772309095" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 485"
```

レスポンス例：

```json
{
  "success": true,
  "message": "",
  "data": {
    "quota": 16605808,
    "rpm": 0,
    "tpm": 0
  }
}
```

内容：

- `quota`：指定条件下での総消費量
- `rpm`、`tpm`：現インターフェースの予備項目（拡張モニタリング用）

## 4. 現アカウントの残高照会

特定の業務Key単位での監視だけでなく、Crazyrouterアカウントの残高をお客様側の管理画面に直接表示したい場合は`/api/user/self`を呼び出します。

リクエストヘッダは他の管理系インターフェースと同じです：

```bash cURL
curl "https://crazyrouter.com/api/user/self" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 4004"
```

レスポンス例：

```json
{
  "success": true,
  "message": "",
  "data": {
    "id": 4004,
    "username": "google_4004",
    "quota": 11000000,
    "used_quota": 0,
    "request_count": 0,
    "group": "default"
  }
}
```

主要項目：

| 項目 | 説明 |
|------|------|
| `quota` | 現在の残り残高（システム内部quota単位） |
| `used_quota` | 過去利用済み量（システム内部quota単位） |
| `request_count` | 過去のリクエスト回数 |
| `group` | 現アカウントグループ |

換算方法：

```text
balance_usd = quota / quota_per_unit
used_usd = used_quota / quota_per_unit
```

例：

```text
quota = 11000000
quota_per_unit = 500000

balance_usd = 11000000 / 500000 = 22
```

つまり上記例の残高は：

```text
$22.00
```

<Note>
  `/api/user/self`は「現在アカウント合計残高表示」に最適です。`/api/log/self`／`/api/log/self/stat`は「期間指定・Key別・モデル別」の消費分析向きです。
</Note>

## 5. 米ドル費用の換算

システム換算パラメータは公開インターフェース`/api/status`から取得可能です：

```bash cURL
curl "https://api.crazyrouter.com/api/status"
```

レスポンス側で注目する点：

```json
{
  "success": true,
  "message": "",
  "data": {
    "quota_per_unit": 500000,
    "quota_display_type": "USD",
    "usd_exchange_rate": 7.3
  }
}
```

換算式：

```text
cost_usd = quota / quota_per_unit
```

例：

```text
16605808 / 500000 = 33.211616 USD
```

## Python利用例

```python
import requests

BASE_URL = "https://crazyrouter.com"
ACCESS_TOKEN = "your_access_token"
USER_ID = "485"
TOKEN_NAME = "gptai"

headers = {
    "Authorization": f"Bearer {ACCESS_TOKEN}",
    "New-Api-User": USER_ID,
    "User-Agent": "Mozilla/5.0",
}

token_resp = requests.get(
    f"{BASE_URL}/api/token/",
    params={"p": 1, "page_size": 100},
    headers=headers,
    timeout=30,
)
token_resp.raise_for_status()
tokens = token_resp.json()["data"]["items"]

log_resp = requests.get(
    f"{BASE_URL}/api/log/self/stat",
    params={
        "type": 2,
        "token_name": TOKEN_NAME,
        "start_timestamp": 1771334901,
        "end_timestamp": 1772309095,
    },
    headers=headers,
    timeout=30,
)
log_resp.raise_for_status()
quota = log_resp.json()["data"]["quota"]

status_resp = requests.get(f"{BASE_URL}/api/status", timeout=30)
status_resp.raise_for_status()
quota_per_unit = status_resp.json()["data"]["quota_per_unit"]

cost_usd = quota / quota_per_unit

print("tokens:", [item["name"] for item in tokens])
print("quota:", quota)
print("cost_usd:", round(cost_usd, 6))
```

## モニタリングのポイント

お客様側の監視モニタリングでは、最低限次の軸で集計することを推奨：

- `token_name`別に利用回数、総消費量、総費用を集計
- `model_name`別でモデル消費割合を集計
- `other.request_path`別で`/v1/chat/completions`や`/v1/responses`などのインターフェースを区別
- `other.http_status`別で成功/失敗率を集計
- `other.request_id`でトラブルシュートのための追跡を確保

## よくある質問

### なぜ管理インターフェースは`sk-xxx`を直接使えないのですか？

`sk-xxx`は業務呼び出し用認証情報で、`TokenAuth`ミドルウェアがチェックします。一方、`/api/token/*`・`/api/log/self*`など管理インターフェースはユーザー認証が必要で、`access_token`と`New-Api-User`が必要になります。

### 特定Keyで自分のログを照会できますか？

はい。`token_name`で`/api/log/self`と`/api/log/self/stat`を絞り込む方法を推奨します。

### APIで直接費用金額を取得できますか？

サーバー側で`cost_usd`項目に対応済みなら、ログ明細で1リクエストごとに米ドル費用を直接取得できます。合計集計時は`quota / quota_per_unit`で換算する方法を推奨します（コンソール表示と一致）。
