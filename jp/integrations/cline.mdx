Cline は VS Code 内で非常に強力なプロキシ型コーディング拡張機能であり、ファイルの読み書き、ターミナルでの実行、段階的なプランニングや多段階コード修正が得意です。Crazyrouter との連携では、Cline 公式提供の `OpenAI Compatible` provider を使うことを推奨します。

## 概要

Cline の OpenAI Compatible provider を利用すると、プロキシリクエストを Crazyrouter に転送できます：

- 推奨プロトコル：`OpenAI-compatible API`
- Base URL：`https://api.crazyrouter.com/v1`
- 認証方法：`sk-...` トークン
- 推奨デフォルトモデル：`claude-opus-4-8` または `gpt-5.5`

<Warning>
Cline はファイルの読み書きやターミナルコマンドの実行も可能です。接続自体は簡単ですが、最大のリスクは「接続できるかどうか」ではなく「過剰な実行権限を与えていないか」です。まず自分が熟知している小さなリポジトリから始めることをおすすめします。
</Warning>

## 利用が適しているユーザー

- VS Code でプロキシ型のプログラミング体験を得たい方
- Crazyrouter のマルチモデル機能をコード修正に活用したい方
- IDE のプロキシトラフィックと CLI トラフィックを分離して管理したい方
- Claude、GPT など複数モデルを統合ゲートウェイ経由で利用したい方

## 利用プロトコル

推奨プロトコル：`OpenAI-compatible API`

Cline の設定画面で以下を選択：

- `API Provider`: `OpenAI Compatible`
- `Base URL`: `https://api.crazyrouter.com/v1`
- `API Key`: あなたの `sk-...`
- `Model ID`: 使用したいモデル名

Base URL に以下を書かないでください：

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

<Note>
Claude Code や Codex、Aider とは違い、Cline の標準 VS Code 接続では通常、環境変数を手で設定する必要はありません。多くの場合、Cline の設定画面で `Base URL`、`API Key`、`Model ID` を入力するだけでOKです。
</Note>

## システム要件と前提条件

| 項目 | 説明 |
|------|------|
| Crazyrouter アカウント | 先に [crazyrouter.com](https://crazyrouter.com) で登録してください |
| Crazyrouter トークン | Cline 専用のトークンを個別に作成することを推奨 |
| Git | `git 2.23+` を推奨 |
| VS Code | 最新の安定版を推奨 |
| Cline 拡張 | 現在の最新版を推奨 |
| 利用可能なモデル | プロキシ型コーディングに適した1～2モデル以上の許可が必要 |
| 環境変数 | 標準の VS Code 接続では原則不要 |

初期ホワイトリストの提案：

- `claude-opus-4-8`
- `gpt-5.5`
- `gemini-3.1-pro`

## OS別インストール手順

### Windows 推奨手順

Cline を Windows で導入する際の最も確実なプロセスは：`Git` + `VS Code` + `拡張マーケットで Cline をインストール` + `Cline の設定で Crazyrouter のパラメータを直接入力する` です。

推奨する順番：

1. Git をインストールする
2. VS Code をインストールする
3. VS Code 拡張マーケットから Cline を導入
4. Crazyrouter で Cline 専用トークンを作成
5. リポジトリを開いて Git スナップショットを作成
6. Cline 設定画面に `OpenAI Compatible`、`Base URL`、`API Key`、`Model ID` を入力

インストール検証用コマンド例：

```powershell
git --version
where.exe git
code --version
where.exe code
```

`code --version` コマンドが見つからない場合でも、VS Code 本体が正常に起動すれば、Cline は問題なく使えます。ターミナルから `code` で直接ディレクトリを開けないだけです。

### macOS 推奨手順

Cline を macOS で使用する典型的な流れは：`Xcode Command Line Tools` + `Homebrew` + `Git` + `VS Code` + `拡張マーケットで Cline をインストール` です。

推奨する順番：

1. Xcode Command Line Tools をインストール
2. Homebrew を導入（未導入の場合）
3. Git をインストール
4. VS Code をインストール
5. VS Code 内で Cline をインストール
6. Cline 設定画面で Crazyrouter のパラメータを直接入力

インストール検証用コマンド例：

```bash
git --version
which git
open -a "Visual Studio Code"
```

ターミナルから `code` コマンドを直接実行したい場合は、VS Code コマンドパレットで `Shell Command: Install 'code' command in PATH` を実行してから、次を確認：

```bash
code --version
which code
```

### Linux に関する説明

Linux ユーザーも基本的には Windows や macOS と同じ考え方でOKです。最初に Git と VS Code をインストールし、次に拡張マーケットから Cline を導入します。Ubuntu / Debian での主なコマンド例：

```bash
sudo apt update
sudo apt install -y git
sudo snap install code --classic
git --version
code --version
```

## ゼロからの完全インストール手順

<Steps>
  <Step title="ステップ1：Git をインストールする">
    ご利用端末にまだ Git が入っていない場合は、まずインストールしてください。

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install --id Git.Git -e --source winget
        git --version
        where.exe git
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        xcode-select --install
        git --version
        ```
        または：
        ```bash
        brew install git
        git --version
        which git
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo apt update
        sudo apt install -y git
        git --version
        which git
        ```
      </Tab>
    </Tabs>

    インストール後、次のコマンドで動作を確認することをおすすめします：

    ```bash
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
    git config --global init.defaultBranch main
    ```
  </Step>

  <Step title="ステップ2：VS Code をインストールする">
    Cline の最も標準的な使い方は VS Code 拡張としての利用です。

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install Microsoft.VisualStudioCode
        code --version
        where.exe code
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        brew install --cask visual-studio-code
        open -a "Visual Studio Code"
        ```

        ターミナルから `code` を直接実行したい場合は、VS Code コマンドパレットで：

        ```text
        Shell Command: Install 'code' command in PATH
        ```

        その後で次を実行して確認：

        ```bash
        code --version
        which code
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo snap install code --classic
        code --version
        which code
        ```
      </Tab>
    </Tabs>

    インストールが終わったら、まず VS Code を1度起動しましょう。
  </Step>

  <Step title="ステップ3：Cline 拡張機能をインストールする">
    VS Code を開いたら：

    1. `Ctrl/Cmd + Shift + X` で拡張マーケットを開く
    2. `Cline` で検索する
    3. インストールボタンを押す
    4. インストール完了後、サイドバーの Cline アイコン または `Ctrl/Cmd + Shift + P` > `Cline: Open In New Tab` を実行

    VS Code から `Running extensions might...` のような通知が出た場合、「許可」してください。

    アイコンが見当たらない場合は、VS Code を再起動して再度ご確認を。
  </Step>

  <Step title="ステップ4：Crazyrouter 上で Cline 専用のトークンを作成する">
    Crazyrouter の管理画面で `cline` という名前のトークンを作ります。初回は以下のみ許可：

    - `claude-opus-4-8`
    - `gpt-5.5`
    - `gemini-3.1-pro`

    <Note>
    Cline の標準 VS Code 接続では基本的に UI で API Key を入力します。Claude Code / Codex のように環境変数メインではありません。ここで最も重要なのは専用トークンと最小限のモデルホワイトリストです。
    </Note>
  </Step>

  <Step title="ステップ5：Git リポジトリを準備し、最初のスナップショットを作成する">
    Cline はファイルの修正やコマンドの実行を行います。初回接続前には必ずリポジトリのスナップショットを取ってください。

    ディレクトリがまだ Git リポジトリでない場合：

    ```bash
    git init
    git add .
    git commit -m "chore: initial snapshot before Cline"
    ```

    既存リポジトリなら、まず次で状況確認：

    ```bash
    git status
    ```
  </Step>

  <Step title="ステップ6：Cline で Crazyrouter の設定を入力する">
    Cline 設定画面で次を入力：

    - `API Provider`: `OpenAI Compatible`
    - `Base URL`: `https://api.crazyrouter.com/v1`
    - `API Key`: あなたの `sk-...`
    - `Model ID`: まず `claude-opus-4-8`

    現在の Cline UI に `Verify` ボタンがあれば、接続確認のため一度押してみてください。なければリードオンリーのテストリクエストを送るだけでも検証可能です。

    初回はモデルをひとつだけ指定し、いきなり複数モデルを同時に使わないこと。
  </Step>

  <Step title="ステップ7：初回の検証を完了する">
    初回検証はこの順序がおすすめです：

    1. まず Cline にリードオンリータスクを実行させる：`現在のワークスペースの README の内容だけを読み取って要点をまとめます。ファイルは一切変更しません。`
    2. 次に低リスクの解析をさせる：`現在のリポジトリで最初に確認すべき価値の高い 3 ファイルを指摘します。`
    3. 最後に小規模修正を試す：`README の明らかな誤字を 1 つだけ修正し、diff を表示します。`

    この3ステップが問題なく動作し、Crazyrouter 管理画面で対応リクエストが確認できれば、主経路は安定したと言えます。
  </Step>

  <Step title="ステップ8：強い権限を段階的に開放する">
    リードオンリーや小規模修正が安定した後は、徐々に以下も試せます：

    1. 小規模な複数ファイルを編集
    2. 低リスクのコマンド実行も許可
    3. 最後に、より複雑なプロキシ型リファクタリングに挑戦

    最初からいきなり大規模リポジトリで広域自動実行はおすすめしません。
  </Step>
</Steps>

## 推奨モデル設定

| 利用シーン | 推奨モデル | 理由 |
|----------|----------|------|
| デフォルトメインプロキシ | `claude-opus-4-8` | 複数ステップの計画、コードの説明、長文コンテキストで安定動作 |
| OpenAI 互換ベースライン | `gpt-5.5` | 2026年3月23日、商用で実戦確認済み。OpenAI互換のベースとして最適 |
| Gemini バックアップ用 | `gemini-3.1-pro` | 2番目の互換性検証経路としておすすめ |

まずは `claude-opus-4-8` で代理フローを検証。OpenAI 互換ベースラインが必要な場合のみ `gpt-5.5` に切り替えてください。

## トークン設定のベストプラクティス

| 項目 | 推奨 | 説明 |
|------|------|------|
| 専用トークン | 必須 | Cline 用トークンは Cursor・Claude Code・Aider と共用しないこと |
| モデルホワイトリスト | 強く推奨 | Cline は高負荷なので、許可モデルは最小限が安全 |
| IP 制限 | 固定オフィス環境なら有効化を推奨 | ノートPCなど移動ネットワークでは慎重に運用 |
| 使用上限設定 | 強く推奨 | 多段階エージェント実行で一気に上限到達する場合あり |
| 環境分離 | おすすめ | 個人 VS Code・リモート開発端末・チーム共有などでトークンを分離 |
| 権限分離 | 強く推奨 | ハイリスクリポジトリには少量上限・専用トークン推奨 |

## よくあるエラー・修正方法

| 現象 | よくある原因 | 修正方法 |
|------|----------|----------|
| 拡張機能はインストール済みだが Cline アイコンが表示されない | VS Code がリフレッシュされていない、または拡張機能が正しく有効化されていない | VS Code を再起動し、コマンドパレットから Cline を開く |
| `code` コマンドが利用できない | VS Code 本体はインストール済みだが、シェルコマンドが PATH に入っていない | Windows ならターミナルを再起動して試す；macOS ではコマンドパレットで `Shell Command: Install 'code' command in PATH` を実行 |
| 401 unauthorized | API Key の誤り、期限切れ、コピーミス等 | token を再生成して貼り直す |
| 403 / model not allowed | token で現在のモデルの利用が許可されていない | Crazyrouter の token 設定でモデルを許可する |
| 404 | Base URL をルートドメインや具体的なAPIパスにしている | `https://api.crazyrouter.com/v1` に修正する |
| `model not found` | `Model ID` 名が間違っているか現在のモデルが利用不可 | `claude-opus-4-8` または他の許可済みモデルに戻す |
| 企業ネットワーク下で接続できない | プロキシまたはファイアウォールによるブロック | まず VS Code 本体のプロキシ設定を確認する。Cline 拡張は VS Code のネットワークプロキシ設定を共用します。 |
| 書き込み不要なファイルも編集された | 最初に広範な書き込み権限を付与した | まずはリードオンリータスクや範囲を絞ったdiff検証から始める |
| コストが急上昇する | 複数ラウンドのプラン＋大量のコンテキスト＋自動実行 | タスク範囲を縮小し、Cline 専用に予算を設ける |

## パフォーマンスとコストのアドバイス

- 最初の導入時は、まずリードオンリータスクや小規模修正のみにする
- 複雑なリファクタリングは `claude-opus-4-8` または `gpt-5.5` を優先利用
- 頻度の高い軽量タスクは、モデルを増やしすぎず、まずホワイトリストを絞り込むことを優先
- 異なるワークスペースやプロジェクトタイプには別々の token 利用を推奨
- 大きなタスク実行毎に Crazyrouter のログで実消費を確認する

## FAQ

### Cline はどの Provider を選べばよいですか？

`OpenAI Compatible` を選んでください。

### Base URL には何を入力すればよいですか？

`https://api.crazyrouter.com/v1` を入力してください。

### Cline のこの接続方法は必ず環境変数を設定する必要がありますか？

通常は不要です。標準的な VS Code 接続方法では、Cline の設定画面で `Base URL`、`API Key`、`Model ID` を直接入力すれば十分です。

### 初回に必ず Git スナップショットを作成するのはなぜですか？

Cline は本当にファイルの読み書きやコマンド実行をするエージェントだからです。先にスナップショットを作成しておけば、レビューやロールバックが楽に行えます。

### 最初に推奨されるモデルはどれですか？

まず `claude-opus-4-8` を使ってください。

### なぜ最初から広い権限を与えないことを推奨するのですか？

Cline は本当にあなたのワークスペースを操作するからです。リードオンリーや小規模タスクでまず検証するのが、一番安全な導入方法です。

<Note>
もし VS Code 内での統合エージェント体験を重視する場合、Cline は Cursor の BYOK 方式より“本物のコードエージェント”に適しています。
</Note>
