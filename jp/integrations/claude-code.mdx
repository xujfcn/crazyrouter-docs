Claude Code は現在 Crazyrouter への優先的な導入が最も推奨されるエンドコーディングツールのひとつです。Anthropic Messages API を直接使用し、コードの閲覧、修正、リファクタリング、コマンド実行、ツール呼び出し、長文コンテキストのリポジトリ分析などに適しています。

## 概要

環境変数を使って、Claude Code は Anthropic のリクエストを直接 Crazyrouter に送信できます：

- 推奨プロトコル：`Anthropic Messages API`
- Base URL：`https://api.crazyrouter.com`
- デフォルト国際API Base URL：`https://api.crazyrouter.com`
- 認証変数：`ANTHROPIC_API_KEY`
- 推奨デフォルトモデル：`claude-opus-4-8`

<Tip>
Claude Code はAnthropicのリクエストパスを自動で補完するため、Base URLは必ずルートドメイン`https://api.crazyrouter.com`または`https://api.crazyrouter.com`を記入してください。`/v1`や`/v1/messages`は手動で追加しないようにしましょう。
</Tip>

- CrazyrouterをClaude Codeのバックエンドとして使いたい開発者

- Claude CodeとCursor/Codex/Aiderの料金を分けたい方

デフォルト国際APIエントリもルートアドレスのみ入力：

## オペレーティングシステム別の完全インストールルート

### Windows推奨ルート

Claude CodeをWindowsで最も安定して使えるルートは、`Git` + `Node.js` + `npm で Claude Code をグローバルインストールする` + `PowerShell`の環境変数設定です。

推奨順序：

1. Gitのインストール
2. Node.js LTSのインストール
3. npmでClaude Codeをインストール
4. PowerShellで一時変数設定
5. PowerShellでユーザー永続変数設定

推奨検証コマンド：

```powershell
git --version
node -v
npm -v
claude --version
where.exe git
where.exe node
where.exe claude
```

`claude --version`でコマンドが見つからない場合は、一度PowerShellを閉じて再度開き、再試行してください。

### macOS推奨ルート

Claude CodeをmacOSで最もスムーズに使えるルートは、`Xcode Command Line Tools` + `Homebrew` + `Git` + `Node.js` + `npm で Claude Code をグローバルインストールする` + `~/.zshrc`の環境変数永続化です。

推奨順序：

1. Xcode Command Line Toolsのインストール
2. Homebrewのインストール（未導入の場合）
3. Git, Node.jsのインストール
4. npmでClaude Codeのインストール
5. `~/.zshrc`の記入
6. 新しいターミナルでコマンドパスの検証

推奨検証コマンド：

```bash
git --version
node -v
npm -v
claude --version
which git
which node
which claude
```

### なぜAPIパスを手動で記入しないのか

Claude CodeはAnthropicのネイティブプロトコルを使用しているため、ルートアドレスのみ伝えれば十分です：

```text
ANTHROPIC_BASE_URL=https://api.crazyrouter.com
```

デフォルト国際APIエントリも同じくルートアドレスのみ記入してください：

```text
ANTHROPIC_BASE_URL=https://api.crazyrouter.com
```

OpenAI互換クライアントのように`/v1`や`/v1/messages`など個別APIパスを手動で構築しないようにしましょう。

スクリプトによる自動インストールとCrazyrouter環境変数の書き込みには [crazyrouter-claude-code](https://github.com/xujfcn/crazyrouter-claude-code) を参照ください。このリポジトリはWindows/macOS/Linuxの一発設定スクリプトを提供します。本ドキュメントは手動設定手順も完全に記載しているため、各設定をご自身で監査できます。

## Claude CodeでClaude以外のモデルを利用する

Claudeシリーズ以外にも、Crazyrouterは一部の国産モデルでAnthropic Messagesのネイティブ接続が可能です。下記リストは **2026-05-15 本番実クライアント再検証済み** モデルのみ掲載し、未再検証の古いモデルは除外しています。

### 実機検証済みモデルリスト

| モデルID | 提供者 | `Reply only OK` | 取得 `agent.md` | 現在の結論 | 備考 |
|---------|--------|------------------|------------------|----------|------|
| `deepseek-v4-pro` | DeepSeek | 合格 | 合格 | Claude Code P0 利用可 | 汎用プログラム用途に適している；Codex 側は現時点で Responses 利用は推奨しない |
| `MiniMax-M2.7` | MiniMax | 合格だが `<think>` を含む | 合格だが `<think>` を含む | プロトコル利用可 | 厳格な出力タスクの体験が悪い |
| `kimi-k2.5` | Moonshot Kimi | 合格 | 合格 | Claude Code P0 利用可 | 現時点で最も安定した国産モデル候補の一つ |
| `kimi-k2.6` | Moonshot Kimi | 合格 | 合格 | Claude Code P0 利用可 | `kimi-k2.5` と同じカテゴリ |
| `glm-5.1` | GLM | 合格 | 合格 | Claude Code P0 利用可 | Claude Code 限定；Codex ネイティブ Responses は現時点で不可 |

> 上記のテストは Claude Code の実際のクライアントを使用し、`https://api.crazyrouter.com` ルートドメイン経由でネイティブの`POST /v1/messages`経路で検証済み。

<Note>
この表の基準は「現時点で再テストし利用可能」であり、「理論的に Anthropic プロトコルへ変換できるすべてのサードパーティモデルの全リスト」ではありません。もし特定の型式がここに掲載されていない場合、現時点の日本語ドキュメントで Claude Code の検証済み推奨項目に含まれていないことを示します。

### モデルを切り替える方法

Claude Code では`ANTHROPIC_MODEL`環境変数またはセッション内の`/model`コマンドでモデルを選択します。上記表内の任意のモデル名に置き換えてください。

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    export ANTHROPIC_BASE_URL=https://api.crazyrouter.com
    export ANTHROPIC_API_KEY=sk-xxx

    # 临时切到 Kimi K2.5
    export ANTHROPIC_MODEL=kimi-k2.5
    claude

    # 或临时切到 MiniMax
    ANTHROPIC_MODEL=MiniMax-M2.7 claude
    ```
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    $env:ANTHROPIC_BASE_URL = "https://api.crazyrouter.com"
    $env:ANTHROPIC_API_KEY  = "sk-xxx"

    $env:ANTHROPIC_MODEL = "kimi-k2.5"
    claude

    # 或临时切换
    $env:ANTHROPIC_MODEL = "MiniMax-M2.7"; claude
    ```
  </Tab>
</Tabs>

また、Claude Code 起動後もセッションコマンドで切り替え可能です：

```text
/model kimi-k2.5
/model MiniMax-M2.7
```

### 利用に関する推奨事項および既知の差異

- **優先順位**：Claude Code 内で国産モデルを優先して利用したい場合、まず`kimi-k2.5`と`kimi-k2.6`から開始し、その後`deepseek-v4-pro`を検討してください。Qwenシリーズは先に`/v1/models`で利用可能なモデルIDを確認し、別途検証してください。
- **MiniMax の既知の差異**：`MiniMax-M2.7`はプロトコルとしては利用できますが、思考過程を通常テキストとして直接出力し、前後に`<think>...</think>`タグが付きます。「指定された一文だけ出力」など厳格なタスクには優先採用を推奨しません。
- **DeepSeek / GLMの制約**：`deepseek-v4-pro`と`glm-5.1`はClaude Code内で利用可能ですが、これらが直接CodexネイティブResponsesの構成にも適応するとは限りません。両者は異なるプロトコルを使用しており、互換の結論を混同しないでください。
- **トークンのホワイトリスト**：Claude Code専用トークンにモデルホワイトリストを設定している場合、利用したい国産モデルも追加してください。そうしないと`403 model not allowed`が返されます。
- **実クライアントでの先行検証推奨**：まず`Reply only OK`を一度動かし、「ファイルを読み込んでタイトルだけ返す」タスクも実行しましょう。これによりAPI単体のテストよりもClaude Code実利用に近い挙動を確認できます。

### ワンコマンドでモデルの利用可否を即時検証

```bash
curl -sS https://api.crazyrouter.com/v1/messages \
  -H "Authorization: Bearer $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k2.5",
    "max_tokens": 32,
    "messages": [{"role":"user","content":"reply OK"}]
  }'
```

HTTPステータス200で`content[].text`が空でなければClaude Codeからそのモデルが正常に利用できることを意味します。

## トークン設定のベストプラクティス

| 設定内容 | 推奨 | 解説 |
|------|------|------|
| 専用トークン | 必須 | Claude CodeはCursor、Codex、OpenClawとトークンを共有しないようにしましょう |
| モデルホワイトリスト | 強く推奨 | 実際に利用するClaudeまたは国産モデルだけ許可し、トラブルシューティングやコスト管理の複雑さを軽減します |
| IP制限 | 固定回線環境では推奨 | ノートPCなど頻繁にIPが変わる場合は注意して利用してください |
| クォータ上限 | 強く推奨 | Claude Codeは長時間対話＋ツール呼び出しで継続して容量を消費します |
| 開発/チーム分割 | 推奨 | 各開発者や共有サーバーごとに個別のトークンを利用してください |
| 漏洩時の即時ローテーション | 必須 | シェル履歴や録画または共有端末でトークンが漏れた際は即時ローテーションを実施してください |

## よくあるエラーと修正方法

| 症状 | よくある原因 | 修正方法 |
|------|----------|----------|
| `claude: command not found` | Claude Codeが正しくインストールされていない、またはnpmのグローバルパスがPATHに含まれていない | 再インストールし、`npm bin -g` ディレクトリがPATHに含まれていることを確認する |
| `node` のバージョンが古い | PCのNodeバージョンが必要条件を満たしていない | Node.jsを18以上にバージョンアップしてからClaude Codeを再インストールする |
| 401 unauthorized | `ANTHROPIC_API_KEY`が無効・期限切れ・複製ミス等 | 新規にトークンを発行しなおし、環境変数を再設定する |
| 403 / model not allowed | トークンが現在のClaudeモデルを許可していない | Crazyrouterのトークン設定で必要なモデルを許可する |
| 404 | Base URLとして`/v1`や`/v1/messages`など誤ったパスを記載 | `https://api.crazyrouter.com`または`https://api.crazyrouter.com`に修正 |
| ログパスに`/v1/v1/messages`、`/v1/v1/models`または`/v1/messages/v1/messages`が出る | Claude CodeのBase URLで`/v1`や完全なエンドポイントを記載し、クライアント側でパスが追加された | Base URLを`ANTHROPIC_BASE_URL`(ルートドメイン)へ修正し、パスは記載しない |
| Claude Codeが起動後も古い設定を使用 | 新しい環境変数が再ロードされていない | 新しい端末を開くか`source ~/.bashrc` / `source ~/.zshrc`をやり直す |
| Git変更が複雑になりすぎる | リポジトリのスナップショットを取る前にAIにコードを変更させている | まず初期スナップショットをコミットし、その後段階的に修正を加える |
| コストが予想以上に高い | 長い履歴＋複数ツール呼び出し＋長時間セッション | セッションを短く、タスクを分割し、Claude Code専用の予算を設ける |

## パフォーマンス・コストに関する推奨

- デフォルトはまず`claude-opus-4-8`を使用
- 複雑なアーキテクチャ分析や長いリファクタリング時のみ`claude-opus-4-8`へ変更
- 初回導入時は小規模なリポジトリで検証し、大規模な本番倉庫で一括操作はしないでください
- 新しいタスクに入るたびに`git status`を確認しましょう
- ツールコールが多い場合は特にCrazyrouterのログやトークン消費を振り返って確認

## FAQ

### Claude Code の Base URL には何を書けばいいですか？

ルートドメインを記載してください：`https://api.crazyrouter.com`

デフォルトの国際APIエンドポイントもルートドメインです：`https://api.crazyrouter.com`

### なぜここに`/v1`を書いてはいけないのですか？

Claude Codeが自動的にAnthropic Messages APIパスを補完するためです。サイトのルートアドレスだけ記載してください。

### Windows上ではどうしたら良いですか？

主にコマンドライン開発であればPowerShellまたはWSL2をおすすめします。いずれの場合もGit・Node.js・Claude Code が正しくインストールされていることを確認してください。

### WindowsではPowerShellとGit Bashどちらを推奨しますか？

初回設定時はPowerShellを推奨します。環境変数の書き込み、`where.exe`の確認やユーザー変数の永続化がより簡単です。

### 初回はなぜGitスナップショットをとるべきですか？

Claude Codeがファイルを修正・コマンド実行を行うためです。先にスナップショットを取っておくことで、問題時にリビューやロールバックが容易です。

### 最初の推奨モデルは？

まず`claude-opus-4-8`を利用してください。通常最も安定したベースラインモデルです。

Claude系シリーズ＋ターミナル開発体験を重視する場合、Claude CodeはCrazyrouter開発ツール連携の最初に配置することをおすすめします。
</Note>
