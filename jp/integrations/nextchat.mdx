NextChat（旧 ChatGPT Next Web）は、軽量でレスポンスが早く、簡単に自分でデプロイできるチャットフロントエンドをすぐに構築したい方に最適です。Crazyrouter を連携する際は、OpenAI 互換ルートを推奨し、サービスURLを Crazyrouter のルートドメインに設定してください。

## 概要

NextChat の OpenAI 設定項目から Crazyrouter にリクエストできます：

- 推奨プロトコル：`OpenAI-compatible API`
- 推奨接続方法：NextChat 標準の OpenAI ルート
- Base URL：`https://api.crazyrouter.com`
- 認証方式：`sk-...` token
- 推奨初回検証モデル：`gpt-5.5`

<Note>
NextChat 公式 README では `BASE_URL` を OpenAI API request base URL と定義しており、サンプルもルートドメイン形式です。同時にローカルの `http://127.0.0.1:4000/api/status` にて公開される `server_address` もルートアドレスとなっています。そのため Crazyrouter 連携時の初回検証は `https://api.crazyrouter.com` を優先して入力してください。もしカスタム版で詳細なパス指定が必要な場合は、そのバージョンの案内に従って調整してください。
</Note>

## 対象ユーザー

- 軽量チャットフロントエンドをすぐに構築したい方
- Crazyrouter を個人や小規模チームのウェブチャット用に使いたい方
- 環境変数でデフォルトのモデル・上流を一括設定したい方
- 最小限の設定で OpenAI 互換ルートをまず動かしたい方

## 利用プロトコル

推奨プロトコル：`OpenAI-compatible API`

NextChat と Crazyrouter を連携する時、まず入力するURL：

```text
https://api.crazyrouter.com
```

下記は入力しないでください：

- `https://api.crazyrouter.com/v1/chat/completions`
- `https://api.crazyrouter.com/v1/models`

もし NextChat の過去のバージョンでより詳細な API ホストの手入力が求められる場合は、そのバージョンの案内に従って調整してください。初回の接続はルートドメインでベースライン検証を行います。

<Tip>
NextChat のデプロイ形態ごとにアクセス位置が異なります。オンライン利用時は設定画面で入力する例が多く、自分でデプロイする場合は環境変数を直接設定するケースが主流です。UIの仕様変更に関わらず、初回検証は最小構成で統一：`API Key` + ルートドメイン `BASE_URL` + 単一モデル `gpt-5.5`。
</Tip>

## 前提条件

| プロジェクト | 説明 |
|------|------|
| Crazyrouter アカウント | まず [crazyrouter.com](https://crazyrouter.com) で登録 |
| Crazyrouter token | NextChat 用に専用の `sk-...` token を作成推奨 |
| NextChat | オンライン版か自分でデプロイ版のどちらでも、現行安定版推奨 |
| 利用可能なモデル | 少なくとも、当日動作確認済みの OpenAI 互換チャットモデルを1つは許可（例：`gpt-5.5`） |

初回推奨ホワイトリスト：

- `gpt-5.5`
- `claude-opus-4-8`
- `gemini-3.1-pro`

## 5分でクイックスタート

<Steps>
  <Step title="NextChat専用トークンを作成する">
    Crazyrouter 管理画面で新しい token を作成し、名称は `nextchat` を推奨。初回は `gpt-5.5` と `claude-opus-4-8` のようなベースモデルだけを許可。
  </Step>
  <Step title="NextChatの設定を開く">
    NextChat にログインし、左下の `設定` アイコンか `Settings` をクリック。
  </Step>
  <Step title="インターフェースアドレスとキーを入力する">
    OpenAI 関連設定に下記を入力：
    - `API Key`：あなたの `sk-...`
    - `インターフェースアドレス / ベースURL`：`https://api.crazyrouter.com`
  </Step>
  <Step title="モデルを指定する">
    `モデル / モデル` で `gpt-5.5` を手入力または選択。バージョンがカスタムモデルリストに対応していれば、追加モデルも補足。
  </Step>
  <Step title="初回認証を完了する">
    新規チャットセッションを作成して `Reply only OK` を送信。正常レスポンスを受け取ったら少しずつモデル追加。
  </Step>
</Steps>

## 自分でデプロイする時のクイック設定

Docker 環境のよくある例：

```yaml
services:
  nextchat:
    image: yidadaa/chatgpt-next-web
    ports:
      - "3000:3000"
    environment:
      - OPENAI_API_KEY=sk-xxx
      - BASE_URL=https://api.crazyrouter.com
      - CUSTOM_MODELS=+gpt-5.5,+claude-opus-4-8,+gemini-3.1-pro
      - HIDE_USER_API_KEY=1
```

主な環境変数の説明：

| 変数 | 推奨値 | 説明 |
|------|--------|------|
| `OPENAI_API_KEY` | `sk-xxx` | 標準 Crazyrouter token |
| `BASE_URL` | `https://api.crazyrouter.com` | 公式の `BASE_URL` の手順でルートドメインを最初に設定し、ベースライン検証に使用 |
| `CUSTOM_MODELS` | `+gpt-5.5,+claude-opus-4-8,+gemini-3.1-pro` | フロントエンド向け追加モデル |
| `HIDE_USER_API_KEY` | `1` | エンドユーザーに他の Key 入力を許可しない |

## 推奨モデル構成

| 利用シーン | 推奨モデル | 理由 |
|----------|----------|------|
| デフォルトチャット主モデル | `gpt-5.5` | 当日動作確認済み・NextChat 基準に最適 |
| 高品質ロング文・解説 | `claude-opus-4-8` | 長文や複雑な解説に向く |
| Gemini バックアップ | `gemini-3.1-pro` | 2番目の互換性検証ルート用 |

推奨順序：まず `gpt-5.5` で稼働を確認、次に `CUSTOM_MODELS` でモデルリスト拡張。

## Token 設定ベストプラクティス

| 設定 | 推奨 | 説明 |
|------|------|------|
| 専用 token | 必須 | NextChat 用 token を LobeChat、Cursor、Codex と共用しない |
| モデルホワイトリスト | 強く推奨 | ユーザーのUIに表示されるモデルだけ許可 |
| IP制限 | 自分でデプロイし出口固定時検討可 | 頻繁にネットワーク変更する個人環境は注意 |
| クォータ上限 | 強く推奨 | Webチャットで多数利用時は消費急増の可能性 |
| 環境分離 | 推奨 | デモサイト・テストサイト・本番サイトそれぞれ別token |
| ユーザーの Key 自由入力 | デフォルトは無効を推奨 | 上流統一・課金制御したい場合は `HIDE_USER_API_KEY=1` を設定 |

## 検証項目一覧

- [ ] `API Key` を正しく保存済み
- [ ] `Base URL` を `https://api.crazyrouter.com` に設定済み
- [ ] 初回モデルを `gpt-5.5` で設定済み
- [ ] チャット初回リクエストは正常戻り
- [ ] 自分でデプロイの場合は `CUSTOM_MODELS` が有効化済み
- [ ] ストリーム出力も正常
- [ ] Crazyrouter 管理画面ログでリクエスト確認可
- [ ] token クォータ・モデルホワイトリストも想定通り

## よくあるエラーと修正方法

| 症状 | 主な原因 | 修正方法 |
|------|----------|----------|
| 401 unauthorized | token ミス、失効、またはコピー時に空白含む | token 再生成・再設定 |
| 403 / model not allowed | ホワイトリストでモデルを許可していない | Crazyrouter token 設定で該当モデル許可 |
| 404 | URL を詳細APIパスにした、またはバージョン変数名ミス | `https://api.crazyrouter.com` に修正し、利用バージョンで `BASE_URL` など変数名も再確認 |
| 自分でデプロイすると設定項目がUIにない | デプロイ方式で設定を環境変数固定し、前端の設定画面には出さない | デプロイ設定内の `OPENAI_API_KEY`、`BASE_URL`、`CUSTOM_MODELS` を直接確認 |
| ページでモデルが見えない | `CUSTOM_MODELS` 未設定、または古い設定をキャッシュしている | `gpt-5.5` を手入力で検証し、再読み込み・環境変数確認 |
| リクエストはできるがモデルエラー | デフォルトモデルの設定ミス、またはモデルが現時点で非稼働 | `gpt-5.5` に戻してベースライン検証 |
| ユーザーが独自 Key を使えてしまう | `HIDE_USER_API_KEY=1` を未実装 | デプロイ環境で該当変数を追記 |
| コスト急増 | 多人数で高権限tokenを共用 | token分割、ホワイトリスト縮小、制限設定 |

## 性能とコストに関するアドバイス

- デフォルトでは `gpt-5.5` のみ許可
- 高額モデルをデフォルトリストから除外し、必要な時だけ追加
- 公開/半公開デプロイ時はユーザー独自Key入力欄を極力隠す
- デモ用と本番用で料金を分け、テスト流量が本番クォータに影響しないように
- 消費増大時は Crazyrouter ログで長時間チャットや多数同時利用が原因か確認

## FAQ

### NextChat にはどのURLを入力すべき？

まず `https://api.crazyrouter.com` を入力。

### なぜ `/v1` を直接入力しない方が良い？

NextChat の公式ドキュメントで `BASE_URL` のサンプルはルートドメイン形式です。加えてローカル `4000` 環境での `server_address` の返却内容からも、初回検証はルートドメインのほうが安定します。

### 初回推奨モデルは何？

最初は `gpt-5.5` を利用。

### `CUSTOM_MODELS` の設定は必須？

必須ではありません。まず `gpt-5.5` を手入力で検証し、問題なければモデルリスト追加。

### 一部デプロイで環境変数しか変更できない理由は？

NextChat のデプロイ方法によって設定画面の公開位置が異なります。自分でデプロイする形式の場合、上流・モデル・Keyは環境変数で固定され、前端では編集できません。

### 自分でデプロイ時はユーザー独自 Key を隠すべき？

上流やコストを一括管理したい時は非表示推奨。

<Note>
最も安価に軽量チャットフロントエンドを構築したいなら NextChat が最適です。チームコラボや多機能が必要なら LobeChat や Dify の方が拡張に向いています。
</Note>
