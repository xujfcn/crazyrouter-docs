> 内容更新日: 2026-06-09

n8n は LLM 呼び出しを自動化フロー、Agent ノード、承認フローや業務システム統合に組み込むのに適しています。Crazyrouter との連携時には、まず n8n の OpenAI 認証情報経由で最小ワークフローを実行し、その後より柔軟な HTTP Request ノードへの切り替えを検討することを推奨します。

## 概要

n8n の OpenAI 認証情報または AI ノードを通じて、ワークフロー内のモデルリクエストを Crazyrouter にリダイレクトできます：

- 推奨プロトコル：`OpenAI-compatible API`
- 推奨連携方法：n8n `OpenAI API` 認証情報 + ノードレベル `Base URL`
- Base URL：`https://api.crazyrouter.com/v1`
- 認証方式：`sk-...` トークン
- 最初の動作検証に推奨するモデル：`gpt-5.5`

一部ノードで必要なパラメータや最新モデル機能がサポートされていない場合は、`HTTP Request` ノードで Crazyrouter API を直接呼び出すフォールバックが可能です。

## 対象ユーザー

- AI を自動化ワークフローに組み入れたい方
- フォーム、データベース、承認、Webhook とモデル連携をしたい方
- AI Agent ノードやオーケストレーションツールで呼び出しを行いたい方
- Crazyrouter を可視化環境で業務フローに統合したい方

## 利用プロトコル

推奨プロトコル：`OpenAI-compatible API`

n8n で Crazyrouter を連携する場合、次の値を入力してください：

```text
https://api.crazyrouter.com/v1
```

次の値は入力しないでください：

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

## 前提条件

| 項目 | 説明 |
|------|------|
| Crazyrouter アカウント | 最初に [crazyrouter.com](https://crazyrouter.com) で登録 |
| Crazyrouter トークン | n8n 専用の `sk-...` トークン発行を推奨 |
| n8n | 現在の安定版利用＆AIノードの利用可否確認 |
| 利用可能なモデル | 当日に正常動作確認済みのチャットモデル（例: `gpt-5.5`）を最低 1 つ許可 |

推奨する初回ホワイトリスト：

- `gpt-5.5`
- `claude-opus-4-8`
- `gemini-3.1-pro`
- `text-embedding-3-large`（ベクトルや検索系ノード利用の場合）

## 5分間クイックスタート

<Steps>
  <Step title="n8n 専用トークンを作成する">
    Crazyrouter 管理画面で `n8n` という名前のトークンを作成します。初回は `gpt-5.5` と `claude-opus-4-8` のみ許可することを推奨します。
  </Step>
  <Step title="OpenAI の認証情報を追加する">
    n8n 内で `Settings` → `Credentials` → `Add Credential` に進み、`OpenAI API` もしくは現在バージョンに対応した OpenAI 認証情報タイプを選択します。
  </Step>
  <Step title="認証情報とノード情報を記入する">
    まず認証情報に次を入力します：
    - `API Key`: あなたの `sk-...`

    次に `OpenAI`、`OpenAI Chat Model` または該当 AI ノードの `Options` で設定：
    - `Base URL`: `https://api.crazyrouter.com/v1`
  </Step>
  <Step title="最小限のワークフローを作成する">
    新規ワークフローを作成し、次の順で使用します：`Manual Trigger` → `OpenAI Chat Model` → `Output`（モデルは `gpt-5.5` を指定）
  </Step>
  <Step title="初回認証を完了する">
    `OpenAI Chat Model` ノードに簡単な入力（例: `Reply only OK`）を入力し、ワークフローを手動実行します。正常なレスポンスが返れば、AI Agent や複雑なフローの設定に進んでください。
  </Step>
</Steps>

## 最小ワークフロー例

### OpenAI Chat Model ノード

```json
{
  "node": "OpenAI Chat Model",
  "parameters": {
    "model": "gpt-5.5",
    "messages": [
      { "role": "user", "content": "{{ $json.input }}" }
    ]
  }
}
```

### AI Agent ワークフロー

可能な限りシンプルな流れから始めるのを推奨します：

1. `Manual Trigger`
2. `AI Agent`
3. `Output`

`AI Agent` で作成した Crazyrouter 認証情報を選択し、最初はツールノード1つだけを接続しましょう。ツールの問題とモデルの問題を区別しやすくなります。

## HTTP Request フォールバック手順

以下の場合は：

- 一部 n8n AI ノードが未対応の新規パラメータを使いたい
- より柔軟なリクエストボディ制御が必要
- headers, body, stream パラメータの明確なデバッグが必要

`HTTP Request` ノードを使い Crazyrouter を直接呼び出せます：

```http
Method: POST
URL: https://api.crazyrouter.com/v1/chat/completions
Headers:
  Authorization: Bearer sk-xxx
  Content-Type: application/json
Body:
  {
    "model": "gpt-5.5",
    "messages": [
      {"role": "user", "content": "{{ $json.input }}"}
    ]
  }
```

<Tip>
推奨順序：まずは OpenAI 認証情報 + ネイティブ AI ノードで動作確認し、ノード機能が不足する場合のみ `HTTP Request` へ切り替えましょう。
</Tip>

<Note>
n8n のバージョンによっては `Base URL` が認証情報ページ、または OpenAI/Chat Model ノードの `Options` に表示されます。現行の公式ドキュメントではノードレベル `Base URL` の上書きをより明記しているため、Crazyrouter 連携時は「認証情報に Key、ノードに Base URL」を入力する設計で設定します。
</Note>

## 推奨モデル設定

| 利用シーン | 推奨モデル | 理由 |
|------------|------------|------|
| デフォルトワークフローモデル | `gpt-5.5` | 当日検証済みで n8n のベースラインに適合 |
| 高品質・複雑 Agent シーン | `claude-opus-4-8` | 複雑な説明や長文タスクに好適 |
| Gemini 予備 | `gemini-3.1-pro` | 2点目の互換性検証経路として有用 |
| 検索／ベクトル系 | `text-embedding-3-large` | 今後のベクトル処理・検索強化に対応 |

推奨手順：まず `gpt-5.5` で最小ワークフローを動作確認後、Agent・ツール・バッチタスクへ拡張してください。

## トークン設定のベストプラクティス

| 設定         | 推奨度      | 説明 |
|--------------|------------|------|
| 専用トークン   | 必須        | n8n はチャットフロント、CLI や SDK サンプルとトークン共有不可 |
| モデルホワイトリスト | 強く推奨    | 利用するモデルだけ許可 |
| IP 制限       | 固定サーバー出口用を推奨 | ローカルテストやクラウド混在利用時は注意 |
| クォータ上限   | 強く推奨    | 自動化タスクはリトライ・ループ・バッチ消費が急増しがち |
| 環境分離       | 必須        | 開発・テスト・本番ワークフローは別トークン利用 |
| ノード階層分離 | 推奨        | 高頻度タスクは低コストモデル、重要タスクは高性能モデル |

## よくあるエラーと修正法

| 現象 | よくある原因 | 修正法 |
|------|----------|--------|
| 認証情報テスト失敗 | API Key のエラー、あるいは Base URL 設定場所ミス | `sk-...` を再度チェック＋`Base URL` を自身のバージョン対応位置に入力 |
| 401 unauthorized | トークン無効化・削除・スペース含むコピー | 新規トークン発行・再登録 |
| 403 / model not allowed | 利用モデルがホワイトリスト外 | Crazyrouter 管理画面で該当モデル許可 |
| 404 | `Base URL` を root ドメインや完全 API パスで設定 | `https://api.crazyrouter.com/v1` へ修正 |
| フローが無限リトライ・コスト急増 | ノードエラー時の自動リトライ／ループ設定漏れ | リトライ上限・ワークフロー分割・クォータ設定 |
| AI Agent 起動は OK だがツール呼び出し不安定 | 認証情報でなくツール側の複雑さ | ツールノードを 1 つのみにして検証 |
| ネイティブ AI ノードにパラメータ欠如 | n8n ノード実装未対応 | `HTTP Request` ノードで Crazyrouter を直接呼び出す |
| バッチタスクでのパフォーマンス不安定 | モデル適正やノード実装のミスマッチ | まず `gpt-5.5` で最小構成検証、その後モデル拡張 |

## パフォーマンス・コストの推奨事項

- 自動化タスクはまず `gpt-5.5` でベースラインを設定
- ループやバッチ、定期実行では厳しいクォータ・エラー通知を
- 本番用・デバッグ用ワークフローのトークン分割
- Agent ワークフローは少数ツール・短い連携で安定後に拡張
- 料金高騰時は Crazyrouter ログと n8n 履歴から再試行・ループ有無を確認

## FAQ

### n8n ではどの Base URL を入力すればいいですか？

`https://api.crazyrouter.com/v1` を入力してください。

### Base URL は認証情報とノードのどちらに入力しますか？

利用中の n8n バージョン画面を優先して確認。現行ドキュメントではノードレベルの `Base URL` オプションを明記。認証情報ページにも入力欄があればそこでも可。最初の設定はノードレベルを推奨します。

### まず使うべきはネイティブ AI ノード？HTTP Request ノード？

まずはネイティブ OpenAI 認証情報＋AI ノードを利用。パラメータ不足や詳細デバッグが必要な時だけ `HTTP Request` へ切り替えてください。

### 最初に推奨するモデルは？

`gpt-5.5` を先に使いましょう。

### ワークフローの費用が急増したのはなぜ？

大抵は単一リクエストではなく、ループ・バッチ・自動リトライや複数人によるワークフロー同時トリガーです。

### n8n で複数トークン分割は必須ですか？

少なくとも開発用・本番用は分離を強く推奨。高頻度処理は別トークン分割が理想です。

<Note>
n8n を Crazyrouter へ連携する価値は「モデル呼び出しができる」だけでなく、「モデルを自動化パイプラインに統合できる」ことにあります。そのため、肝心なのは一回の対話の正常応答ではなく、リトライ・ループ・バッチ処理・トークン配分まで一括管理することです。
</Note>
