Aider はとても便利な端末用ペアプログラミングツールであり、Gitリポジトリでの小さなステップによるコード修正、diffの審査、文脈ファイルの追加や段階的な修正に最適です。Crazyrouter と連携する場合は、Aider 公式がサポートする OpenAI 互換の設定方法が最も安全です。

## 概要

環境変数または `~/.aider.conf.yml` を使うことにより、Aider は Crazyrouter へリクエストを送信できます：

- 推奨プロトコル：`OpenAI-compatible API`
- Base URL：`https://api.crazyrouter.com/v1`
- 認証変数：`OPENAI_API_KEY`
- 推奨デフォルトモデル記述：`gpt-5.5`

<Tip>
日常的なワークフローが「コードを読む -> 数カ所直す -> diffを見る -> さらに修正する」という場合、Aider は軽量かつ安定して現場導入しやすい端末開発ツールのひとつです。
</Tip>

## 対象者

- 端末で小刻みなコード修正コミットを行いたい方
- 文脈ファイルや diff、コミットペースを明確に操作したい方
- Aider と Codex、Claude Code の課金管理を分けたい方
- まず最も直接的な OpenAI 互換方式で Crazyrouter に接続したい方

## 使用プロトコル

推奨プロトコル：`OpenAI-compatible API`

Aider 公式でサポートされる設定項目：

- `OPENAI_API_KEY`
- `OPENAI_API_BASE`
- `openai-api-key`
- `openai-api-base`

Crazyrouter の設定例：

```text
OPENAI_API_BASE=https://api.crazyrouter.com/v1
```

注意点：Crazyrouter におけるモデル名は、管理画面のモデルリストや pricing ページに表示されている元のモデルIDです。例として `gpt-5.5`、`claude-opus-4-8` です。Aider 側でもこのモデルIDを直接入力してください：

```text
gpt-5.5
```

<Warning>
Crazyrouter のモデル名には `openai/` プレフィックスを追加しないこと。`openai/gpt-5.5` は本サービスのモデル名ではなく、これを記載すると `model not found` やルートで利用不可となります。
</Warning>

## OS別の完全インストール手順

### Windows 推奨手順

Aider の Windows で最も安全な経路は：`Git` + `Python` + `PowerShell で Aider をインストールする` + `PowerShell で環境変数を設定する` です。

推奨作業順：

1. Git をインストール
2. Python をインストール
3. PowerShell で Aider 公式インストールスクリプトを実行、または `aider-install` を先に導入
4. PowerShell で一時変数を設定
5. PowerShell でユーザー固有の永続変数設定
6. 新しい端末を開いて `aider` コマンドと変数が有効か確認

推奨検証コマンド：

```powershell
git --version
python --version
pip --version
aider --version
where.exe git
where.exe python
where.exe aider
```

`aider --version` でコマンドが見つからない場合、PowerShell を閉じて再度開き、リトライしてください。

### macOS 推奨手順

Aider の macOS における最もスムーズな流れは：`Xcode Command Line Tools` + `Homebrew` + `Git` + `Python` + `Aider 公式インストールスクリプト` + `~/.zshrc` の永続環境変数設定です。

推奨作業順：

1. Xcode Command Line Tools のインストール
2. Homebrew のインストール（未導入の場合）
3. Git・Python のインストール
4. Aider 公式インストールスクリプト実行 または `aider-install` / `uv` でインストール
5. `~/.zshrc` の設定
6. 新しい端末を開いて `aider` コマンドと変数経路確認

推奨検証コマンド：

```bash
git --version
python3 --version
pip3 --version
aider --version
which git
which python3
which aider
```

### Linux の注意点

Linux は基本的に macOSの端末手順を参考にでき、永続環境変数は通常 `~/.bashrc` に記載します。ローカル開発や初回クラウド導入時には、まず現在のshellで一時的な変数を設定して動作確認、必要に応じて永続化してください。

## ゼロからの完全インストール手順

<Steps>
  <Step title="ステップ 1：Git をインストールする">
    マシンに Git が未導入の場合は必ず先にインストールしてください。

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install --id Git.Git -e --source winget
        git --version
        where.exe git
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        xcode-select --install
        git --version
        ```
        または：
        ```bash
        brew install git
        git --version
        which git
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo apt update
        sudo apt install -y git
        git --version
        which git
        ```
      </Tab>
    </Tabs>

    推奨追加：

    ```bash
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
    git config --global init.defaultBranch main
    ```
  </Step>

  <Step title="ステップ 2：Python と pip をインストールする">
    Aider 公式インストーラーは Python を用いるか、必要に応じて自分専用の Python 実行環境を自動準備します。トラブルシュートを見据え、事前にマシンの Python 動作を確認してください。

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install Python.Python.3.12
        python --version
        pip --version
        where.exe python
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        brew install python
        python3 --version
        pip3 --version
        which python3
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo apt update
        sudo apt install -y python3 python3-pip python3-venv
        python3 --version
        pip3 --version
        which python3
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="ステップ 3：Aider をインストールする">
    Aider の現状推奨ワンクリックインストールスクリプトはこちらです。

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        powershell -ExecutionPolicy ByPass -c "irm https://aider.chat/install.ps1 | iex"
        aider --version
        where.exe aider
        ```
      </Tab>
      <Tab title="macOS / Linux">
        ```bash
        curl -LsSf https://aider.chat/install.sh | sh
        aider --version
        which aider
        ```
      </Tab>
    </Tabs>

    インストールの詳細確認を重視したい場合、Aider 公式 `aider-install` 経路も選択可能です：

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        python -m pip install aider-install
        aider-install
        aider --version
        ```
      </Tab>
      <Tab title="macOS / Linux">
        ```bash
        python3 -m pip install aider-install
        aider-install
        aider --version
        ```
      </Tab>
    </Tabs>

    すでにチームで統一して `uv` を利用中の場合、公式ドキュメント通りに導入ください：

    ```bash
    python -m pip install uv
    uv tool install --force --python python3.12 --with pip aider-chat@latest
    aider --version
    ```

    <Warning>
    システム環境に手動で `pip install aider-chat` を直接配置することは初期導入では推奨しません。公式としてはインストールスクリプトや `aider-install`、`uv` を使った依存管理がより安定します。
    </Warning>
  </Step>

  <Step title="ステップ 4：Crazyrouter で Aider 専用 token を作成する">
    Crazyrouter 管理画面で `aider` という名前でトークンを作成し、初回は以下のみ許可してください：

    - `gpt-5.5`
    - `claude-opus-4-8`
    - `gemini-3.1-pro`

    <Note>
    このホワイトリストには Crazyrouter の元のモデル名のみ記載、`openai/` プレフィックス不要です。
    </Note>
  </Step>

  <Step title="ステップ 5：現在の端末で一時的に環境変数を設定する">
    まず一時的な設定を行い、動作確認後に永続設定へ移してください。

    <Tabs>
      <Tab title="macOS / Linux">
        ```bash
        export OPENAI_API_KEY=sk-xxx
        export OPENAI_API_BASE=https://api.crazyrouter.com/v1
        echo $OPENAI_API_KEY
        echo $OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        $env:OPENAI_API_KEY = "sk-xxx"
        $env:OPENAI_API_BASE = "https://api.crazyrouter.com/v1"
        echo $env:OPENAI_API_KEY
        echo $env:OPENAI_API_BASE
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="ステップ 6：環境変数を永続的な設定に書き込む">
    <Tabs>
      <Tab title="Linux Bash">
        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.bashrc
        echo 'export OPENAI_API_BASE=https://api.crazyrouter.com/v1' >> ~/.bashrc
        source ~/.bashrc
        echo $OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="macOS / Zsh">
        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.zshrc
        echo 'export OPENAI_API_BASE=https://api.crazyrouter.com/v1' >> ~/.zshrc
        source ~/.zshrc
        echo $OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        [System.Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "sk-xxx", "User")
        [System.Environment]::SetEnvironmentVariable("OPENAI_API_BASE", "https://api.crazyrouter.com/v1", "User")

        $env:OPENAI_API_KEY = "sk-xxx"
        $env:OPENAI_API_BASE = "https://api.crazyrouter.com/v1"

        echo $env:OPENAI_API_BASE
        ```
      </Tab>
    </Tabs>

    永続化後は新しい端末を開き、再度下記を実行することを推奨します：

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        aider --version
        echo $env:OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="macOS / Linux">
        ```bash
        aider --version
        echo $OPENAI_API_BASE
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="ステップ 7：オプションとして ~/.aider.conf.yml に書き込む">
    毎回手動でパラメータ追加したくない場合、設定ファイルへ記載しておくことも可能です。

    <Tabs>
      <Tab title="macOS / Linux">
        ```bash
        cat > ~/.aider.conf.yml <<'EOF'
        model: gpt-5.5
        openai-api-base: https://api.crazyrouter.com/v1
        EOF
        cat ~/.aider.conf.yml
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        @'
        model: gpt-5.5
        openai-api-base: https://api.crazyrouter.com/v1
        '@ | Set-Content -Path "$HOME/.aider.conf.yml"

        Get-Content $HOME/.aider.conf.yml
        ```
      </Tab>
    </Tabs>

    セキュリティ重視の場合は、key を環境変数のみに入れ、設定ファイルには `model` と `openai-api-base` のみ残す運用も可能です。
  </Step>

  <Step title="ステップ 8：Git リポジトリを準備し、最初のスナップショットを作成する">
    Aider の体験は Git リポジトリ内が最適です。現在ディレクトリが Git リポジトリでない場合：

    ```bash
    git init
    git add .
    git commit -m "chore: initial snapshot before Aider"
    ```

    既存リポジトリの場合は、まず状況を確認してください：

    ```bash
    git status
    ```
  </Step>

  <Step title="ステップ 9：Aider を起動して最初の認証を完了する">
    プロジェクトディレクトリへ入り、以下を実行してください：

    ```bash
    cd /path/to/your/project
    aider --model gpt-5.5
    ```

    初回検証は以下順序で進めることをおすすめします：

    1. `現在のリポジトリ構造のみを要約してください。ファイルの変更はしないでください。`
    2. `README を読んで、最小限の修正提案をしてください。直接修正はまだしないでください。`
    3. diff が正常表示されることを確認したら、小規模修正を行ってください

    <Tip>
    他のモデルを一時検証したい場合も同じ記述方式で、例えば `aider --model claude-opus-4-8`。
    </Tip>
  </Step>
</Steps>

## 推奨モデル設定

| 利用場面 | Aider 推奨記述 | 理由 |
|----------|----------------|------|
| デフォルト主力コーディング | `gpt-5.5` | Crazyrouter の元モデルID使用で、Aider OpenAI 互換の基準として最適 |
| Claude 系代替           | `claude-opus-4-8` | 長めの文脈解釈や、安定した多段一問一答協調用途に向く |
| Gemini バックアップ     | `gemini-3.1-pro` | 2番目の互換性検証経路として最適 |

まず `gpt-5.5` で動作確認、状況に応じて `claude-opus-4-8` や `gemini-3.1-pro` を追加してください。

## トークン設定ベストプラクティス

| 設定         | 推奨   | 説明                                     |
|--------------|--------|------------------------------------------|
| 専用トークン | 必須   | Aider と他の IDE / CLI でトークン共用しないこと |
| モデルホワイトリスト | 強く推奨 | 最小モデルセットを維持し、高額モデル誤切替を防ぐ |
| IP制限       | 環境次第 | 固定サーバーなら有効化も検討、モバイル開発機では慎重に |
| 使用量上限   | 強く推奨 | Aider は長いセッションやラウンド修正で消費が継続 |
| 環境分離     | 推奨   | ローカル・リモート・CIごとにトークン分離 |
| 流出対応     | 即時交換 | `.aider.conf.yml`、shell履歴や録画流出後は速やかにキー交換 |

## よくあるエラーと修復方法

| 現象 | よくある原因 | 修復方法 |
|------|----------|----------|
| `aider: command not found` | Aider のインストールが成功していない、またはインストーラが実行ファイルを PATH に登録していない | 公式インストーラを再実行し、新しいターミナルで再試行 |
| Pythonバージョンの混乱 | システムのPythonとAider実行環境が衝突している | インストールスクリプト、`aider-install` または `uv` を優先的に使い、複数の依存パッケージを混在させない |
| 401 unauthorized | API Key が間違っている、期限切れ、またはコピーが不完全 | トークンを再生成して再設定 |
| 403 / model not allowed | トークンで現在のモデルが許可されていない | Crazyrouter のトークン設定でモデルを許可 |
| 404 | Base URL が間違っている、または `/v1` が不足している | `https://api.crazyrouter.com/v1` に修正 |
| `model not found` | モデル名の記載ミス、存在しない`openai/`プレフィックスの使用、または該当モデルが当サイトで未公開 | pricingページやモデルリストにある元のモデルID（例：`gpt-5.5`、`claude-opus-4-8`）に戻す |
| 設定ファイルと環境変数の挙動不一致 | 両設定の衝突 | メイン設定元を一つにして、Aiderを再起動 |
| コスト急増 | 長いセッションや大量のコンテキストファイル | コンテキストを適宜整理し、トークン割当を制限 |

## パフォーマンスとコストのアドバイス

- 初回導入時は小規模レポジトリで検証する
- デフォルトは`gpt-5.5`を使い、クロス検証が必要な場合は`claude-opus-4-8`を追加
- プロジェクトタイプごとにトークンを分け、コストの統計がしやすいようにする
- 長いセッションでは不要ファイルの含有を避けるため、コンテキストを整理
- 大幅な変更時は必ずAider生成のdiffやCrazyrouter ログを確認

## FAQ

### AiderにはどのBase URLを入力すればよいですか？

`https://api.crazyrouter.com/v1`を入力してください。

### なぜモデル名を`openai/gpt-5.5`のように書いてはいけないのですか？

Crazyrouterのモデル名はベンダープレフィックスを付けません。実際に認識されるのは`gpt-5.5`のような元のモデルIDです。`openai/gpt-5.5`は別のモデル名として扱われ、当サイトにはそのモデルがありません。

### 環境変数と設定ファイル、どちらがおすすめですか？

どちらも可能です。まずは環境変数の方が速いですが、長期利用には`~/.aider.conf.yml`も設定すると良いです。

### なぜ初回はGitスナップショットを取るよう推奨しますか？

Aiderはファイルを変更したりdiffを生成したり、コミットやコミット提案を自動で行います。事前にスナップショットを取っておけば、トラブル時やロールバックが簡単です。

### 最初に推奨されるモデルは何ですか？

`gpt-5.5`が最初の推奨モデルです。

### Aiderは必ずGitレポジトリで使わないといけませんか？

必須ではありませんが、Gitレポジトリ内での利用経験が一番良く、変更結果のレビューも容易です。
