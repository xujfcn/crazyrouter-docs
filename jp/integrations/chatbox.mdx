ChatBox は、Windows、macOS、Linux をサポートする一般的なクロスプラットフォームAIクライアントで、Web版もあります。Crazyrouter と接続する際は、特定ベンダーのプリセットに頼らず、まず ChatBox の `OpenAI API Compatible` または `OpenAI API` を利用した設定を推奨します。

このやり方のメリットは：

- 設定が簡単、一般ユーザーにも素早く導入できる
- Crazyrouter で許可されたモデルを直接切り替え可能
- デスクトップでのチャット、ナレッジベースQ&A、ファイル補助読書など様々な用途に適応

## 結論から

まず下記の設定で始めることをおすすめします：

- Provider / APIモード：`OpenAI API Compatible` または `OpenAI API`
- API Host：`https://api.crazyrouter.com`
- API Path：デフォルトまたは空欄
- API Key：`sk-xxx`
- 最初の検証モデル：`gpt-5.5`

<Note>
ChatBox 公式ドキュメントによると、`API Path` は通常手動入力不要で、デフォルトは OpenAI 互換チャットパスです。したがって Crazyrouter のドキュメントでは、`API Host` はルートドメイン `https://api.crazyrouter.com` とします。`/v1/chat/completions` を手動で追加しないように推奨します。
</Note>

## 対象ユーザー

- デスクトップで Crazyrouter を素早く使いたい人
- 複数モデルの日常チャットや翻訳・要約・執筆補助をしたい人
- ローカルのナレッジベースやファイルQ&A能力を Crazyrouter と組み合わせたい人
- コードを書くつもりがなく、GUIだけで設定を完了したい人

## 前提条件

| 項目 | 説明 |
|------|------|
| Crazyrouterアカウント | [crazyrouter.com](https://crazyrouter.com) で登録 |
| Crazyrouterトークン | ChatBox 用の専用トークン作成を推奨 |
| ChatBoxクライアント | デスクトップ版インストールを推奨、ナレッジベース等の機能が充実 |
| 利用可能モデル | チャットモデルを最低1つ許可 |

初回は以下のみ許可することを推奨：

- `gpt-5.5`
- `claude-opus-4-8`
- `gemini-3.1-pro`

## ChatBox のインストール

### Windows

1. [ChatBox公式サイト](https://chatboxai.app/)を開く
2. Windowsインストーラーをダウンロード
3. ダブルクリックでインストール
4. 完了したら ChatBox を起動

### macOS

1. [ChatBox公式サイト](https://chatboxai.app/)を開く
2. macOSインストーラーをダウンロード
3. `Applications` にドラッグ
4. 初回起動時にシステムセキュリティ警告が出た場合は、案内に従い許可

### Linux

1. [ChatBox公式サイト](https://chatboxai.app/)を開く
2. お使いのディストリビューション用のインストーラーまたはデスクトップ版をダウンロード
3. インストール後 ChatBox を起動

<Tip>
Crazyrouter が ChatBox 上で動作するか、まず検証したい場合はデスクトップ版の利用を優先し、いきなり多数端末での同期やナレッジベース、複雑なモデルリストも同時に試そうとしないこと。
</Tip>

## 推奨設定方法

ChatBox のバージョンによって画面名が多少異なる場合がありますが、主な入り口は：

- `Settings`
- `Model Provider`
- `AI Provider`
- `Add`

もし現在のバージョンで `OpenAI API` プロバイダーが内蔵されていれば、そのまま選択してください。なければ `OpenAI API Compatible` プロバイダーを新規追加します。

## 設定手順

<Steps>
  <Step title="ステップ 1：Crazyrouter で ChatBox 専用トークンを作成する">
    初回はモデルを1～2個だけ許可するのがおすすめ：

    - `gpt-5.5`
    - `claude-opus-4-8`

    モデルが多いとトラブルシュート範囲が広がるため、絞ると問題の特定が容易です。
  </Step>

  <Step title="ステップ 2：ChatBox の設定を開く">
    ChatBox 起動後、左下の設定入口をクリックし、以下を開きます：

    - `Model Provider`
    - または `AI Provider`
  </Step>

  <Step title="ステップ 3：OpenAI 互換プロバイダーを選択または新規追加する">
    下記2つのケースをおすすめします：

    - `OpenAI API` があれば選択
    - なければ `Add` をクリックし、`OpenAI API Compatible` プロバイダーを新規追加
  </Step>

  <Step title="ステップ 4：Crazyrouter の接続情報を入力する">
    推奨入力内容：

    - `API Host`: `https://api.crazyrouter.com`
    - `API Path`: デフォルトまたは空欄
    - `API Key`: `sk-xxx`

    プロバイダー名の入力欄があれば `Crazyrouter` としてもOKです。
  </Step>

  <Step title="ステップ 5：最初のモデルを追加する">
    初回は1モデルだけ追加を推奨：

    - `gpt-5.5`

    最小経路検証が通れば、順次追加：

    - `claude-opus-4-8`
    - `gemini-3.1-pro`
  </Step>

  <Step title="ステップ 6：Check または Save を使ってまず接続テストを行う">
    ChatBox のバージョンに `Check` ボタンがあれば、まず `Check` を押してください。

    `Save` しかなければ、一度保存し、メイン画面に戻って新規チャットでテストします。
  </Step>

  <Step title="ステップ 7：メイン画面で最初の最小限の検証を行う">
    新しいチャットを作成し、現行モデルが `gpt-5.5` であることを確認し、次を入力：

    ```text
    Reply only OK
    ```

    `OK` または近い結果が安定して返れば、ChatBox から Crazyrouter へのメイン経路は通っています。
  </Step>
</Steps>

## 推奨検証順序

下記の流れで進めることを推奨、一度に多数モデルや機能を試さない：

1. トークンはまず1つだけ設定
2. モデルもまず1つ `gpt-5.5` のみ設定
3. まずはテキストチャット検証
4. 次に2つ目のモデルを追加
5. 最後にナレッジベース、ファイルQ&A、複雑な会話パラメータを追加

## 推奨モデル

| シーン | 推奨モデル | 理由 |
|------|----------|------|
| 初回接続性検証 | `gpt-5.5` | 当日動作実績あり、OpenAI互換ベースライン検証に最適 |
| 高品質執筆・説明 | `claude-opus-4-8` | 複雑な説明・校正・要約に最適 |
| Geminiバックアップ | `gemini-3.1-pro` | 同一クライアントでOpenAI系以外をクロス検証可能 |

## ChatBox の主要機能と Crazyrouter の連携例

### 通常チャット

最も簡単なので、まず設定が正しいか検証に使う。

### ナレッジベース／ファイルQ&A

通常チャットで問題ないことを確認してから開始。初回は：

- ファイルはできるだけ小さく
- 内容はできるだけ明確に
- まずは単一ファイルでQ&A検証

API設定が正しいか未確定の状態では、多数ファイルや大規模ナレッジベースは避けてください。

### 複数モデル切り替え

ChatBox でタスク分担等に活用可能：

- 基本チャット：`gpt-5.5`
- 要約・執筆など重要タスク：`claude-opus-4-8`
- 初回標準検証：`gpt-5.5`

## パラメータ推奨値

ChatBox が各種サンプリングパラメータをサポートする場合、初回は控えめ設定がおすすめ：

| パラメータ | 推奨値 | 説明 |
|------|--------|------|
| Temperature | `0.2` から `0.7` | 初回検証では高め設定は避ける |
| Max Tokens | デフォルトまたは中程度 | 出力が長すぎるとトラブルシュート困難に |
| Context Messages | デフォルト維持 | まずは基本チャットの検証のみ |

## トークン利用のベストプラクティス

| 設定 | 推奨 | 説明 |
|------|------|------|
| 専用トークン | 必須 | IDEや自動化フローと共有しない |
| モデルホワイトリスト | 強く推奨 | まず1～2モデルのみ許可 |
| クォータ上限 | 強く推奨 | ナレッジベース大量Q&Aで消費が急拡大するのを防ぐ |
| 環境別トークン | 推奨 | 個人とチームで別トークンを分離 |
| 流出時対応 | 即時ローテーション | スクリーンショット・録画・画面共有で漏れた場合、速やかにKey交換 |

## よくあるエラーと修復方法

| 症状 | 主な原因 | 修復方法 |
|------|----------|----------|
| 401 unauthorized | トークン不正・コピーミス・失効 | トークン再生成・再コピー |
| 404 | Host・Path の入力ミス | Host を `https://api.crazyrouter.com` に戻し、Path はデフォルト維持 |
| 403 / モデル未許可 | トークンで該当モデルを許可していない | Crazyrouterトークン設定でモデル許可 |
| `model not found` | モデル名のスペルミス | まず `gpt-5.5` で最小検証へ戻す |
| 保存成功だがチャット失敗 | Provider 選択ミス・モデル未追加 | Provider タイプ・モデルリスト再確認 |
| ナレッジベースQ&A遅い・失敗 | ファイルサイズ過大・タスク複雑 | 小サイズファイル・テキストQ&Aへ戻す |
| `/v1` を入力すべきかわからない | 現バージョンは通常手動入力不要 | Host はルートドメイン、Pathは空欄またはデフォルトを推奨 |

## FAQ

### ChatBoxではどのProviderを選べばよい？

`OpenAI API` または `OpenAI API Compatible` を優先して選択してください。

### API Host の入力値は？

`https://api.crazyrouter.com` を入力します。

### `/v1/chat/completions` を手動入力すべきか？

通常不要。ChatBox公式ドキュメントでは`API Path` がデフォルト値として設定されているので、まずはデフォルトまたは空欄のままにしてください。

### 最初のモデルには何を設定するのが推奨？

まず `gpt-5.5` を入力します。

### どのタイミングでモデル・ナレッジベースを追加すべき？

最小チャット経路が通ってから、段階的に追加します。

<Note>
「まず ChatBox を動くようにする」場合、一気に多くのモデルや機能を設定するより、`gpt-5.5` を使って最小チャット経路の検証を先に行うのがおすすめです。
</Note>
