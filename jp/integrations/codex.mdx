> 内容更新日: 2026-06-09

Codex CLI は OpenAI 提供のターミナル用コーディングエージェントです。ローカルリポジトリでのコード修正、レビュー、大規模なリファクタリングやコマンド連携に適しています。Crazyrouter を連携する際は、現行正式対応の `config.toml` カスタム provider 手法を推奨します（旧方式は非推奨）。

## 概要

`~/.codex/config.toml` でカスタム provider を設定すると、Codex CLI は Crazyrouter にリクエストを中継できます：

- 推奨プロトコル：`OpenAI-compatible API`
- 利用する API 種類：`Responses API`
- Base URL：`https://api.crazyrouter.com/v1`
- 認証用変数：`OPENAI_API_KEY`
- 推奨デフォルトモデル：`gpt-5.5`

<Tip>
ChatGPT のみ使っていた場合、Crazyrouter に繋ぐ際は API Key とカスタム provider の設定へ切替えてください。モデル、ログ、利用枠、課金管理が細かく制御可能になります。
</Tip>

  環境変数や Codex 設定をスクリプトで直接書込む場合は crazyrouter-codex-cli リポジトリを参照ください。
</Card>

## 想定ユースケース

- Crazyrouter をターミナル主導型のコーディングワークフローに統合したい方
- ローカルのリポジトリでバルク編集、コードレビュー、自動実行をしたい方
- Codex、Cursor、Claude Code のトラフィックごとに課金管理したい方
- 現行 OpenAI 最新モデルで端末コーディングを効率化したい方

## 利用プロトコル

推奨プロトコル：`OpenAI-compatible API`

Codex CLI は現在カスタム `model_provider` で OpenAI 互換の provider を推奨しており、以下を指定します：

- `base_url = "https://api.crazyrouter.com/v1"`
- `wire_api = "responses"`

<Note>
Crazyrouter は `/v1/responses` をサポートしているため、Codex CLI 連携時は Responses API ルートを直接利用可能です。ただしこのルートは GPT 系の理解で進めてください。Claude は `POST /v1/responses` をサポートしていません。
</Note>

## システム要件と前提条件

| 項目 | 内容 |
|------|------|
| Crazyrouter アカウント | 先に [crazyrouter.com](https://crazyrouter.com) で登録 |
| Crazyrouter トークン | Codex 用の `sk-...` トークンを新規作成推奨 |
| Git | `git 2.23+` 推奨 |
| Node.js | `Node.js 20+` 推奨 |
| Codex CLI | 現行安定版推奨 |
| 利用可能モデル | コーディング用途向け最低1つ（例：`gpt-5.5`） |

初期許可リスト（ホワイトリスト）は以下がおすすめです：

- `gpt-5.5`

## OS ごとインストール推奨手順

### Windows 推奨フロー

Windows では、Codex の最も簡単な導入経路は：`Git` + `Node.js` + `npm で Codex をグローバルインストールする` + `PowerShell で環境変数を設定する` です。

おすすめの順番：

1. Git をインストール
2. Node.js LTS をインストール
3. npm で Codex CLI をインストール
4. PowerShell で `OPENAI_API_KEY` を書き込み
5. PowerShell で `$HOME/.codex/config.toml` を書き込み

推奨動作確認コマンド：

```powershell
git --version
node -v
npm -v
codex --version
where.exe git
where.exe node
where.exe codex
```

`codex --version` でコマンドが見つからない場合は、一度 PowerShell を閉じて再度開き、再試行してください。

### macOS 推奨フロー

macOS では、ベストプラクティスは基本的に：`Homebrew` + `Git` + `Node.js` + `brew` あるいは `npm` で Codex CLI をインストールし、`~/.zshrc` で環境変数を永続化します。

おすすめの順番：

1. Xcode Command Line Tools をインストール
2. Homebrew をインストール（未導入の場合）
3. Git、Node.js をインストール
4. Codex CLI をインストール
5. `~/.zshrc` を書き込み
6. `~/.codex/config.toml` を書き込み

推奨動作確認コマンド：

```bash
git --version
node -v
npm -v
codex --version
which git
which node
which codex
```

### Codex CLI インストール代替パス

パッケージマネージャ以外にも、Codex 公式リポジトリから GitHub Releases のバイナリで直接導入可能です。多くのケースでは下記を優先的におすすめします：

- Windows：`npm install -g @openai/codex`
- macOS：`brew install --cask codex` または `npm install -g @openai/codex`

Crazyrouter 関連の自動設定スクリプトを利用したい場合は [crazyrouter-codex-cli](https://github.com/xujfcn/crazyrouter-codex-cli) も参照できます。
当ドキュメントでは全手動設定手順も記載していますので、導入内容をすべて確認したい場合も安心です。

## 推奨モデル設定

| 利用場面 | 推奨モデル | 理由 |
|----------|----------|------|
| 標準コーディング | `gpt-5.5` | 2026年3月23日時点の実運用実績あり。Codex／Responses API 主軸に最適です。 |

Claude 利用時は Claude 本来の `POST /v1/messages` か OpenAI 互換の `POST /v1/chat/completions` を利用し、Codex の `wire_api = "responses"` ルートには適用しないでください。

### 国産モデルの純正対応状況

`2026-05-15` の再検証を踏まえて、Crazyrouter 上で **原生 `POST /v1/responses`** かつ Codex CLI で安定利用可能な国産モデルは、現状下記のみ明記推奨です：

| モデル | 現状評価 | 備考 |
|------|----------|------|
| `kimi-k2.5` | 推奨 | `/v1/responses` SSE で `response.completed` まで取得 OK。Codex でのレス・ファイル読取も正常。 |
| `kimi-k2.6` | 推奨 | `kimi-k2.5` と同等で、国産主力枠として問題なし。 |
| `MiniMax-M2.7` | 非推奨 | 最低限 Responses プローブで `convert_request_failed` が発生。ファイル読取も `response.completed` 前に停止。 |
| `deepseek-v4-pro` | 非推奨 | Claude Code は利用可。ただし Codex 向け Responses ルートは 500／高負荷／リトライ失敗が起きやすい。 |
| `glm-5.1` | 非推奨 | 現行 Responses ネイティブルートはこのモデル未対応上流で終了し、Codex 側で `stream closed before response.completed` となる。 |

Codex で国産モデル評価をしたい場合、まずトークン許可一覧を以下のみに絞り：

- `gpt-5.5`
- `kimi-k2.5`
- `kimi-k2.6`

`MiniMax-M2.7`、`deepseek-v4-pro`、`glm-5.1` を Codex のデフォルト許可枠に直接追加するのは非推奨です。実験的挙動や切断再試を許容する場合のみ検討ください。

### 国産モデル切替方法

`base_url = "https://api.crazyrouter.com/v1"` や `wire_api = "responses"` は現行維持で、`model` フィールドのみ切替えて下さい。例：

```toml
model = "kimi-k2.5"
model_provider = "crazyrouter"

[model_providers.crazyrouter]
name = "Crazyrouter"
base_url = "https://api.crazyrouter.com/v1"
env_key = "OPENAI_API_KEY"
wire_api = "responses"

[profiles.crazyrouter]
model = "kimi-k2.5"
model_provider = "crazyrouter"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

初めて国産モデルに切り替える際は、引き続きこの順序で検証することをおすすめします：

1. `Reply only OK`
2. `Read the repository structure only. Do not edit files.`
3. `Read agent.md and reply with exactly the first Markdown heading text.`

## Token設定ベストプラクティス

| 設定 | 推奨 | 説明 |
|------|------|------|
| 専用トークン | 必須 | CodexはCursor・Claude Codeとトークンを共有しないでください |
| モデルホワイトリスト | 強く推奨 | Codexが実際に呼び出すモデルだけ開放 |
| IP制限 | 固定出口環境では推奨 | 個人端末がネットワークを頻繁に変える場合は慎重に利用 |
| クォータ上限 | 強く推奨 | Codexのプロキシ実行は短時間で消費が進みやすいです |
| 環境分離 | 推奨 | ローカル開発・リモートサーバ・CIごとにトークンを分ける |
| 漏洩時の対応 | 即時ローテーション | シェル履歴・設定バックアップ・画面共有などでトークンが露出した場合はすぐ交換 |

## よくあるエラーと対処法

| 現象 | 主な原因 | 修復方法 |
|------|----------|----------|
| `codex: command not found` | CLIインストール失敗またはグローバルnpmパスがPATHに未設定 | Codexを再インストールし、npmグローバルbinがPATHに入っているか確認 |
| 401 unauthorized | `OPENAI_API_KEY` が間違い・期限切れ・コピーに空白混入 | 新しいトークンを生成し、環境変数を再セット |
| 403 / model not allowed | トークンで現モデルが有効化されていない | Crazyrouterのトークン設定で該当モデルを有効化 |
| 404 | `base_url` 記述ミス、または`/v1` を忘れた | `https://api.crazyrouter.com/v1` に訂正 |
| リクエスト構造エラー | `wire_api` が`responses` でない | `wire_api = "responses"` に訂正 |
| CLI起動するがリクエストがCrazyrouter経由しない | `model_provider` で`crazyrouter` に切り替えていない | `config.toml` のprovider設定を確認 |
| Git変更がレビューしづらい | 事前にリポジトリスナップショットを取っていない | 初期スナップショットをコミットしてからCodexで実際の変更 |
| コスト急増 | 長いコンテキスト・多段ツール呼び出し・複数リポジトリで同一トークン共用 | トークン分割・クォータ制限・モデルホワイトリスト縮小 |

## パフォーマンスとコストのアドバイス

- 最初は小さいリポジトリで接続検証してください。初回から巨大リポジトリ全タスク実行は避けましょう
- 基本ルートは`gpt-5.5`推奨。まずGPT/Responsesの主経路が動作することを確認
- CodexとIDE系ツールとで請求を分離し、高消費箇所の特定を容易に
- ハイリスクなリポジトリやCI環境には厳格なトークンクォータを設定
- 高消費イベントがあったときは、まずCrazyrouterのログで多段プロキシ挙動が原因か確認

## FAQ

### Codex CLIのBase URLは何を書く？

`https://api.crazyrouter.com/v1` にしてください。

### WindowsではPowerShellとGit Bashどちら推奨？

最初のセットアップはドキュメント記載のPowerShell手順がおすすめ。ユーザー環境変数や`$HOME/.codex/config.toml`とも親和性が高いです。

### ここで`wire_api = "responses"`を設定する理由は？

Codex CLIのカスタムprovider推奨方式がResponsesAPI経由運用のため、Crazyrouterが`/v1/responses`に対応しています。

### ここでClaudeを推奨しない理由は？

現在Claudeは`POST /v1/messages`と`POST /v1/chat/completions`のみ対応で、`POST /v1/responses`は未対応。Codexのこの経路は`wire_api = "responses"`で決め打ちなのでClaudeは非推奨です。

### なぜ最初にGitスナップショット推奨？

Codexはファイル改変やコマンド実行も行うエージェントのため、先にスナップショットを取ればレビューやロールバックが簡単になります。

### 既に`codex login`でもAPI Key設定が必要？

必要です。Crazyrouter連携時は`OPENAI_API_KEY`とカスタムprovider設定が必要です。

### 最初の推奨モデルは？

最初は`gpt-5.5`推奨。

<Note>
OpenAI/Responses APIルートで最もスムーズな端末エージェント体験を得たい場合、CodexはGPT/Responsesルートで構成してください。Claudeを使いたい場合はClaude CodeあるいはClaudeネイティブAPIのドキュメントを参照してください。
</Note>
