Cherry Studio は、デスクトップで複数モデルのチャット、知識整理、MCP ツール連携に適した AI クライアントです。Crazyrouter と連携する場合、Cherry Studio の `OpenAI` カスタムプロバイダーモードを利用することを推奨します。この方法がモデルリストやストリーム出力、通常のチャット機能との互換性を最も簡単に実現できます。

## 概要

Cherry Studio のカスタムプロバイダー機能を使えば、Crazyrouter を OpenAI 互換の上流として接続できます：

- 推奨プロトコル：`OpenAI-compatible API`
- 推奨プロバイダータイプ：`OpenAI`
- API アドレス：`https://api.crazyrouter.com`
- 認証方式：`sk-...` トークン
- 推奨の初回認証モデル：`gpt-5.5`

<Note>
Cherry Studio 公式ドキュメントより：もし上流のインターフェースが `https://xxx.com/v1/chat/completions` のような形式の場合、`API アドレス` には通常ルートアドレスのみを入力します。つまり、Crazyrouter を連携する際は `https://api.crazyrouter.com` を優先的に入力し、`https://api.crazyrouter.com/v1` ではありません。
</Note>

<Tip>
Cherry Studio は標準の残りパスを自動的に補完します。上流が通常の `.../v1/chat/completions` ルーティングでない場合のみ、`API アドレス` で完全なアドレスを手動入力し、`#` で終わるようにしてください。Crazyrouter の通常チャット接続ではそれをする必要はありません。
</Tip>

## このような方におすすめ

- デスクトップで複数モデルを一括管理したい方
- Crazyrouter を日常チャット、ライティング、翻訳、資料整理に使いたい方
- MCP ツールをローカルチャットクライアントに接続したい方
- ひとつの画面で低コストモデルと高性能モデルを素早く切り替えたい方

## 利用プロトコル

推奨プロトコル：`OpenAI-compatible API`

推奨の接続方法は、新規 `OpenAI` タイプのカスタムプロバイダーを追加し、Crazyrouter のルートドメインを `API アドレス` に入力することです：

```text
https://api.crazyrouter.com
```

最初から以下を入力しないでください：

- `https://api.crazyrouter.com/v1/chat/completions`
- `https://api.crazyrouter.com/v1/models`

特殊で標準外のルーティングを使用している場合のみ、Cherry Studio で完全なアドレスを手動で入力し、`#` で終わるようにしてください。Crazyrouter の通常チャット接続ではこの必要はありません。

## 前提条件

| 項目 | 説明 |
|------|------|
| Crazyrouter アカウント | まず [crazyrouter.com](https://crazyrouter.com) で登録 |
| Crazyrouter トークン | Cherry Studio 用に専用の `sk-...` トークンを作成推奨 |
| Cherry Studio | 現在の安定版デスクトップクライアント利用推奨 |
| 利用可能モデル | 少なくとも当日検証済有効なチャットモデルを 1 つ用意 (例：`gpt-5.5`) |

最初のホワイトリスト推奨モデル：

- `gpt-5.5`
- `claude-opus-4-8`
- `gemini-3.1-pro`

## 5分で素早く始める

<Steps>
  <Step title="Cherry Studio専用トークンを作成">
    Crazyrouter の管理画面で新しいトークンを作成し、名前は `cherry-studio` など分かりやすいものにします。最初は、確実に使う 2～4 モデルだけ許可し、全モデルを一気に開放しないでください。
  </Step>
  <Step title="カスタムプロバイダを追加">
    Cherry Studio を開き、`設定` → `モデルサービス` に進み、下部の `追加` または `+ Add` をクリックします。プロバイダータイプは `OpenAI` を選び、名前は `Crazyrouter` を推奨。
  </Step>
  <Step title="接続情報を入力">
    プロバイダー設定画面で次を入力：
    - `API Key`: あなたの `sk-...`
    - `API アドレス`: `https://api.crazyrouter.com`

    入力後は `チェック` をクリックし、トークンとアドレスが有効か確認します。
  </Step>
  <Step title="モデルを取得して追加">
    `管理` または `Manage` をクリックしてモデルリストを取得、そして必要なモデルをこのプロバイダーに手動で追加。注意：ポップアップにモデルが表示されても、まだ利用可能リストに入っていません。通常もう一度 `+` を押す必要があります。まずは基準となるモデル（例：`gpt-5.5`）だけ追加がお勧めです。
  </Step>
  <Step title="プロバイダを有効にして初回チャットを行う">
    右上の有効化スイッチをオンにし、チャット画面に戻って `gpt-5.5` を選んで、簡単なリクエスト（例：`Reply only OK`）を送信。正常返答が来れば、他のモデルを追加し始めてください。
  </Step>
</Steps>

## 推奨モデル設定

| 利用シーン | 推奨モデル | 理由 |
|----------|----------|------|
| デフォルト主力チャット | `gpt-5.5` | 当日実測OK・OpenAI互換主基準に最適 |
| 高品質コード/長文 | `claude-opus-4-8` | 強力な推論・ライティング・コード解説に向く |
| Gemini 予備 | `gemini-3.1-pro` | 2つ目のプロバイダー対応確認ラインに適合 |

推奨の手順：まず `gpt-5.5` で動作確認し、その後徐々に `claude-opus-4-8`・`gemini-3.1-pro` を追加してください。

## Token 設定のベストプラクティス

| 設定 | 推奨 | 説明 |
|------|------|------|
| 専用トークン | 必須 | Cherry Studio 用トークンは Cursor、Claude Code、Codex と共用しないこと |
| モデルホワイトリスト | 強く推奨 | Cherry Studio で本当に使うモデルのみ開放 |
| IP制限 | 環境に応じて | 固定オフィスネットなら使用推奨、頻繁にネット切替するノートPCなら注意 |
| クォータ上限 | 強く推奨 | デスクトップチャットクライアントは高頻度利用しやすいので別枠で制限 |
| 開発/本番分離 | 推奨 | 個人/共有/デモ端末でトークンを分けて運用 |
| 複数Keyラウンドロビン | 慎重に | Cherry Studio は複数keyラウンドロビン可だが、トラブル時に複雑化、まずは1 key で安定動作確認を |

## MCP 利用アドバイス

Cherry Studio は MCP サービスも利用できますが、次の2段階テストを推奨します：

1. まず Crazyrouter のチャットモデルが安定して動くかだけ確認
2. その後、MCP サービスを個別追加し各ツールを順次テスト

これによりモデル接続問題と MCP ツール問題を混同せず切り分けられます。

MCP を有効にする場合：

- まずツール呼び出しが安定しているモデルを選ぶこと
- MCP サービスは最初は 1 件だけ掛けて検証
- ツールの初回呼び出しは最もシンプルな読取・検索からテスト

## よくあるエラーと修復方法

| 現象 | 原因 | 修復方法 |
|------|----------|----------|
| `チェック` に失敗 | `API Key` エラーまたは空白付きコピペ | トークンを再生成し、純粋な `sk-...` だけ貼り付ける |
| 401 unauthorized | トークンの有効期限切れや削除済み | Crazyrouterの管理画面で新規トークン生成・差し替え |
| 403 / model not allowed | トークンのホワイトリストに対象モデルなし | トークン設定で当該モデルを許可 |
| 404 | `API アドレス` を完全なAPIパスで入力した、またはプロバイダータイプミス | `OpenAI` タイプに戻し、アドレスを `https://api.crazyrouter.com` に修正 |
| `チェック` が失敗するがアドレスとKeyは合っている | Cherry Studioは現在のモデルリスト内最後の会話モデルで疎通確認するが、そのモデルが無効な場合あり | まず `gpt-5.5` だけ残し、怪しいモデル削除後 `チェック` を再実行 |
| モデルリストの取得不可 | アドレス誤り・ネットワーク問題・プロバイダー未有効 | まず `チェック` を押し、スイッチとネット接続を再確認 |
| 接続はOKでもチャット時エラー | 非互換・使用不可なモデルを追加した | まず `gpt-5.5` のみで疎通（基準テスト）実施 |
| ストリーム出力異常 | モデル自体・クライアントバージョンの互換性問題 | `gpt-5.5` に戻し Cherry Studioをアップデート |
| MCPツール呼び出し失敗 | モデル問題でなく MCPサービス設定不備 | 一旦MCPを無効化しモデルのみ検証、MCPは別途修正 |

## 性能とコスト面アドバイス

- 最初は1～2モデルのみ使用し、モデル数が多すぎて混乱しないよう注意
- デフォルトはまず `gpt-5.5` で、複雑な長文やコード説明時に `claude-opus-4-8`に切替
- ロングチャットが多い人は Cherry Studio用に個別クォータ設定推奨
- Cherry Studioは複数モデル切替可だが、高額モデルは重要タスクのみに絞ると良い
- 消費が異常に多い時は、Crazyrouterのログで高頻度リトライ/長文連続会話が無いか確認

## FAQ

### Cherry Studio にはどのアドレスを書けば良いですか？

`https://api.crazyrouter.com` を優先的に入力してください。

### なぜ最初から `/v1` を勧めないのですか？

Cherry Studio の公式見解によれば、多くの OpenAI 互換上流はルートのみでよく、クライアントが自動でパスを補います。Crazyrouter でもこの方法が推奨です。

### APIフルURL+`#` 必要なシーンは？

上流が標準OpenAIルートで無い場合のみです。Crazyrouterの通常チャット接続では不要、まずはルートドメインで試してください。

### 最初の推奨モデルは？

まず `gpt-5.5` を推奨します。

### 最初から沢山モデル追加可能？

可能ですが、いきなり全て入れるのは推奨しません。まず1モデルで疎通確認し、徐々に増やしてください。

### Cherry StudioはCrazyrouterと MCP 併用可能？

可能ですが、まずチャットモデル疎通確認後、MCPを順次有効化したほうが不具合の特定がしやすいです。

<Note>
デスクトップでの多モデルチャットや MCP の軽量連携を目的とする場合、Cherry Studioは最適な選択です。IDEでのコード代理体験が最重要なら、Cursor、Claude Code、Codex、Cline などの利用を優先してください。
</Note>
