# チャット完了オブジェクト

`/v1/chat/completions`はストリーミングされないリクエストの場合は`chat.completion`、ストリーミングされるリクエストの場合は`chat.completion.chunk`を返します。

このページでは、Crazyrouterで最も安定して幅広く利用されている、OpenAI互換のレスポンス構造に注目しています。

## ストリーミングされないオブジェクト

最小限の本番用リクエスト例:

```bash cURL
curl https://api.crazyrouter.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-5.5",
    "messages": [
      {
        "role": "user",
        "content": "Explain what a REST API is in one sentence."
      }
    ],
    "max_tokens": 64
  }'
```

一般的な本番用レスポンススケルトン:

```json
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion",
  "created": 1774177466,
  "model": "gpt-5.5",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "...",
        "reasoning_content": null,
        "tool_calls": null
      },
      "finish_reason": "stop"
    }
  ]
}
```

### 読み方について

- `message.content`は最終的なテキスト回答です
- `message.tool_calls`はモデルがツール実行を要求する場合にのみ現れます
- `message.reasoning_content`は一部のモデルやルートで出現する可能性がありますが、現時点では必須項目として扱うべきではありません

## ストリーミングオブジェクト

ストリーミングリクエストの場合、サーバーは`chat.completion.chunk` SSEイベントを返します:

```json
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion.chunk",
  "created": 1774177466,
  "model": "gpt-5.5",
  "choices": [
    {
      "index": 0,
      "delta": {
        "role": "assistant",
        "content": "..."
      },
      "finish_reason": null
    }
  ]
}
```

一般的なSSEの構造:

```text
data: {"object":"chat.completion.chunk",...}
data: {"choices":[{"delta":{"content":"..."}}],...}
data: [DONE]
```

---

## よく使われる項目

| フィールド | 意味 |
|-------|---------|
| `object` | 非ストリーミング時は`chat.completion`、ストリーミング時は`chat.completion.chunk` |
| `model` | レスポンスに使用された実際のモデル |
| `choices[].message.content` | ストリーミングされない最終テキスト |
| `choices[].message.tool_calls` | ストリーミングされないツール要求 |
| `choices[].delta.content` | ストリーミングテキストの差分 |
| `choices[].finish_reason` | `stop`、`length`、`tool_calls`などの停止理由 |

<Note>
  上流のモデルによって追加のフィールドが流されることがあります。クライアントコードでは、安定した共通フィールドを最優先に利用し、すべてのモデルが同じ拡張を提供していると仮定しないようにしてください。
</Note>
