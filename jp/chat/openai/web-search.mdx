# ウェブ検索

このページでは、`2026-03-22`上のCrazyrouter本番環境で再検証された、OpenAIスタイルのウェブ検索挙動のみを記載しています。

現在の主なパスは以下の通りです：

- `gpt-5.5`
- `POST /v1/responses`
- `tools: [{ "type": "web_search_preview" }]`

## 現時点での結論

本日の本番再確認では：

- Responses APIを通じた`gpt-5.5`は安定して`web_search_call`を返しました
- 従来型のChat Completionsプローブである`tools: [{ "type": "web_search" }]`は`200`を返しましたが、安定的かつ検証可能な検索トリガー信号を得られなかったため、主な記載パターンとはしていません

---

## 検証されたリクエスト

```bash cURL
curl https://api.crazyrouter.com/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-5.5",
    "input": "Use web search to find one current technology headline published recently.",
    "tools": [
      {
        "type": "web_search_preview"
      }
    ]
  }'
```

検証済み`output.type`値：

```json
["web_search_call", "message"]
```

これにより、検索プロセスと最終回答が別々に返ってくることを示しています。

---

## Python例

```python Python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="https://api.crazyrouter.com/v1"
)

response = client.responses.create(
    model="gpt-5.5",
    input="Use web search to find one current technology headline published recently.",
    tools=[
        {"type": "web_search_preview"}
    ]
)

print(response.output_text)
```

---

## 検索が実際に実行されたかの確認方法

`response.output`を直接確認してください：

```python Python
for item in response.output:
    print(item.type)
```

次のような内容が見られた場合：

```text
web_search_call
message
```

モデルが最初に検索を行い、その後回答したことになります。

---

## 主な方法としては推奨されない旧パターン

今回の本番再確認では、旧型のChat Completionsの型についても調査しました：

```json
{
  "tools": [
    {
      "type": "web_search"
    }
  ]
}
```

結果：

- リクエストは`200`を返却しました
- しかし、安定した検証可能な検索トリガーマーカーは検出されませんでした

したがって、Crazyrouterのドキュメントでは、現在OpenAIスタイルのウェブ検索は主にResponses API経由で記載するべきです。
