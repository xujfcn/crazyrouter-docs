# Gemini オーディオ理解

```text
POST /v1beta/models/{model}:generateContent
```

`2026-04-08` 時点で、Crazyrouter 当サイト及びローカル `4000` ポートでの再テストの結論：

- `gemini-3.1-pro` は `audio/wav` を読み取ることが可能です
- 現在安定して稼働確認済みのメイン経路は `inlineData` です
- 短い音声に対する文字起こし、言語判定、要約説明は全てテキストプロンプトで直接実行できます

---

## 検証済みの最小リクエスト

```bash
curl "https://api.crazyrouter.com/v1beta/models/gemini-3.1-pro:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "inlineData": {
              "mimeType": "audio/wav",
              "data": "BASE64_WAV_DATA"
            }
          },
          {
            "text": "请返回 JSON，字段为 transcript、language、summary。"
          }
        ]
      }
    ],
    "generationConfig": {
      "maxOutputTokens": 512
    }
  }'
```

本番環境で同様条件下にて返却された成功形式の主要パターン：

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "```json\n{\n  \"transcript\": \"叮\",\n  \"language\": \"zh-CN\",\n  \"summary\": \"音频中包含一个简短的提示音。\"\n}\n```"
          }
        ]
      }
    }
  ]
}
```

## リクエストの要点

- オーディオ理解には`inlineData`の優先利用を推奨
- `mimeType`は実際の音声フォーマットと一致させてください（例：`audio/wav`、`audio/mpeg`）
- `data`にはBase64データのみを記載し、Data URLのプリフィックスは含めないでください
- 厳密なJSON形式が必要な場合は、[構造化出力](/jp/features/structured-outputs)制約を追記してください

<Note>
  本ページは、すでに稼働が確認された短い音声理解のメインパスをまとめています。より長いオーディオの文字起こしや音声生成については、それぞれ既存の [STT](/jp/audio/stt)、[TTS](/jp/audio/tts) ページをご覧ください。Realtimeは現在、公開向けの推奨事例としては記載していません。
</Note>
