# Gemini と OpenAI 互換モデル一覧

```
GET /v1beta/openai/models
```

このエンドポイントは互換ブリッジです：

- 認証方式は Gemini スタイルでも利用可能です
- レスポンス構造は OpenAI スタイルのモデル一覧です

このページでは `2026-03-23` が Crazyrouter の本番環境で確認済みの動作のみを記載します。

## 利用するシーン

- あなたのクライアントが `?key=` の利用に慣れている場合
- あなたのミドルウェアがすでに `x-goog-api-key` を使用している場合
- Gemini ネイティブのモデルメタデータではなく、OpenAI スタイルの `list + data[]` 構造が欲しい場合

もしあなたが標準的な OpenAI クライアントの場合は、[GET /v1/models](/jp/chat/openai/models) の利用を優先してください。

## 認証方式

今回の確認では以下3つの方式の利用が可能でした：

```http
Authorization: Bearer YOUR_API_KEY
```

```http
x-goog-api-key: YOUR_API_KEY
```

```text
GET /v1beta/openai/models?key=YOUR_API_KEY
```

## リクエスト例

<CodeGroup>

```bash cURL
curl "https://api.crazyrouter.com/v1beta/openai/models?key=YOUR_API_KEY"
```

```bash cURL with Header
curl https://api.crazyrouter.com/v1beta/openai/models \
  -H "x-goog-api-key: YOUR_API_KEY"
```

</CodeGroup>

## 現在の本番検証結果

`2026-03-23` の本番環境での確認では：

- `?key=` のリクエストで `200` が返ります
- `x-goog-api-key` のリクエストで `200` が返ります
- トップレベルの `object` は `list` となります
- トップレベルの `success` は `true` となります
- 現在返されるモデル数は `541` です
- `data[]` 内の要素にはよく使われるフィールドが含まれます：
  - `id`
  - `object`
  - `created`
  - `owned_by`
  - `supported_endpoint_types`

## 各フィールド説明

| フィールド | 型 | 説明 |
|------|------|------|
| `data[]` | array | 現在のトークンで利用可能なモデル一覧 |
| `id` | string | モデル識別子 |
| `owned_by` | string | モデルの提供元または所属組織 |
| `supported_endpoint_types` | array | 現在のモデルがサポートしているインターフェーススタイル |
| `object` | string | `list` で固定 |
| `success` | boolean | リクエストが成功したかどうか |

<Note>
  `supported_endpoint_types` は、現在のモデルがサポートしているインターフェーススタイルのみを示します。現状では `openai` は `POST /v1/chat/completions`、`anthropic` は `POST /v1/messages`、`openai-response` のみが `POST /v1/responses` に該当します。Claude は、現時点で公開サポートしているのは `openai` + `anthropic` であり、`openai-response` には対応していません。
</Note>

<Note>
  このエンドポイントは「Gemini モデルだけを返す」ものではありません。現在のトークンで見えるモデルの OpenAI スタイル一覧を返しますが、エントリーポイントと認証方式が Gemini スタイルのクライアントにより適しているだけです。
</Note>
