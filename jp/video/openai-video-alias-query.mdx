# 動画タスククエリアス

```
GET /v1/video/generations/{task_id}
```

互換動画ルートを通じて提出されたタスクの状態を確認するために使用します。これは `/v1/video/generations` の付随クエリルートです。

## 認証

```http
Authorization: Bearer YOUR_API_KEY
```

## リクエスト例

```bash cURL
curl https://api.crazyrouter.com/v1/video/generations/video_task_abc123   -H "Authorization: Bearer YOUR_API_KEY"
```

## 典型的な成功レスポンス

```json
{
  "code": "success",
  "message": "",
  "data": {
    "id": "video_task_abc123",
    "task_id": "video_task_abc123",
    "status": "SUCCESS",
    "result_url": "https://media.crazyrouter.com/task-artifacts/example.mp4",
    "artifact_url": "https://media.crazyrouter.com/task-artifacts/example.mp4"
  }
}
```

## ローカル検証で存在しないタスクへのレスポンス

ローカル `http://127.0.0.1:4000` 環境で存在しないタスクを確認すると、次のレスポンスが返されます：

```json
{
  "code": "task_not_exist",
  "message": "task_not_exist",
  "data": null
}
```

## 一般的なステータス

| ステータス | 説明 |
|------|------|
| `queued` | タスクが提出済み、または待機中 |
| `processing` | タスク処理中 |
| `SUCCESS` | タスク完了 |
| `failed` | タスク失敗 |

<Note>
異なる動画モデルや上流元によって完了結果フィールドに若干の違いがある場合があります。最も安定した方法は、作成とクエリをできるだけ同じ互換ルートで行い、`data.artifact_url` または `data.result_url` を優先して読み込むことです。
</Note>
