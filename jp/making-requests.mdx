## リクエスト形式

すべてのAPIリクエストはHTTPSプロトコルを使用し、リクエストボディはJSON形式です。

<Note>
デフォルトでは`https://api.crazyrouter.com/v1`を優先して使用します。もし、あるツールでルートドメインを記入すべきか`/v1`を記入すべきか分からない場合、まずは[API Endpointの説明](https://docs.crazyrouter.com/jp/api-endpoint)を参照してください。
</Note>

### 必須リクエストヘッダー

| Header | 値 | 説明 |
|--------|-----|------|
| `Authorization` | `Bearer YOUR_API_KEY` | API認証キー |
| `Content-Type` | `application/json` | リクエストボディの形式 |

### オプションリクエストヘッダー

| Header | 値 | 説明 |
|--------|-----|------|
| `Accept` | `application/json` | レスポンス形式 |
| `Content-Encoding` | `gzip` | オプション。リクエストボディがgzip圧縮されている場合に設定 |

## リクエスト例

```bash
curl https://api.crazyrouter.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -d '{
    "model": "gpt-5.5",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": false
  }'
```

## gzipを使用したリクエストボディの送信

リクエストボディが大きい場合、例えば長いコンテキストや長文書、大量のメッセージ履歴を毎回アップロードする場合は、元のJSONリクエストボディをgzip圧縮して送信できます。

gzipを有効にすると転送方法のみが変わり、リクエストの意味は変わりません。サーバー側はJSON解析前に自動で解凍します。

リクエストヘッダーを追加する必要があります：

```http
Content-Type: application/json
Content-Encoding: gzip
```

<Note>
  `Content-Encoding: gzip`は「リクエストボディがgzip圧縮されている」ことを示します。これは`Accept-Encoding: gzip`とは異なり、通常後者はレスポンス圧縮で使用されます。
</Note>

### Python

```python
import gzip
import json
import requests

payload = {
    "model": "gpt-5.5",
    "messages": [
        {"role": "user", "content": "这里放很长的上下文或文档内容..."}
    ],
    "stream": False
}

raw = json.dumps(payload, ensure_ascii=False).encode("utf-8")
compressed = gzip.compress(raw)

resp = requests.post(
    "https://api.crazyrouter.com/v1/chat/completions",
    headers={
        "Authorization": "Bearer sk-xxxxxxxx",
        "Content-Type": "application/json",
        "Content-Encoding": "gzip",
    },
    data=compressed,
    timeout=120,
)

print(resp.status_code, resp.text)
```

### Node.js

```js
import zlib from "node:zlib";

const payload = {
  model: "gpt-5.5",
  messages: [
    { role: "user", content: "这里放很长的上下文或文档内容..." },
  ],
  stream: false,
};

const raw = Buffer.from(JSON.stringify(payload));
const compressed = zlib.gzipSync(raw);

const resp = await fetch("https://api.crazyrouter.com/v1/chat/completions", {
  method: "POST",
  headers: {
    Authorization: "Bearer sk-xxxxxxxx",
    "Content-Type": "application/json",
    "Content-Encoding": "gzip",
  },
  body: compressed,
});

console.log(resp.status, await resp.text());
```

### サイズに応じて自動的にgzipを有効化

システムがワークフローの場合、一般的にどのリクエストを圧縮するかしないかをビジネスロジックで手動で区別する必要はありません。統一されたHTTPクライアントラッパーでJSONボディのサイズを判定し、閾値を超えた場合に自動的にgzipすることを推奨します。

推奨閾値：

```text
body >= 128KB：启用 gzip
body < 128KB：保持原样发送
```

リクエストが頻繁にMB単位になる場合は、閾値を`256KB`に設定しても構いません。小さいリクエストはgzipを強制することは推奨されません。圧縮オーバーヘッドやgzipヘッダーにより、サイズがむしろ大きくなる可能性があります。

Pythonラッパー例：

```python
import gzip
import json
import requests

def post_json(url, payload, api_key, gzip_threshold=128 * 1024):
    raw = json.dumps(payload, ensure_ascii=False).encode("utf-8")

    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    }

    if len(raw) >= gzip_threshold:
        body = gzip.compress(raw)
        headers["Content-Encoding"] = "gzip"
    else:
        body = raw

    return requests.post(url, headers=headers, data=body, timeout=120)
```

Node.jsラッパー例：

```js
import zlib from "node:zlib";

async function postJson(url, payload, apiKey, gzipThreshold = 128 * 1024) {
  const raw = Buffer.from(JSON.stringify(payload));
  const headers = {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  };

  const body =
    raw.length >= gzipThreshold
      ? (() => {
          headers["Content-Encoding"] = "gzip";
          return zlib.gzipSync(raw);
        })()
      : raw;

  return fetch(url, {
    method: "POST",
    headers,
    body,
  });
}
```

適用シーン：

- 単一リクエストボディが通常1MBを超える場合
- 長いコンテキストや長文書を繰り返しアップロードする場合
- クライアント側でHTTPボディやリクエストヘッダーを直接制御できる場合

## ストリーミングリクエスト

`stream: true`を設定してSSEストリーミング出力を有効にします：

```bash
curl https://api.crazyrouter.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -d '{
    "model": "gpt-5.5",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

ストリーミングレスポンス形式はServer-Sent Events（SSE）で、各イベントは`data: `で始まり、最後は`data: [DONE]`で終了します。
