# モデル公式価格方式

本記事では上流メーカーの公式課金基準のみを解説しており、Crazyrouter の実際の販売価格とは異なります。

- 上流公式基準：メーカー自身の `input`、`output`、`cached input`、`tool call`、`search grounding`、`prompt caching` などの課金方式
- Crazyrouter 基準：当サイト独自の販売価格、倍率、割引、チャネル差異および決済方式

<Note>
  本ページは `2026-04-27` で参照できるメーカー公式ドキュメントをもとに整理しています。メーカーは価格改定、プレビュー用モデルや長文コンテキスト、検索ツールやキャッシュ規則の調整を行う場合があります。ご利用前に必ず公式リンクで再度ご確認ください。
</Note>

## 公式単価例表

下記例では、各メーカーで最も一般的かつビジネス予算に直結しやすい区分のみを抜粋しています：

- Anthropic：標準 API 価格。`Fast mode`、`US-only inference` の乗数や Batch 割引は含みません
- OpenAI：`Standard` 価格。Batch、Priority、Regional Processing などの追加料金は含みません
- Gemini：`Standard` 価格。テキスト / 画像 / 動画入力でデフォルト、`Gemini 3*` には `<= 200K prompt` 区分を適用
- xAI：サイト内ルーティング名に静的な単独価格が公開されていない場合、「未単列」と明記します
- Z.AI：公式の `Text Models` 価格を参照
- MiniMax：メイン表は `Pay as You Go`、サブスクリプション型は別枠で `Token Plan` を記載

<Note>
  特別な注記が無い限り、下表の金額はすべて `USD / 1M tokens` で示しています。
</Note>

## Anthropic

Anthropic 系モデルの公式課金方式は単なる `input / output` の2区分ではなく、以下に分解されます：

- `Base Input Tokens`
- `5m Cache Writes`
- `1h Cache Writes`
- `Cache Hits & Refreshes`
- `Output Tokens`

また、共通で下記2ルールがあります：

- `Batch API` 入力・出力は基本的に標準価格 `50%割引` で課金
- Prompt キャッシュの倍率ルール公開は以下：`5分間キャッシュへの書き込み = 入力値の1.25倍`、`1時間キャッシュへの書き込み = 入力値の2倍`、`キャッシュの読取り = 入力値の0.1倍`

| サイト内モデル名 | 公式対応 | 公式課金方式 | 特殊説明 |
| --- | --- | --- | --- |
| `claude-opus-4-8` | Anthropic `claude-opus-4-8` | `base input / 5m cache write / 1h cache write / cache hit / output` に基づいて課金 | Anthropic 公式で `Sonnet 4.6` が `1M context` 対応明示。該当長文コンテキストでも標準単価で特別加算なし |
| `claude-opus-4-8` | Anthropic `claude-opus-4-8` | `base input / 5m cache write / 1h cache write / cache hit / output` に基づいて課金 | `Opus 4.6` も `1M context` 標準課金。さらに公式は `Fast mode` を別途提供、価格は標準単価 `6x` |
| `claude-opus-4-8` | Anthropic `claude-opus-4-8` | `base input / 5m cache write / 1h cache write / cache hit / output` に基づいて課金 | `Opus 4.7` は現在の Anthropic 公式公開価格中で独立したモデル。`US-only inference` を有効にすると公式は `1.1x` の乗数ありと説明 |
| `claude-opus-4-8` | Anthropic スナップショット ID `claude-opus-4-8`、公称エイリアスは多くの場合 `claude-opus-4-8` | なお `Sonnet 4.5` の `base input / cache write / cache hit / output` 方式で課金 | 日付入りの API スナップショット名であり、別料金枠ではありません。予算・計画時は `Claude Sonnet 4.5` の公式解釈を厳守してください |

## OpenAI

OpenAI この一連のテキストモデルに関する公式公開方針は最も統一されており、主要な内容は以下の通りです：

- `Input`
- `Cached input`
- `Output`

追加ルールは通常次の通りです：

- `Responses API` 自体は単独で追加料金は発生せず、選択したモデルのトークン単価で請求されます
- `Web search`、コンテナ・コード実行・Computer Use などのツールはツールごとに課金され、純粋なトークン単価には含まれません
- `Batch API` 入力と出力は通常、標準料金 `50%割引` で計算されます

| サイト内モデル名 | 公式対応 | 公式料金方式 | 特別説明 |
| --- | --- | --- | --- |
| `gpt-5.5` | サイト内別名、通常は OpenAI `gpt-5.5` に対応 | `input / cached input / output` で課金 | `gpt-5.5` の公式標準料金は `270K` 以下のコンテキストに適用されます；リージョナルエンドポイントは別料金 `+10%` となります |
| `gpt-4o` | OpenAI `gpt-4o` | `input / cached input / output` で課金 | `gpt-4o` は一貫した標準方針で、Claude のような個別キャッシュ書き込み欄や、Gemini の Search grounding 用の別表はありません |
| `gpt-5` | OpenAI `gpt-5` | `input / cached input / output` で課金 | Responses API でツールを有効化するとツール費用は別計算；公式価格ページに「thinking token 単価」は個別記載されていません |
| `gpt-5.5` | サイト内で OpenAI `gpt-5.1-codex-max` に対応 | `input / cached input / output` で課金 | これは Codex 志向のモデルですが、公開価格構造は通常の GPT-5.1 テキストモデルと同一です；より agentic coding / Codex ワークフロー理解に適しています |
| `gpt-5-mini` | OpenAI `gpt-5-mini` | `input / cached input / output` で課金 | 小型モデルで、構造は変わらず単価が低いだけです |
| `gpt-5-nano` | OpenAI `gpt-5-nano` | `input / cached input / output` で課金 | Nano バージョンも標準トークン三段階課金を踏襲します |
| `gpt-5.5` | OpenAI `gpt-5.5` | `input / cached input / output` で課金 | `gpt-5.5` も GPT-5シリーズの標準方針に属します；Web search / File search / Code interpreter を利用する場合、ツール費用は別途必要です |
| `gpt-5.5` | OpenAI `gpt-5.5` | `input / cached input / output` で課金 | 現在 OpenAI 公式ではこれをフラッグシップモデルとして扱っています；公開価格ページには `270K` 以下のコンテキストに標準料金が適用されると記載されており、超長コンテキストの場合は最新の詳細料金リストを参照してください |

## Google Gemini

- `Standard`
- `Batch`
- `Flex`
- `Priority`

さらに個別に下記が示されます：

- `Input`
- `Output (including thinking tokens)`
- `Context caching price`
- `Context caching storage`
- `Grounding with Google Search`
- `Grounding with Google Maps`

| サイト内モデル名 | 公式対応 | 公式料金方式 | 特別説明 |

## xAI Grok

xAI 公式規則のポイントは「thinking モデル用の別料金表があるかどうか」ではなく、トークンとツールを分割することです：

- `Prompt tokens`
- `Cached prompt tokens`
- `Completion tokens`
- `Reasoning tokens`

xAI 公式はさらに明記しています：

- `Reasoning tokens` は `completion token price` で料金を計算します
- `Web Search`、`X Search`、`Code Execution`、`Collections Search` などサーバー側ツールは `1000回ごとに` で個別課金されます
- `Batch API` のトークン系料金は通常 `50%割引` です

| サイト内モデル名 | 公式対応 | 公式料金方式 | 特別説明 |
| --- | --- | --- | --- |
| `grok-4.1-fast` | サイト内 reasoning 経路；公式的には Grok 4.1 の `Thinking` 構成に対応 | 公式見解では `prompt / cached prompt / completion / reasoning` の4種トークンと必要に応じた tool invocation 費用が加算 | 現在 xAI の公開API料金ページで重点的に紹介されているのは `grok-4-1-fast-reasoning` などの SKUです；従い、ここでは「xAI reasoning モデル公式課金構造で精算」する認識が正確で、サイト内名称を独立した公式SKUと考える必要はありません |
| `grok-4.1` | サイト内 Grok 4.1 メイン経路；公式的には Grok 4.1 の「思考無し」構成に近い | 公式見解では全て `prompt / cached prompt / completion` だが、検索・コード実行・添付ファイル検索などツール利用時はツール課金が別建て | xAI の公開APIページの現行表記は `grok-4.1-fast` と `grok-4-1-fast-*` を重視しています；予算策定時はxAIが公開するトークン課金・ツール課金ルールに注目してください |

## MiniMax

MiniMax モデル群はまず2つの公式販売方式を区別する必要があります：

- `Pay as You Go`
- `Token Plan`

その内訳：

- `Pay as You Go` は標準 API の従量課金型
- `Token Plan` はサブスクリプション制で、`M2.7` を `5時間のローリングウィンドウによるリクエスト上限` 単位で課金し、トークン単価のみではありません

| サイト内モデル名 | 公式対応 | 公式料金方式 | 特別説明 |
| --- | --- | --- | --- |
| `MiniMax-M2.7` | サイト内で `MiniMax-M2.7` に対応 | `Pay as You Go` なら `input / output / prompt caching read / prompt caching write` で課金；`Token Plan` なら `requests / 5hrs` のサブスクリプション枠で計算 | ここは本ページで最も異なる会社です。生産予算立案時は優先的に `Pay as You Go` を、開発者による大規模コーディングでの利用時は `Token Plan` が割安かを確認してください |

## 結論

「公式が何で請求するのか」を素早く判断したいだけなら、次の種別を記憶すれば十分です：

- Anthropic：`base input + cache write/read + output`
- OpenAI：`input + cached input + output`、ツール課金は別
- Gemini：`マルチプロセスモード + input/output + キャッシング + search/maps基盤連携`
- xAI：`prompt/cached/completion/reasoning`、サーバー側ツール課金は別
- Z.AI：`input + cached input + cached storage + output`
- MiniMax：`従量制トークン` または `サブスクリプション上限` 、2方式並行

<Warning>
  本ページは「上流公式の料金方式」を解説したものであり、Crazyrouterの外部販売価格ではありません。実際のチャージ・課金・倍率・特典等は Crazyrouter サイト内の pricing・コンソール・`/api/pricing` の応答に準じてください。
</Warning>
