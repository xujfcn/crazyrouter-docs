> 内容更新日: 2026-06-09

Linux または macOS 上でワンクリックスクリプトを使用して [OpenClaw](https://github.com/open-claw/open-claw) AI ゲートウェイをデプロイし、Crazyrouter をデフォルトバックエンドとして利用します。インストーラーは、直接実行可能な `~/.openclaw/openclaw.json` を書き込み、システムサービスへの登録や、チャット・コーディング・長文コンテキストタスクに適したモデル群のプリセットも行います。

## 概要

OpenClaw は Crazyrouter を自分で自由にコントロールできるローカル AI エントリーポイントとして活用できます：

- ローカル WebUI / ゲートウェイ、デフォルトで `18789` をリッスン
- Crazyrouter のモデルとリソースをそのまま流用可能
- Telegram をサポートし、さらに DingTalk・WeCom・QQ Bot・Discord・Slack・Feishu 等のプラグインもプリセット済み
- パーソナル常駐ボット・社内助っ人・家庭サーバ・軽量セルフホスティングに最適

## 利用対象

- Crazyrouter をコマンド一発でローカル AI ゲートウェイに繋げたい方
- 自分のサーバーで Telegram Bot を動かしたい方
- チャット・WebUI・IM エントリを一元管理したい方
- 開発マシンや家庭用小型サーバーに常駐アシスタントを導入したい方

## 利用規約

推奨規約：`OpenAI-compatible API`

- インストーラーは `crazyrouter` プロバイダーをデフォルトで `https://api.crazyrouter.com/v1` に設定します
- さらに `crazyrouter-claude` および `crazyrouter-minimax` プロバイダーも追記され、Anthropic Messages 互換経路への切り替えが容易です
- OpenClaw はローカルゲートウェイと WebUI のみを公開し、認証はインストール時に生成される `gateway.auth.token` に依存します

<Note>
OpenClaw のプロバイダーアドレスを手動変更する場合は、まず [API Endpoint 説明](https://docs.crazyrouter.com/jp/api-endpoint) を確認し、クライアントに入力すべきルートドメインもしくは `/v1` を把握してください。
</Note>

## 前提条件

| 項目 | 説明 |
|------|------|
| Crazyrouter アカウント | [crazyrouter.com](https://crazyrouter.com) から事前登録 |
| Crazyrouter API Key | OpenClaw 用の専用トークンを新規作成推奨。Cursor や Claude Code とは共用しないでください |
| OS | Linux または macOS（x64/arm64 どちらも対応） |
| ネットワーク | サーバーがインターネットアクセス可能であること。他端末から WebUI にアクセスする場合、`18789` ポートも解放 |
| Node.js | インストーラーが自動的に Node.js 22+ を導入します |
| Telegram Bot Token | 任意。Telegram 利用時のみ必要 |

<Warning>
OpenClaw インストーラーはゲートウェイをローカルネットワークアドレス（`bind: lan`）にバインドします。サーバーが直接インターネットに公開される場合、必ずファイアウォールでアクセス制限を施し、ゲートウェイログイントークンの厳重な管理を行ってください。
</Warning>

## 5分でクイックスタート

<Steps>
  <Step title="専用のCrazyrouterトークンを作成する">
    Crazyrouter 管理画面で OpenClaw 専用の `sk-...` トークンを作成します。ゲートウェイで使用予定のモデル（例：`claude-opus-4-8`、`gpt-5.5`、`gemini-3.1-pro`）だけを許可しておくのがおすすめです。
  </Step>
  <Step title="インストールスクリプトを実行する">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/xujfcn/crazyrouter-openclaw/main/install.sh | bash
    ```
    言語選択や API Key 入力をスキップしたい場合は次のように実行できます：
    ```bash
    CRAZYROUTER_API_KEY=sk-xxx INSTALLER_LANG=zh \
      curl -fsSL https://raw.githubusercontent.com/xujfcn/crazyrouter-openclaw/main/install.sh | bash
    ```
  </Step>
  <Step title="インストーラーの出力された3つの値を控える">
    - WebUI アドレス：`http://<サーバーIP>:18789`
    - 自動ログインアドレス：`http://<サーバーIP>:18789?token=<gateway_token>`
    - 設定ファイル：`~/.openclaw/openclaw.json`
  </Step>
  <Step title="WebUIを開いて初回認証を行う">
    ブラウザで自動ログインアドレスにアクセスし、OpenClaw コンソールへ入れるか、デフォルトモデル `claude-opus-4-8` で「ok とだけ返信して」等テストメッセージが送れるか検証します。
  </Step>
  <Step title="必要に応じてTelegram連携を完了する">
    インストーラーは Telegram も今すぐ設定するか聞いてきます。即時設定を選択し、Bot Token を入力後、ボット宛に何かメッセージを送れば最初のオーナー連携が完了します。
  </Step>
</Steps>

## 推奨モデル構成

インストーラーは `claude-opus-4-8` を主モデル（メインモデル）にします。日常で使うデフォルトモデルを切り替えたい時は `~/.openclaw/openclaw.json` の `agents.defaults.model.primary` を直接編集してください。

| シーン | 推奨モデル | 理由 |
|------|----------|------|
| デフォルト日常会話 | `claude-opus-4-8` | 現行デフォルト主モデル。有質なチャットやメイン制御に適す |
| コーディング／Agent | `gpt-5.5` | 最新 OpenAI 互換主力。コーディングや Agent ベースラインに推薦 |
| 高コスパ予備 | `claude-opus-4-8` | クオリティ・安定性・コストのバランス型 |
| Gemini 予備枠 | `gemini-3.1-pro` | 互換性検証のサブルートに適す |
| 深層推論 | `claude-opus-4-8` | より強力な推論チェーンが求められる場面向き |

例：デフォルトモデルを `gpt-5.5` に変更する

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "crazyrouter/gpt-5.5"
      }
    }
  }
}
```

Claude 互換プロバイダーを明示利用したい場合は次の設定例を参照：

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "crazyrouter-claude/claude-opus-4-8"
      }
    }
  }
}
```

## Token 設定のベストプラクティス

| 設定 | 推奨 | 説明 |
|------|------|------|
| 専用トークン | 必須 | OpenClaw 用と他の IDE/CLI とは別でトークンを用意する |
| モデルホワイトリスト | 推奨 | OpenClaw で使うモデルだけ許可し誤利用を防止 |
| IP 制限 | 固定出口サーバーでは推奨 | サーバーの固定IPならトークンもそのIP限定推奨 |
| リソース上限 | 推奨 | ボット用途用に月/日の上限を設ける |
| 環境分離 | 推奨 | 本運用ボットとテスト用で別トークンを使い分ける |
| 漏洩時対応 | 即時切替 | `openclaw.json`・ログや共有リンクでトークンが漏洩した場合は Crazyrouter トークン・ゲートウェイトークンを早急に再生成 |

<Tip>
OpenClaw には主に2種の認証があります。ひとつは Crazyrouter `sk-...` API Key（モデル呼び出し用）、もう一つは OpenClaw ローカルゲートウェイのログイントークン（WebUI用）。この2つは使い分けてください。
</Tip>

## 初回セットアップ成功チェックリスト

- [ ] ブラウザで `http://<サーバーIP>:18789?token=<gateway_token>` にアクセスできる
- [ ] OpenClaw WebUI に正常ログインできる（ログインループしない）
- [ ] デフォルトモデルで最初の返信が返ってくる
- [ ] モデル変更後もサービス再起動で問題なく動作する
- [ ] `journalctl --user -u openclaw -f` または `tail -f ~/.openclaw/openclaw.log` でリクエスト成功を確認
- [ ] Telegram を設定した場合、ボットへメッセージ送付→返信受信できる
- [ ] `~/.openclaw/openclaw.json` バックアップを保存済み

## 重要ファイルと主な設定

### ファイルパス

| パス | 用途 |
|------|------|
| `~/.openclaw/openclaw.json` | メイン設定ファイル |
| `~/.openclaw/start-gateway.sh` | 起動スクリプト（システムサービスが参照） |
| `~/.openclaw/crash-guard.cjs` | インストーラーによる安定化パッチ |
| `~/.openclaw/credentials/.telegram-owner-paired` | Telegram 最初の owner 登録済みマーカー |
| `~/.config/systemd/user/openclaw.service` | Linux ユーザー向け systemd サービス |
| `~/Library/LaunchAgents/com.crazyrouter.openclaw.plist` | macOS launchd サービス |
| `~/.openclaw/openclaw.log` | macOS 標準ログ |
| `~/.openclaw/openclaw.err` | macOS エラーログ |

### 変更頻度の高い設定

| JSON パス | 用途 | 主な変更点 |
|-----------|------|-----------|
| `models.providers.crazyrouter.apiKey` | Crazyrouter OpenAI 互換キー | API Keyを入れ替え |
| `models.providers.crazyrouter.baseUrl` | OpenAI 互換ベースURL | 通常 `https://api.crazyrouter.com/v1` のまま |
| `agents.defaults.model.primary` | デフォルトメインモデル | `gpt-5.5`や`claude-opus-4-8`等に切り替え |
| `gateway.port` | WebUI / ゲートウェイ ポート | 独自ポートに変更 |
| `gateway.auth.token` | WebUI ログイントークン | 漏洩時には即変更 |
| `gateway.bind` | リッスン範囲 | デフォルトは `lan` |
| `channels.telegram.botToken` | Telegram Bot Token | Telegram 利用時に記入 |
| `plugins.entries.*.enabled` | 各IMプラグインの有効設定 | 不要なプラグインは無効化 |
| `env.vars.OPENAI_API_KEY` | 一部内部機能使い回し用API Key | 通常メインキーと同じにしておく |

## IM 連携

### Telegram

インストーラーが最も充実サポートしているチャネルです。こちらから始めるのがおすすめです：

1. Telegram で `@BotFather` を検索
2. `/newbot` を送信してボット作成および Bot Token を取得
3. インストーラーで `Set up Telegram Bot now?` を聞かれたら `Y` を選択
4. Bot Token を貼り付けると、インストーラーはそれを `~/.openclaw/openclaw.json` に保存します
5. インストーラーがゲートウェイを自動再起動した後、ボットに何でもよいのでメッセージを送信
6. 最初に送信したユーザーが自動的に owner 扱いで連携されます
7. 自動連携失敗時は以下を実行：

```bash
openclaw pairing list
openclaw pairing approve <code>
```

Telegram 設定を手動編集する際は、インストーラー生成データ構造が参考になります：

```json
{
  "channels": {
    "telegram": {
      "enabled": true,
      "botToken": "123456789:ABCdef...",
      "dmPolicy": "pairing",
      "groupPolicy": "allowlist",
      "streaming": "off"
    }
  },
  "plugins": {
    "entries": {
      "telegram": { "enabled": true }
    }
  }
}
```

### その他の IM プラットフォーム

インストーラーは以下のプラグインエントリーも予め有効化しています：

- `dingtalk`
- `openclaw-wecom`
- `qqbot`
- `discord`
- `slack`
- `feishu`

ですが、これらのチャネルは各自でプラットフォーム認証情報や該当 `channels.<name>` 設定が必要です。おすすめフロー：

1. 対象プラットフォームにボット or アプリを事前作成
2. 認証情報を `~/.openclaw/openclaw.json` へ記入
3. 該当 `plugins.entries.<name>.enabled` を `true` にしておくことを確認
4. OpenClaw サービスを再起動
5. ログでそのチャネルのロード成功を確認

| プラットフォーム | インストーラー対応 | 必要作業 |
|------|------------|----------|
| Telegram | 対話的設定に対応 | Bot Token 入力と owner 連携 |
| DingTalk | プラグイン自動インストール／有効化 | ボット認証＆チャンネル設定を追加 |
| WeCom | プラグイン自動インストール／有効化 | 企業アプリ認証＆チャンネル設定を追加 |
| QQ Bot | プラグイン自動インストール／有効化 | ボット認証＆チャンネル設定を追加 |
| Discord/Slack/Feishu | プラグイン有効済み | それぞれの手順に従いチャンネル認証を追加 |

<Note>
OpenClaw をチーム IM へ連携する場合、チームボット用に別途 Crazyrouter トークンを作成し、モデルホワイトリストや使用上限もより厳格に設定することを強く推奨します。
</Note>

## サービス運用・ログ管理

<Tabs>
  <Tab title="Linux（systemd）">
    ```bash
    systemctl --user status openclaw
    systemctl --user start openclaw
    systemctl --user restart openclaw
    systemctl --user stop openclaw
    journalctl --user -u openclaw -f
    ```

    説明：インストーラーは `loginctl enable-linger $(whoami)` を自動実行します。これにより SSH 切断後もユーザーサービスは継続動作します。
  </Tab>
  <Tab title="macOS（launchd）">
    ```bash
    launchctl list | grep openclaw
    launchctl start com.crazyrouter.openclaw
    launchctl stop com.crazyrouter.openclaw
    launchctl stop com.crazyrouter.openclaw && launchctl start com.crazyrouter.openclaw
    tail -f ~/.openclaw/openclaw.log
    cat ~/.openclaw/openclaw.err
    ```

    説明：macOS なら `openclaw.log` で通常ログを、`openclaw.err` で起動失敗時の詳細確認が可能です。
  </Tab>
</Tabs>

## パフォーマンスとコスト最適化のコツ

- まずは `claude-opus-4-8` のまま全体フローを動かし、問題なければ用途ごとにモデルを使い分け推奨
- 高頻度な会話や通知用途ではコスト重視で `claude-opus-4-8`・`gemini-3.1-pro` へとダウングレード可能
- コーディング系フローは `gpt-5.5` を単独起用
- チーム用途では Telegram・企業IM・WebUI を各々別トークンに分離し、コスト管理・リスク分散を図る
- 必要最小限のプラグインとモデルのみ有効化し、誤請求を削減

## アップグレード手順

OpenClaw 本体・パッチ・サービススクリプトもセットで再適用できるため、最も安全なアップデート方法は再度インストーラーを実行することです：

<Steps>
  <Step title="現在の設定をバックアップする">
    ```bash
    cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak
    ```
  </Step>
  <Step title="インストールスクリプトを再度実行する">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/xujfcn/crazyrouter-openclaw/main/install.sh | bash
    ```
  </Step>
  <Step title="カスタム設定が必要な場合は戻すか確認する">
    Telegram以外のchannelを手動で追加した場合や、デフォルトモデルを変更した場合は、`openclaw.json`と再度比較し、これらのカスタマイズ項目が引き続き存在することを確認してください。
  </Step>
  <Step title="再起動して認証を行う">
    WebUIを再度開いて、モデル、ログ、接続済みIMチャンネルが正常に動作していることを確認してください。
  </Step>
</Steps>

もしOpenClaw npmパッケージだけをアップグレードしたい場合は、`npm install -g openclaw@latest`を先に実行し、サービスを再起動しても構いません。しかし、この方法ではインストーラー内のパッチやスクリプトの更新が再適用されません。

## アンインストールガイド

<Tabs>
  <Tab title="Linux">
    ```bash
    systemctl --user disable --now openclaw
    rm -f ~/.config/systemd/user/openclaw.service
    systemctl --user daemon-reload
    rm -rf ~/.openclaw
    npm uninstall -g openclaw
    ```
  </Tab>
  <Tab title="macOS">
    ```bash
    launchctl stop com.crazyrouter.openclaw
    launchctl unload ~/Library/LaunchAgents/com.crazyrouter.openclaw.plist
    rm -f ~/Library/LaunchAgents/com.crazyrouter.openclaw.plist
    rm -rf ~/.openclaw
    npm uninstall -g openclaw
    ```
  </Tab>
</Tabs>

OpenClawのためだけにNode.jsをインストールした場合は、他のプロジェクトが依存していないことを確認した上で、Node.jsを手動で削除しても構いません。

## よくあるエラーと修正方法

| 現象 | 主な原因 | 修正方法 |
|------|----------|----------|
| WebUIが開けない | サービス未起動、ポート使用中、ホスト側のファイアウォール未許可 | サービス状態を確認し、`18789`ポートとファイアウォールをチェック |
| ページは開くが常にログイン要求される | `gateway.auth.token`が間違っている、または自動ログインのURLではない | インストーラーの出力による`?token=...`リンクを再確認し、必要であれば`openclaw.json`もチェック |
| 401 unauthorized | `models.providers.*.apiKey`内のCrazyrouter keyが無効または失効 | API Keyを更新後、サービスを再起動 |
| 403 / model not allowed | OpenClawがリクエストしているモデルがCrazyrouter tokenのホワイトリストにない | token設定で対応するモデルを許可 |
| 429 / 配額超過 | tokenの上限超過やレートリミット発動 | 配額を増やすか、安価なモデルへ交換、tokenを分割 |
| モデル変更後も古いモデルが呼ばれる | サービス再起動未実施、またはproviderパスミス | `agents.defaults.model.primary`を確認し再起動 |
| Telegram Botが返信しない | `botToken`未記入、ownerペアリング未完了、またはサービス再起動未実施 | `channels.telegram`を確認、サービス再起動、メッセージ再送でペアリングをトリガー |
| Linuxインストール後サービス未起動と表示 | systemdユーザーサービス失敗 | `journalctl --user -u openclaw -f`を実行しエラー内容を確認 |
| macOSインストール後サービス未起動と表示 | launchdの起動失敗 | `~/.openclaw/openclaw.err`を確認 |

## よくある質問（FAQ）

### Crazyrouterバックエンドにはどのアドレスを使うべきですか？

基本的にインストーラーが書き込んだ値をそのまま利用してください：OpenAI互換providerは`https://api.crazyrouter.com/v1`、Claude / MiniMaxネイティブ互換providerは`https://api.crazyrouter.com`。

### デフォルトモデルはどれを残すべき？

ほとんどの場合、`claude-opus-4-8`を残してください。OpenClawを主にコードアシスタントとして使う場合は`gpt-5.5`に切り替えてください。

### モデルリストに使いたいモデルが表示されないのはなぜ？

多くの場合、Crazyrouter tokenが該当モデルを許可していないか、providerプレフィックスが間違っている場合があります。

### Telegramの個人チャットはできるが、グループチャットができないのはなぜ？

インストーラーはデフォルトでTelegramのグループポリシーを`allowlist`に設定します。ご自身の用途に合わせてTelegram channel設定を調整してください。

### OpenClawを最も安全に外部公開するには？

最低限3つ：アクセス元の制限、`gateway.auth.token`の保護、OpenClaw用に独立したCrazyrouter tokenの利用。パブリックに直接公開する場合は、リバースプロキシや追加のアクセスコントロールも推奨。
