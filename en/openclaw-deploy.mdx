Deploy the [OpenClaw](https://github.com/open-claw/open-claw) AI gateway on Linux or macOS using a one-click script, with Crazyrouter as the default backend. The installer will write a directly runnable `~/.openclaw/openclaw.json`, register a system service, and pre-configure a set of models suitable for chatting, coding, and long-context tasks.

## Overview

OpenClaw is suitable for turning Crazyrouter into your own controllable local AI access point:

- Local WebUI/gateway, listening by default on `18789`
- Can directly reuse Crazyrouter's models and quota
- Supports Telegram and pre-enables plugin entries for DingTalk, WeCom, QQ Bot, Discord, Slack, and Feishu
- Suitable for personal always-on bots, team internal assistants, home servers, or lightweight self-hosted scenarios

## Who is it for

- Those who want to connect Crazyrouter to a local AI gateway with a single command
- Those who want to run a Telegram Bot on their own server
- Those who want to manage chat, WebUI, and IM entries centrally
- Those who want to deploy a resident assistant on a dev machine or small home host

## Usage Agreement

Recommended agreement: `OpenAI-compatible API`

- The installer by default points the `crazyrouter` provider to `https://api.crazyrouter.com/v1`
- It will also write `crazyrouter-claude` and `crazyrouter-minimax` providers, making it easy to switch to the Anthropic Messages compatible path
- OpenClaw itself exposes the local gateway and WebUI; authentication relies on the `gateway.auth.token` generated during installation

<Note>
If you need to manually adjust the OpenClaw provider address later, first refer to [API Endpoint documentation](https://docs.crazyrouter.com/en/api-endpoint) to confirm whether the current client should fill in the root domain or `/v1`.
</Note>

## Prerequisites

| Item | Description |
|------|------|
| Crazyrouter Account | Register first at [crazyrouter.com](https://crazyrouter.com) |
| Crazyrouter API Key | It is recommended to create a dedicated token for OpenClaw, do not share it with Cursor or Claude Code |
| Operating System | Linux or macOS, both x64/arm64 are supported |
| Network | The server needs access to the public Internet; if you want to access the WebUI from other devices, also allow port `18789` |
| Node.js | The installer will try to automatically install Node.js 22+ |
| Telegram Bot Token | Optional, only needed if you want to connect Telegram |

<Warning>
The OpenClaw installer binds the gateway to the local network address (`bind: lan`) by default. If your host is directly exposed to the public, be sure to set up firewall restrictions and properly keep your gateway login token safe at the same time.
</Warning>

## 5-Minute Quick Start

<Steps>
  <Step title="Create a dedicated Crazyrouter token">
    In Crazyrouter's backend, create a `sk-...` token dedicated for OpenClaw. It is recommended to only open up the models you plan to use in the gateway, such as `claude-opus-4-8`, `gpt-5.5`, `gemini-3.1-pro`.
  </Step>
  <Step title="Run the installation script">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/xujfcn/crazyrouter-openclaw/main/install.sh | bash
    ```
    If you want to skip language selection and API Key input, you can also do this:
    ```bash
    CRAZYROUTER_API_KEY=sk-xxx INSTALLER_LANG=zh \
      curl -fsSL https://raw.githubusercontent.com/xujfcn/crazyrouter-openclaw/main/install.sh | bash
    ```
  </Step>
  <Step title="Note down the 3 values output by the installer">
    - WebUI address: `http://<server IP>:18789`
    - Auto-login address: `http://<server IP>:18789?token=<gateway_token>`
    - Config file: `~/.openclaw/openclaw.json`
  </Step>
  <Step title="Open the WebUI for the initial verification">
    Visit the auto-login address with your browser, make sure you can access the OpenClaw console, and send a test message using the default model `claude-opus-4-8`, for example "Just reply ok".
  </Step>
  <Step title="Complete the Telegram pairing if needed">
    The installer will ask if you want to immediately configure Telegram. If you choose to set up now, after entering the Bot Token, send your bot any message to complete the first owner pairing.
  </Step>
</Steps>

## Recommended Model Configurations

The installer defaults the main model to `claude-opus-4-8`. If you want to change the everyday default model, just modify `~/.openclaw/openclaw.json`'s `agents.defaults.model.primary` directly.

| Scenario | Recommended Model | Reason |
|------|----------|------|
| Default daily chat | `claude-opus-4-8` | Current default main model, suitable as a high-quality daily chat and main control model |
| Coding / Agent | `gpt-5.5` | Latest OpenAI-compatible main model, suitable as the baseline for coding and Agent |
| High cost performance backup | `claude-opus-4-8` | Balanced in quality, stability and cost |
| Gemini backup | `gemini-3.1-pro` | Suitable as a second compatibility verification path |
| Deep reasoning | `claude-opus-4-8` | Suitable for scenarios requiring stronger reasoning chains |

Example: Change the default model to `gpt-5.5`

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "crazyrouter/gpt-5.5"
      }
    }
  }
}
```

If you explicitly want to use the Claude-compatible provider, do it like this:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "crazyrouter-claude/claude-opus-4-8"
      }
    }
  }
}
```

## Token Best Practices

| Setting | Recommendation | Description |
|------|------|------|
| Dedicated token | Must | Do not share the same token for OpenClaw and other IDE/CLI |
| Model whitelist | Recommended to enable | Only keep models that OpenClaw will use to reduce misuse |
| IP restriction | Recommended if server IP is fixed | If your host’s outbound IP is fixed, restrict the token to this server |
| Quota limit | Recommended | Set a separate monthly or daily budget for the bot scenario |
| Environment isolation | Recommended | Separate tokens for production and test bots |
| Leak handling | Immediate rotation | If `openclaw.json`, logs, or share links exposed the token, reset Crazyrouter and gateway tokens immediately |

<Tip>
There are at least two types of credentials in OpenClaw: one is Crazyrouter’s `sk-...` API Key, used to call models; the other is OpenClaw’s local gateway login token, used for accessing the WebUI. Do not mix the two.
</Tip>

## First Successful Checklist

- [ ] Browser can open `http://<server IP>:18789?token=<gateway_token>`
- [ ] OpenClaw WebUI can enter normally, does not repeatedly ask for login
- [ ] The default model can return the first message successfully
- [ ] After changing the model, the service can still respond normally after restart
- [ ] `journalctl --user -u openclaw -f` or `tail -f ~/.openclaw/openclaw.log` can see successful requests
- [ ] If Telegram is enabled, messages sent to the bot can receive replies
- [ ] `~/.openclaw/openclaw.json` backup has been saved

## Key Files and Configuration Items

### File Locations

| Path | Usage |
|------|------|
| `~/.openclaw/openclaw.json` | Main configuration file |
| `~/.openclaw/start-gateway.sh` | Startup script, called by the system service |
| `~/.openclaw/crash-guard.cjs` | Stability patch written by the installer |
| `~/.openclaw/credentials/.telegram-owner-paired` | Mark file after Telegram's first owner pairing is completed |
| `~/.config/systemd/user/openclaw.service` | Linux user-level systemd service |

| `~/.openclaw/openclaw.log` | macOS general log |
| `~/.openclaw/openclaw.err` | macOS error log |

### Most Frequently Modified Config Items

| JSON Path | Function | Common Modification |
|-----------|------|----------|
| `models.providers.crazyrouter.apiKey` | Crazyrouter OpenAI-compatible key | Change API Key |
| `models.providers.crazyrouter.baseUrl` | OpenAI-compatible base URL | Usually keep `https://api.crazyrouter.com/v1` |
| `agents.defaults.model.primary` | Default main model | Switch to `gpt-5.5`, `claude-opus-4-8`, etc. |
| `gateway.port` | WebUI/gateway port | Change to your own port |
| `gateway.auth.token` | WebUI login token | Change immediately if leaked |
| `gateway.bind` | Listening range | Default is `lan` |
| `channels.telegram.botToken` | Telegram Bot Token | Fill when Telegram is enabled |
| `plugins.entries.*.enabled` | Whether each IM plugin is enabled | Turn off unused plugins as needed |
| `env.vars.OPENAI_API_KEY` | API Key for reuse by some internal capabilities | Usually keep same as main key |

## IM Integration

### Telegram

This is the most fully supported channel by the installer, it is recommended to start with Telegram:

1. Search `@BotFather` on Telegram
2. Send `/newbot` to create a bot, and get the Bot Token
3. When the installer asks `Set up Telegram Bot now?`, select `Y`
4. Paste the Bot Token, the installer will write it into `~/.openclaw/openclaw.json`
5. After the installer automatically restarts the gateway, send any message to the bot
6. The first person to send a message will be automatically paired as the owner
7. If automatic pairing fails, execute:

```bash
openclaw pairing list
openclaw pairing approve <code>
```

When manually editing the Telegram config, refer to the structure written by the installer:

```json
{
  "channels": {
    "telegram": {
      "enabled": true,
      "botToken": "123456789:ABCdef...",
      "dmPolicy": "pairing",
      "groupPolicy": "allowlist",
      "streaming": "off"
    }
  },
  "plugins": {
    "entries": {
      "telegram": { "enabled": true }
    }
  }
}
```

### Other IM Platforms

The installer pre-enables these plugin entries:

- `dingtalk`
- `openclaw-wecom`
- `qqbot`
- `discord`
- `slack`
- `feishu`

However, these channels usually require you to fill in the platform credentials and corresponding `channels.<name>` config yourself. The recommended workflow is:

1. First, create a bot or app on the relevant platform
2. Write the platform credentials into `~/.openclaw/openclaw.json`
3. Make sure the corresponding `plugins.entries.<name>.enabled` is `true`
4. Restart the OpenClaw service
5. Check the logs to verify if the channel was successfully loaded

| Platform | Installer Status | What You Still Need to Do |
|------|------------|----------------|
| Telegram | Supports interactive configuration | Fill in Bot Token, complete owner pairing |
| DingTalk | Plugin will be installed and enabled | Fill in bot credentials and relevant channel config |
| WeCom | Plugin will be installed and enabled | Fill in enterprise app credentials and channel config |
| QQ Bot | Plugin will be installed and enabled | Fill in bot credentials and channel config |
| Discord/Slack/Feishu | Plugin entry already enabled | Complete channel credentials as required by each bot |

<Note>
If you are preparing to connect OpenClaw to team IM, it is strongly recommended to create a separate Crazyrouter token for the team bot, and set a stricter model whitelist and quota.
</Note>

## Service Management and Logs

<Tabs>
  <Tab title="Linux (systemd)">
    ```bash
    systemctl --user status openclaw
    systemctl --user start openclaw
    systemctl --user restart openclaw
    systemctl --user stop openclaw
    journalctl --user -u openclaw -f
    ```

    Note: The installer will try to execute `loginctl enable-linger $(whoami)`, so that even if you exit SSH, user-level services outside the session can continue to run.
  </Tab>
  <Tab title="macOS (launchd)">
    ```bash
    launchctl list | grep openclaw
    launchctl start com.crazyrouter.openclaw
    launchctl stop com.crazyrouter.openclaw
    launchctl stop com.crazyrouter.openclaw && launchctl start com.crazyrouter.openclaw
    tail -f ~/.openclaw/openclaw.log
    cat ~/.openclaw/openclaw.err
    ```

    Note: On macOS, `openclaw.log` is usually used for running logs, `openclaw.err` is better for troubleshooting startup failures.
  </Tab>
</Tabs>

## Performance and Cost Recommendations

- Use `claude-opus-4-8` by default first, then refine model separation after confirming the whole workflow
- For high-frequency daily Q&A or bot notifications, switch back for cost to `claude-opus-4-8` or `gemini-3.1-pro`
- Use `gpt-5.5` separately for coding workflows
- In teams, assign Telegram / enterprise IM / WebUI different tokens for cost accounting and risk isolation
- Keep only necessary plugins and models to reduce cost from misuse

## Upgrade Guide

The most reliable way to upgrade is to rerun the installer, as it will update the OpenClaw package, patches, and service scripts together.

<Steps>
  <Step title="Back up the current configuration">
    ```bash
    cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak
    ```
  </Step>
  <Step title="Execute the installation script again">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/xujfcn/crazyrouter-openclaw/main/install.sh | bash
    ```
  </Step>
  <Step title="Check if custom configuration needs to be restored">
    If you have manually added any channels other than Telegram or changed the default model, re-compare `openclaw.json` to make sure these custom settings are still present.
  </Step>
  <Step title="Restart and verify">
    Reopen the WebUI and confirm that the model, logs, and connected IM channels are working properly.
  </Step>
</Steps>

If you clearly only want to upgrade the OpenClaw npm package, you can also execute `npm install -g openclaw@latest` first, then restart the service; but this method will not re-apply patches and script updates from the installer.

## Uninstallation Guide

<Tabs>
  <Tab title="Linux">
    ```bash

    rm -f ~/.config/systemd/user/openclaw.service
    systemctl --user daemon-reload

    ```
  </Tab>
  <Tab title="macOS">
    ```bash
    launchctl stop com.crazyrouter.openclaw
    ```

If you installed Node.js specifically for OpenClaw at the beginning, you can also manually remove Node.js after confirming that no other projects depend on it.

## Common Errors and Fixes

| Phenomenon | Common Cause | Fix |
|------|----------|----------|
| WebUI does not open | Service not started, port occupied, firewall not open on host | Check the service status first, then check `18789` port and firewall |
| The page opens but keeps asking for login | `gateway.auth.token` is incorrect, or you are not using the auto-login address | Re-read the `?token=...` link output by the installer, and check `openclaw.json` if necessary |
| 401 unauthorized | Crazyrouter key in `models.providers.*.apiKey` is invalid or expired | Update the API Key and restart the service |
| 403 / model not allowed | The model OpenClaw is requesting is not in the Crazyrouter token whitelist | Allow the corresponding model in the token settings |
| 429 / quota exhausted | Token overused or rate limit triggered | Increase quota, use a cheaper model, or split the token |
| Old model is still used after model change | Service was not restarted, or wrong provider path was changed | Check `agents.defaults.model.primary`, then restart |
| Telegram Bot doesn't reply | `botToken` not written, owner pairing not complete, or service not restarted | Check `channels.telegram`, restart the service, resend a message to trigger pairing |
| After installing on Linux prompts that service might not be started | systemd user service failed | Run `journalctl --user -u openclaw -f` to see the error |
| After installing on macOS prompts that service might not be started | launchd failed to start | Check `~/.openclaw/openclaw.err` |

## FAQ

### Which address should be used as the Crazyrouter backend?

Just keep the value set by the installer by default: OpenAI compatible provider uses `https://api.crazyrouter.com/v1`, Claude / MiniMax natively compatible providers use `https://api.crazyrouter.com`.

### Which default model should I keep?

In most cases, keep `claude-opus-4-8` first. If you mainly use OpenClaw as a code assistant, then switch to `gpt-5.5`.

### Why can't I see the model I want to use in the model list?

Usually because your Crazyrouter token hasn’t allowed that model, or you changed to a wrong provider prefix.

### Why do private Telegram chats work but group chats don't?

The installer sets the default Telegram group policy to `allowlist`. You need to further adjust the Telegram channel configuration according to your usage needs.

### How do I open OpenClaw to the public most safely?

At a minimum, do three things: restrict source access, protect `gateway.auth.token`, and use a separate Crazyrouter token for OpenClaw. If exposing directly to the public internet, it’s recommended to add a reverse proxy and extra access control.
