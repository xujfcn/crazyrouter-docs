# Gemini Audio Understanding

```text
POST /v1beta/models/{model}:generateContent
```

As of `2026-04-08`, Crazyrouter’s repeated testing at this site and with the local `4000` port show the following results:

- `gemini-3.1-pro` is able to read `audio/wav`
- The currently stable main pathway is `inlineData`
- For short audio, transcription, language detection, and summary can all be done directly through text prompts

---

## Verified Minimum Request

```bash
curl "https://api.crazyrouter.com/v1beta/models/gemini-3.1-pro:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "inlineData": {
              "mimeType": "audio/wav",
              "data": "BASE64_WAV_DATA"
            }
          },
          {
            "text": "请返回 JSON，字段为 transcript、language、summary。"
          }
        ]
      }
    ],
    "generationConfig": {
      "maxOutputTokens": 512
    }
  }'
```

Key patterns of successful returns in production environments:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "```json\n{\n  \"transcript\": \"叮\",\n  \"language\": \"zh-CN\",\n  \"summary\": \"音频中包含一个简短的提示音。\"\n}\n```"
          }
        ]
      }
    }
  ]
}
```

## Request Essentials

- Audio understanding should prioritize `inlineData`
- `mimeType` should match the actual audio format, such as `audio/wav`, `audio/mpeg`
- Only include the Base64 content in `data`, do not add the Data URL prefix
- If you require strict JSON, you can also add [structured output](/en/features/structured-outputs) constraints

<Note>
  This page documents the main pathway for short audio understanding that has been fully tested. For longer audio transcription and speech generation, please refer to the existing [STT](/en/audio/stt), [TTS](/en/audio/tts) pages. Realtime is not currently recommended as a public demo case.
</Note>
