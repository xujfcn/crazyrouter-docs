# Gemini Video Understanding

```text
POST /v1beta/models/{model}:generateContent
```

As of `2026-04-08`, repeated tests between Crazyrouter site and local `4000` port show:

- `gemini-3.1-pro` can read `video/mp4`
- The currently stable main process is `fileData.fileUri`
- Video files must be on a public URL accessible by Gemini upstream

---

## Minimum Verified Request

```bash
curl "https://api.crazyrouter.com/v1beta/models/gemini-3.1-pro:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "fileData": {
              "mimeType": "video/mp4",
              "fileUri": "https://example.com/demo.mp4"
            }
          },
          {
            "text": "请用一句中文回答：视频里的主体是什么，如何运动，镜头是否固定。"
          }
        ]
      }
    ],
    "generationConfig": {
      "maxOutputTokens": 512
    }
  }'
```

Key structure that has successfully returned in similar production environments:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "视频里的主体是一个红色小球，它从左向右滚动，镜头是固定的。"
          }
        ]
      }
    }
  ]
}
```

## Request Essentials

- The currently recommended way for video understanding is `fileData.fileUri`
- `mimeType` should be filled with the actual file, such as `video/mp4`
- `fileUri` must be accessible by Gemini upstream
- If the file is in a private network, requires authentication, or the URL cannot be connected directly, it is currently very likely to fail

<Note>
  For image understanding, use `inlineData` first. Do not directly copy the successful method for images to videos. For images, see [Gemini Image Understanding](/en/chat/gemini/vision).
</Note>
