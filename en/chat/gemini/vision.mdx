# Gemini Image Understanding

```
POST /v1beta/models/{model}:generateContent
```

As of `2026-04-08`, repeated local testing between Crazyrouter and `4000` port shows:

- `gemini-3.1-pro` can reliably read images through `inlineData` and return text descriptions
- Using remote image URLs as `fileData.fileUri` has encountered issues such as fetch failures and abnormal upstream responses across various channels
- Therefore, the recommended method for image understanding in this document is to use `inlineData`

---

## Verified Minimal Request

```bash
curl "https://api.crazyrouter.com/v1beta/models/gemini-3.1-pro:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "BASE64_PNG_DATA"
            }
          },
          {
            "text": "请用一句中文描述这张图片里有什么。"
          }
        ]
      }
    ]
  }'
```

The key response format seen in production:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "这张图片展示了多种鲜艳色彩平滑过渡的渐变效果。"
          }
        ]
      }
    }
  ]
}
```

## Request Key Points

- For image understanding, give priority to `inlineData`
- `mimeType` should match the actual image format, such as `image/png` or `image/jpeg`
- For `data`, only fill in the Base64 content; do not include the `data:image/...;base64,` prefix
- If you only have a remote image URL, do not use it as the preferred main pathway for Gemini image understanding at this time

<Note>
  If you want to work with video understanding, see [Gemini Video Understanding](/en/chat/gemini/video). If you want to work with audio understanding, see [Gemini Audio Understanding](/en/chat/gemini/audio).
</Note>
