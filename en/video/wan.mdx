# Wan Video

The Wan series currently uses different client-facing protocols based on its capabilities:

- Text-to-Video (`wan2.5-t2v-preview`, `wan2.2-t2v-plus`): Uses `POST /v1/video/generations`, and queries via `GET /v1/video/generations/{task_id}`.
- Image-to-Video, First & Last Frame Video, Subject Reference Video: Uses Alibaba Bailian compatible path `POST /alibailian/api/v1/services/aigc/video-generation/video-synthesis`, and queries via `GET /alibailian/api/v1/tasks/{task_id}`.

<Warning>
  Do not submit `wan2.2-t2v-plus` to `/alibailian/api/v1/services/aigc/video-generation/video-synthesis`. Production environment will return `invalid_request`, and prompt you to use `/v1/video/generations` instead.
</Warning>

For complete request body and task query formats in Alibaba-format workflows, please see the [Alibaba Bailian Video API](/en/video/alibailian). This page summarizes currently available `Wan` models, capabilities, pricing units, and recommended protocols.

## Protocol Agreements

### 1. Text-to-Video

- Recommended submission path: `POST /v1/video/generations`
- Recommended query path: `GET /v1/video/generations/{task_id}`
- Key fields: `model`, `prompt`, `seconds`, `size`
- Typical models: `wan2.5-t2v-preview`, `wan2.2-t2v-plus`

### 2. Image-to-Video

- Key field: `input.img_url`
- Typical models: `wan2.5-i2v-preview`, `wan2.2-i2v-plus`, `wan2.2-i2v-flash`

### 3. First & Last Frame Video

- Key fields: `input.first_frame_url`, `input.last_frame_url`
- Typical model: `wan2.2-kf2v-flash`

### 4. Subject Reference Video

- Key fields: `input.image_url`
- Typical model: `wan2.2-s2v`

## Request Examples

### Text-to-Video: Wan 2.2 T2V Plus

```bash cURL
curl -X POST https://api.crazyrouter.com/v1/video/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "wan2.2-t2v-plus",
    "prompt": "一段平静的电影感山间云海镜头",
    "seconds": "5",
    "size": "480P"
  }'
```

### Image-to-Video

```bash cURL
curl -X POST https://api.crazyrouter.com/alibailian/api/v1/services/aigc/video-generation/video-synthesis \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "wan2.5-i2v-preview",
    "input": {
      "prompt": "让画面中的人物转头看向镜头",
      "img_url": "https://example.com/first-frame.png"
    },
    "parameters": {
      "resolution": "720P",
      "duration": 5,
      "prompt_extend": true,
      "audio": true
    }
  }'
```

## Task Retrieval

Wan currently still uses an asynchronous task model. After the client creates a task, query according to the submission protocol:

Text-to-Video:

```http
GET /v1/video/generations/{task_id}
```

Alibaba-compatible workflows for image, first&last frame, and subject reference:

```http
GET /alibailian/api/v1/tasks/{task_id}
```

When the query returns `status = SUCCESS`, obtain the final video result from `result_url` or `artifact_url`.

## Boundary Explanations

- The currently recommended client protocol for Wan text-to-video is `/v1/video/generations`, not the Alibaba Bailian compatible submission path.
- The Alibaba Bailian compatible path is mainly used for migration scenarios such as image-to-video, first&last frame video, and subject reference video in Alibaba formats.
- Internally, Crazyrouter can use Official, ApiPass, Kie, or other third-party providers as providers, but these providers do not define client protocols individually.
- Beta rows can be shown to clients initially; after launch, combine with production task logs to supplement live evidence. After successful closed-loop, remove the Beta label.
