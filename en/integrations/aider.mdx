> Content updated: 2026-06-09

Aider is a very practical terminal-based pair programming tool, suitable for making incremental code changes, reviewing diffs, adding context files, and fixing issues in rounds within a Git repository. When connecting to Crazyrouter, the most reliable way is to use the officially supported OpenAI-compatible configuration of Aider.

## Overview

By using environment variables or `~/.aider.conf.yml`, Aider can send requests to Crazyrouter:

- Recommended protocol: `OpenAI-compatible API`
- Base URL: `https://api.crazyrouter.com/v1`
- Authentication variable: `OPENAI_API_KEY`
- Recommended default model notation: `gpt-5.5`

<Tip>
If your usual workflow is "read code -> change a few places -> view diff -> fix again", Aider is often the lightest and most stable terminal coding tool to land for real use.
</Tip>

## Who It's For

- People who want to make incremental code changes and commits in the terminal
- Those who want clear control over context files, diffs, and commit rhythm
- Users who want to manage billing for Aider, Codex, and Claude Code separately
- Anyone who wants to connect Crazyrouter using the most direct OpenAI-compatible method first

## Protocol Usage

Recommended protocol: `OpenAI-compatible API`

Aider officially supports the following configuration items:

- `OPENAI_API_KEY`
- `OPENAI_API_BASE`
- `openai-api-key`
- `openai-api-base`

Crazyrouter's corresponding notation:

```text
OPENAI_API_BASE=https://api.crazyrouter.com/v1
```

Also note: Crazyrouter's model name is the original model ID shown in the backend model list and pricing page, such as `gpt-5.5` and `claude-opus-4-8`. The same model ID should be filled in directly in Aider:

```text
gpt-5.5
```

<Warning>
Do not add extra `openai/` prefixes to Crazyrouter model names. `openai/gpt-5.5` is not a model name on this site and will cause `model not found` errors or no available channels for routing.
</Warning>

## Complete Installation Paths by Operating System

### Recommended Path for Windows

The most reliable path for Aider on Windows is: `Git` + `Python` + `PowerShell installation of Aider` + `PowerShell: Set environment variables`.

Recommended order:

1. Install Git
2. Install Python
3. Use PowerShell to run Aider's official installation script, or install `aider-install` first
4. Set temporary environment variables with PowerShell
5. Set persistent user-level environment variables with PowerShell
6. Open a new terminal to confirm `aider` command and variables are effective

Recommended verification command:

```powershell
git --version
python --version
pip --version
aider --version
where.exe git
where.exe python
where.exe aider
```

If `aider --version` cannot find the command, close and reopen PowerShell before trying again.

### Recommended Path for macOS

The smoothest path for Aider on macOS is usually: `Xcode Command Line Tools` + `Homebrew` + `Git` + `Python` + `Official Aider installation script` + `~/.zshrc` to persist environment variables.

Recommended order:

1. Install Xcode Command Line Tools
2. Install Homebrew (if you don’t already have it)
3. Install Git and Python
4. Run Aider's official installation script, or install via `aider-install` / `uv`
5. Write `~/.zshrc`
6. Open a new terminal to verify `aider` command and variable paths

Recommended verification command:

```bash
git --version
python3 --version
pip3 --version
aider --version
which git
which python3
which aider
```

### Linux Instructions

Linux can generally follow the terminal path for macOS, except persistent environment variables are usually written to `~/.bashrc`. If this is your local development machine or first connection to a cloud server, prioritize using temporary variables in the current shell before deciding whether to write them persistently.

## Complete Installation from Scratch

<Steps>
  <Step title="Step 1: Install Git">
    If the machine doesn't have Git, install it first.

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install --id Git.Git -e --source winget
        git --version
        where.exe git
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        xcode-select --install
        git --version
        ```
        Or:
        ```bash
        brew install git
        git --version
        which git
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo apt update
        sudo apt install -y git
        git --version
        which git
        ```
      </Tab>
    </Tabs>

    It's recommended to supplement:

    ```bash
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
    git config --global init.defaultBranch main
    ```
  </Step>

  <Step title="Step 2: Install Python and pip">
    The official Aider installer will use Python or automatically prepare its own Python runtime environment. For easier troubleshooting, confirm Python is available on your machine first.

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install Python.Python.3.12
        python --version
        pip --version
        where.exe python
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        brew install python
        python3 --version
        pip3 --version
        which python3
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo apt update
        sudo apt install -y python3 python3-pip python3-venv
        python3 --version
        pip3 --version
        which python3
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Step 3: Install Aider">
    The currently recommended one-click installation script from Aider is as follows.

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        powershell -ExecutionPolicy ByPass -c "irm https://aider.chat/install.ps1 | iex"
        aider --version
        where.exe aider
        ```
      </Tab>
      <Tab title="macOS / Linux">
        ```bash
        curl -LsSf https://aider.chat/install.sh | sh
        aider --version
        which aider
        ```
      </Tab>
    </Tabs>

    If you want to clearly see the installation process, you can follow the official Aider `aider-install` method:

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        python -m pip install aider-install
        aider-install
        aider --version
        ```
      </Tab>
      <Tab title="macOS / Linux">
        ```bash
        python3 -m pip install aider-install
        aider-install
        aider --version
        ```
      </Tab>
    </Tabs>

    If your team already uses `uv` uniformly, follow the official documentation for installation:

    ```bash
    python -m pip install uv
    uv tool install --force --python python3.12 --with pip aider-chat@latest
    aider --version
    ```

    <Warning>
    It's not recommended to manually `pip install aider-chat` to the system environment right from the start. The official recommendation is to use installation scripts, `aider-install`, or `uv` for more reliable dependency isolation.
    </Warning>
  </Step>

  <Step title="Step 4: Create a dedicated Aider token in Crazyrouter">
    Create a token named `aider` in the Crazyrouter backend, and initially only enable:

    - `gpt-5.5`
    - `claude-opus-4-8`
    - `gemini-3.1-pro`

    <Note>
    The whitelist here uses the original Crazyrouter model names; no need to write the `openai/` prefix.
    </Note>
  </Step>

  <Step title="Step 5: Temporarily set environment variables in the current terminal">
    First configure temporarily, after successful testing then write persistent settings.

    <Tabs>
      <Tab title="macOS / Linux">
        ```bash
        export OPENAI_API_KEY=sk-xxx
        export OPENAI_API_BASE=https://api.crazyrouter.com/v1
        echo $OPENAI_API_KEY
        echo $OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        $env:OPENAI_API_KEY = "sk-xxx"
        $env:OPENAI_API_BASE = "https://api.crazyrouter.com/v1"
        echo $env:OPENAI_API_KEY
        echo $env:OPENAI_API_BASE
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Step 6: Write the environment variable to a persistent configuration">
    <Tabs>
      <Tab title="Linux Bash">
        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.bashrc
        echo 'export OPENAI_API_BASE=https://api.crazyrouter.com/v1' >> ~/.bashrc
        source ~/.bashrc
        echo $OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="macOS / Zsh">
        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.zshrc
        echo 'export OPENAI_API_BASE=https://api.crazyrouter.com/v1' >> ~/.zshrc
        source ~/.zshrc
        echo $OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        [System.Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "sk-xxx", "User")
        [System.Environment]::SetEnvironmentVariable("OPENAI_API_BASE", "https://api.crazyrouter.com/v1", "User")

        $env:OPENAI_API_KEY = "sk-xxx"
        $env:OPENAI_API_BASE = "https://api.crazyrouter.com/v1"

        echo $env:OPENAI_API_BASE
        ```
      </Tab>
    </Tabs>

    After persisting, it's recommended to open a new terminal and execute once more:

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        aider --version
        echo $env:OPENAI_API_BASE
        ```
      </Tab>
      <Tab title="macOS / Linux">
        ```bash
        aider --version
        echo $OPENAI_API_BASE
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Step 7: Optionally write to ~/.aider.conf.yml">
    If you don’t want to add parameters manually each time, you can write a configuration file.

    <Tabs>
      <Tab title="macOS / Linux">
        ```bash
        cat > ~/.aider.conf.yml <<'EOF'
        model: gpt-5.5
        openai-api-base: https://api.crazyrouter.com/v1
        EOF
        cat ~/.aider.conf.yml
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        @'
        model: gpt-5.5
        openai-api-base: https://api.crazyrouter.com/v1
        '@ | Set-Content -Path "$HOME/.aider.conf.yml"

        Get-Content $HOME/.aider.conf.yml
        ```
      </Tab>
    </Tabs>

    For greater security, you can keep only the key in an environment variable and only leave `model` and `openai-api-base` in the configuration file.
  </Step>

  <Step title="Step 8: Prepare the Git repository and make the first snapshot">
    Aider provides the best experience in a Git repository. If the current directory is not a Git repository:

    ```bash
    git init
    git add .
    git commit -m "chore: initial snapshot before Aider"
    ```

    If it's an existing repository, check:

    ```bash
    git status
    ```
  </Step>

  <Step title="Step 9: Start Aider and complete the first verification">
    After entering the project directory, run:

    ```bash
    cd /path/to/your/project
    aider --model gpt-5.5
    ```

    For first-time verification, follow this order:

    1. `Please only summarize the current repository structure, do not modify any files`
    2. `Please read the README and provide the minimal changes needed. Do not make direct changes yet.`
    3. Confirm diffs are displayed normally before making small changes

    <Tip>
    If you want to temporarily test another model, use the same notation, e.g., `aider --model claude-opus-4-8`.
    </Tip>
  </Step>
</Steps>

## Recommended Model Configuration

| Usage Scenario | Recommended Notation in Aider | Reason |
|----------|------------------|------|
| Default main coding | `gpt-5.5` | Uses Crazyrouter's original model ID, suitable as the baseline for Aider’s OpenAI compatibility |
| Claude-style alternative | `claude-opus-4-8` | Suitable for long context explanations and stable multi-turn collaboration |
| Gemini backup | `gemini-3.1-pro` | Suitable as a second compatibility verification path |

It's recommended to start with `gpt-5.5`, then add `claude-opus-4-8` or `gemini-3.1-pro` as needed by the scenario after successful testing.

## Token Best Practices

| Setting | Recommendation | Description |
|------|------|------|
| Dedicated token | Mandatory | Aider should not share tokens with other IDEs / CLI |
| Model whitelist | Strongly recommended | Keep the model collection minimal to avoid switching mistakenly to pricier models |
| IP restriction | Enable depending on environment | Fixed servers can consider, be cautious with mobile dev machines |
| Quota limit | Strongly recommended | Aider's long sessions and multi-round fixes can consume resources continuously |
| Environment isolation | Recommended | Separate tokens for local development, remote machines, and CI |
| Leak handling | Rotate immediately | After `.aider.conf.yml` or shell history or screen recording leakage, change the key immediately |

## Common Errors and Fixes

| Phenomenon | Common Cause | Solution |
|------|----------|----------|
| `aider: command not found` | Aider was not installed successfully, or the installer did not add the executable to PATH | Run the official installer again and try a new terminal |
| Python version is messy | System Python conflicts with Aider environment | Give priority to using the install script, `aider-install` or `uv`, and avoid installing multiple dependencies yourself |
| 401 unauthorized | API Key is wrong, expired, or incomplete | Regenerate token and reset it |
| 403 / model not allowed | Token does not allow the current model | Allow the model in the Crazyrouter token settings |
| 404 | Wrong Base URL, or missing `/v1` | Change to `https://api.crazyrouter.com/v1` |
| `model not found` | Model name written incorrectly, used a non-existent `openai/` prefix, or the model is not open on this site | Revert to an original model ID listed on the pricing page or model list, e.g., `gpt-5.5`, `claude-opus-4-8` |
| Configuration file and environment variable behavior are inconsistent | Conflicting configurations | Keep one main configuration source and restart Aider |
| Cost increases too fast | Long sessions accumulate or too many context files | Clean up context and limit token quota timely |

## Performance and Cost Suggestions

- For first integrations, validate in a small repository first
- Use `gpt-5.5` by default; add `claude-opus-4-8` for cross-validation if needed
- It is recommended to separate tokens for different project types for cost statistics
- Clean up context timely when sessions get long to avoid carrying irrelevant files repeatedly
- After each major change, review Aider generated diffs and Crazyrouter logs

## FAQ

### Which Base URL should I fill in for Aider?

Enter `https://api.crazyrouter.com/v1`.

### Why shouldn't the model name be written as `openai/gpt-5.5`?

Because Crazyrouter's model names do not include the vendor prefix; the actual ID recognized on this site is the original model ID like `gpt-5.5`. `openai/gpt-5.5` will be treated as a different model name, which does not exist on this site.

### Should I use environment variables or a configuration file?

Either is fine. Using environment variables is faster to start; for long-term use, it is recommended to also add `~/.aider.conf.yml`.

### Why do you recommend creating a Git snapshot first the first time?

Because Aider will modify files, generate diffs, and automatically commit or suggest commits. Making a snapshot in advance makes troubleshooting and rollbacks much easier.

### What is the first recommended model?

Start with `gpt-5.5`.

### Does Aider have to be used in a Git repository?

It's not absolutely required, but the experience is usually best in a Git repository, and reviewing modification results is much easier.
