Cursor is suitable for connecting Crazyrouter to your daily coding workflow, for chatting, code explanation, refactoring suggestions, and general editing assistance.

## Overview

With Cursor's BYOK (Bring Your Own Key) capability, you can direct some chat model requests to Crazyrouter and be billed according to your own token.

- Recommended connection mode: OpenAI compatible mode
- Crazyrouter Base URL: `https://api.crazyrouter.com/v1`
- Authentication method: `sk-...` token
- Best initial features to connect: Chat, Ask, standard editing dialogs

<Warning>
According to Cursor’s official documentation, `Custom API keys only work with standard chat models`, features like Tab Completion that rely on special models will continue to use Cursor’s built-in models. This limitation comes from Cursor itself, not Crazyrouter.
</Warning>

## Who Should Use This

- Developers who want to use Crazyrouter token across Cursor
- Those who want to control model selection, costs, and quotas
- Teams wanting to connect Cursor’s chat abilities to Crazyrouter
- People who want separate billing and quota for different IDEs / CLI

## Usage Protocol

Recommended protocol: `OpenAI-compatible API`

When connecting Crazyrouter in Cursor, use the OpenAI-compatible base address:

```text
https://api.crazyrouter.com/v1
```

Do not use these:

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

## Prerequisites

| Item | Description |
|------|------|
| Crazyrouter account | Register first at [crazyrouter.com](https://crazyrouter.com) |
| Crazyrouter token | It’s recommended to create a separate `sk-...` token for Cursor usage |
| Cursor desktop | It’s recommended to upgrade to the latest stable version before configuring |
| Available models | Ensure at least 1 to 2 OpenAI-compatible chat models are permitted on your token |

Recommended to allow one of these models first:

- `gpt-5.5`
- `claude-opus-4-8`
- `gemini-3.1-pro`

<Tip>
If you need to configure Claude Code, Codex, Cline later, do not share the same token with Cursor. Separating tokens makes it easier to troubleshoot and control costs.
</Tip>

## 5-Minute Quick Start

<Steps>
  <Step title="Create a dedicated token for Cursor">
    In the Crazyrouter dashboard, create a new token. It’s recommended to name it `cursor`. Enable a small whitelist of models first, for example `gpt-5.5` and `claude-opus-4-8`.
  </Step>
  <Step title="Open Cursor settings">
    Open Cursor and go to `Cursor Settings` → `Models`.
  </Step>
  <Step title="Enter OpenAI access information">
    In the OpenAI-related configuration section, fill in:
    - `OpenAI API Key`: your `sk-...`
    - `Override OpenAI Base URL`: `https://api.crazyrouter.com/v1`

    If your Cursor version doesn't show `Override OpenAI Base URL`, it means the current version's support for custom OpenAI-compatible endpoints is incomplete. You should upgrade Cursor or wait for further improvements.
  </Step>
  <Step title="Validate the key and select a model">
    Click `Verify`. After passing, enable one model first for verification; it’s recommended to select `gpt-5.5`.
  </Step>
  <Step title="Complete the first test">
    Open Cursor’s chat panel and send a simple request, such as: `Reply with only OK`. If you get a successful response, Crazyrouter is connected.
  </Step>
</Steps>

Recommended sequence: start with `gpt-5.5`, then try `claude-opus-4-8` and `gemini-3.1-pro` step by step.

## Best Practices for Token Settings

| Setting | Recommendation | Description |
|------|------|------|
| Dedicated token | Mandatory | Use a separate token for Cursor to avoid mixing with other tools |
| Model whitelist | Recommended to enable | Only allow models actually used by Cursor |
| IP restriction | Enable as needed | Usually not recommended if your PC exit IP changes; enable for fixed office networks |
| Quota limit | Strongly recommended | Set a separate budget for Cursor to avoid consuming total quota all at once |
| Dev/production separation | Recommended | Use different tokens for personal machines, team machines, and CI machines |
| Rotation frequency | Recommended periodically | If screenshots, recordings, or sync config may leak tokens, reset regularly |

## Verification Checklist

- [ ] `Cursor Settings` → `Models` key works with `Verify`
- [ ] `Override OpenAI Base URL` is correctly set to `https://api.crazyrouter.com/v1`
- [ ] Successfully selected at least one Crazyrouter model
- [ ] First chat panel request returns successfully
- [ ] Corresponding requests are visible in Crazyrouter backend logs
- [ ] Token quota and model whitelist meet expectations
- [ ] You know that Tab Completion and other special abilities may not use Crazyrouter

## Common Errors and Fixes

| Phenomenon | Common cause | Fix |
|------|----------|----------|
| `Verify` failed | API Key error, or Base URL typo | Recheck `sk-...` and `https://api.crazyrouter.com/v1` |
| 401 unauthorized | Token is invalid, expired, or copied with spaces | Regenerate token and paste pure value only |
| 403 / model not allowed | Current model not allowed in token whitelist | Allow relevant model in Crazyrouter token settings |
| 404 | Base URL is set to root domain or specific endpoint | Change uniformly to `https://api.crazyrouter.com/v1` |
| Model list incorrect or missing | Cursor BYOK refresh failed, or version compatibility issue | Restart Cursor, re-verify, upgrade to latest stable if needed |
| Chat works but Tab completion doesn’t use Crazyrouter | Cursor official limitation: special abilities use built-in models | This is expected, not a Crazyrouter fault |
| Custom models not usable | Cursor’s support for custom OpenAI-compatible endpoints is unstable | Use `gpt-5.5` first, then try other models step by step |
| Unexpectedly high costs | Multiple functions sharing same token, or whitelist too wide | Narrow model scope and set separate quota for Cursor |

## Performance and Cost Recommendations

- Only enable `gpt-5.5` in the first phase
- Prioritize `gpt-5.5` for complex code explanations, summaries, and refactoring
- For multi-vendor verification, add `claude-opus-4-8` and `gemini-3.1-pro`
- If using Claude Code / Codex at the same time, split tokens to track costs
- When facing suspicious high consumption, check Crazyrouter logs to confirm if Cursor’s multi-turn context is the cause

## FAQ

### Which Base URL should be used in Cursor?

Use: `https://api.crazyrouter.com/v1`

### Why do some functions not go through Crazyrouter even though I entered a key?

Because Cursor's official docs state that custom API keys only cover standard chat models. Special abilities such as Tab Completion still use Cursor’s own models.

### Which model is recommended for the first time?

Use `gpt-5.5` first. It’s the latest OpenAI-compatible baseline successfully tested so far.

### Can I directly use Claude or other models?

It can be tried, but it’s best to complete basic verification via OpenAI-compatible route first. Whether custom models work smoothly depends on Cursor’s current compatibility implementation.

### What if chat works but model selection is always messed up?

Restart Cursor and re-verify; if the problem persists, roll back to `gpt-5.5`, which is a proven baseline.

<Note>
If you mainly want to use Crazyrouter in stable coding workflows, Claude Code, Codex, and Cline are often more directly controllable than Cursor’s custom endpoint route. Cursor is better suited to connect chat and general editing assistance first.
</Note>
