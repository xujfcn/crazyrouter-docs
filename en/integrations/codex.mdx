Codex CLI is OpenAI's command-line coding agent tool, suitable for making code changes, reviews, batch refactoring, and command collaboration in local repositories. When integrating with Crazyrouter, it is recommended to use the currently officially supported `config.toml` custom provider method instead of the old configuration approach.

## Overview

By configuring the custom provider with `~/.codex/config.toml`, Codex CLI can send requests to Crazyrouter:

- Recommended protocol: `OpenAI-compatible API`
- Interface type used: `Responses API`
- Base URL: `https://api.crazyrouter.com/v1`
- Authentication variable: `OPENAI_API_KEY`
- Recommended default model: `gpt-5.5`

<Tip>
If you have only used ChatGPT login before, please switch to API Key + custom provider configuration when connecting with Crazyrouter. This makes models, logs, quota, and billing more manageable.
</Tip>

## Who is this for?

- People who want to connect Crazyrouter to a terminal agent-style coding workflow
- People who want to perform batch modification, code review, and automation in local repositories
- People who want to split billing for Codex, Cursor, Claude Code traffic
- People who want to prioritize using the latest verified OpenAI models for terminal agent coding

## Usage Protocol

Recommended protocol: `OpenAI-compatible API`

Codex CLI currently recommends using the OpenAI-compatible provider via custom `model_provider`, and specifying:

- `base_url = "https://api.crazyrouter.com/v1"`
- `wire_api = "responses"`

<Note>
Crazyrouter supports `/v1/responses`, so Codex CLI can directly use the Responses API in this integration. However, this path only supports GPT models for now; Claude does not support `POST /v1/responses`.
</Note>

## Complete Installation Steps by Operating System

### Recommended Path for Windows

The simplest path for Codex on Windows is: `Git` + `Node.js` + `Globally install Codex using npm` + `Configure environment variables in PowerShell`.

Recommended sequence:

1. Install Git
2. Install Node.js LTS
3. Use npm to install Codex CLI
4. Use PowerShell to write `OPENAI_API_KEY`
5. Use PowerShell to write `$HOME/.codex/config.toml`

Recommended verification command:

```powershell
git --version
node -v
npm -v
codex --version
where.exe git
where.exe node
where.exe codex
```

If `codex --version` reports command not found, close and reopen PowerShell, then try again.

### Recommended Path for macOS

On macOS, the most convenient path is usually: `Homebrew` + `Git` + `Node.js` + `brew` or install Codex CLI via `npm` + persist environment variables with `~/.zshrc`.

Recommended sequence:

1. Install Xcode Command Line Tools
2. Install Homebrew (if you don't have it yet)
3. Install Git, Node.js
4. Install Codex CLI
5. Write `~/.zshrc`
6. Write `~/.codex/config.toml`

Recommended verification command:

```bash
git --version
node -v
npm -v
codex --version
which git
which node
which codex
```

### Alternative Codex CLI Installation Paths

In addition to package managers, the official Codex repository also offers GitHub Releases binary packages. For most users, it is still recommended to prioritize:

- Windows: `npm install -g @openai/codex`
- macOS: `brew install --cask codex` or `npm install -g @openai/codex`

If you want to use a script to automatically write Crazyrouter-related configurations, you can refer to [crazyrouter-codex-cli](https://github.com/xujfcn/crazyrouter-codex-cli). This repository provides one-click configuration scripts for Windows, macOS, and Linux; this documentation still retains complete manual configuration steps to make it easier for you to review every setting.

        winget install OpenJS.NodeJS.LTS

        sudo apt install -y nodejs npm
        node -v
        npm -v

      </Tab>
    </Tabs>

    If the default version installed by your distribution is too old, please upgrade to a later version before proceeding.
  </Step>

  <Step title="Step 3: Install Codex CLI">
    <Tabs>
      <Tab title="Windows PowerShell">
        It is recommended to use npm for global installation directly:
        ```powershell
        npm install -g @openai/codex
        codex --version
        where.exe codex
        ```
      </Tab>
      <Tab title="macOS">
        Homebrew is preferred:
        ```bash
        brew install --cask codex
        codex --version
        which codex
        ```

        If you prefer npm, you can also:
        ```bash
        npm install -g @openai/codex
        codex --version
        which codex
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Step 4: Create a dedicated Codex token in Crazyrouter">
    In the Crazyrouter backend, create a token named `codex`, and for the first time only allow:

    - `gpt-5.5`

    This keeps initial troubleshooting simple and better controls costs.
  </Step>

  <Step title="Step 5: First, set a temporary environment variable">
    Codex reads `OPENAI_API_KEY` from the provider configuration. First set in the current terminal:

    <Tabs>
      <Tab title="Linux / macOS">
        ```bash
        export OPENAI_API_KEY=sk-xxx
        echo $OPENAI_API_KEY
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        $env:OPENAI_API_KEY = "sk-xxx"
        echo $env:OPENAI_API_KEY
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Step 6: Save the API Key into a persistent environment variable">
    For daily use, it is recommended to write into your shell configuration file or user environment variables.

    <Tabs>
      <Tab title="Linux Bash">
        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.bashrc
        source ~/.bashrc
        ```
      </Tab>
      <Tab title="macOS / Zsh">
        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.zshrc
        source ~/.zshrc
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        [System.Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "sk-xxx", "User")
        $env:OPENAI_API_KEY = "sk-xxx"
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Step 7: Write the Codex configuration file to ~/.codex/config.toml">
    When Codex CLI starts, it will read `~/.codex/config.toml`.

    <Tabs>
      <Tab title="macOS">
        ```bash
        mkdir -p ~/.codex
        cat > ~/.codex/config.toml <<'EOF'
        model = "gpt-5.5"
        model_provider = "crazyrouter"

        [model_providers.crazyrouter]
        name = "Crazyrouter"
        base_url = "https://api.crazyrouter.com/v1"
        env_key = "OPENAI_API_KEY"
        wire_api = "responses"

        [profiles.crazyrouter]
        model = "gpt-5.5"
        model_provider = "crazyrouter"
        approval_policy = "on-request"
        sandbox_mode = "workspace-write"
        EOF
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        New-Item -ItemType Directory -Force "$HOME/.codex" | Out-Null
        @'
        model = "gpt-5.5"
        model_provider = "crazyrouter"

        [model_providers.crazyrouter]
        name = "Crazyrouter"
        base_url = "https://api.crazyrouter.com/v1"
        env_key = "OPENAI_API_KEY"
        wire_api = "responses"

        [profiles.crazyrouter]
        model = "gpt-5.5"
        model_provider = "crazyrouter"
        approval_policy = "on-request"
        sandbox_mode = "workspace-write"
        '@ | Set-Content -Path "$HOME/.codex/config.toml"
        ```
      </Tab>
    </Tabs>

    You can check after configuration:

    <Tabs>
      <Tab title="macOS">
        ```bash
        cat ~/.codex/config.toml
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        Get-Content $HOME/.codex/config.toml
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Step 8: Prepare the Git repository and make the first snapshot">
    If the directory is not yet a Git repository:

    ```bash
    git init
    git add .
    git commit -m "chore: initial snapshot before Codex"
    ```

    If it is already an existing repository, at least check:

    ```bash
    git status
    ```
  </Step>

  <Step title="Step 9: Start Codex and complete the first verification">
    Once inside the repository directory, you can first perform a minimal verification:

    ```bash
    cd /path/to/your/project
    codex --profile crazyrouter "Reply only OK"
    ```

    After success, enter interactive mode:

    ```bash
    codex --profile crazyrouter
    ```

    Initial verification is recommended in the following order:

    1. `Reply only OK`
    2. `Read the repository structure only. Do not edit files.`
    3. `Find the highest-risk file in this repo and explain why, but do not change anything.`
  </Step>
</Steps>

## Recommended Model Configuration

| Usage Scenario | Recommended Model | Reason |
|----------|----------|------|
| Default main coding | `gpt-5.5` | Successfully verified in production as of March 23, 2026, suitable as the main baseline for Codex / Responses API |

If you need Claude, please use native `POST /v1/messages` or OpenAI-compatible `POST /v1/chat/completions`; do not configure Claude for this Codex `wire_api = "responses"` route.

### Native Support for Domestic Models

Based on `2026-05-15` production retesting, the domestic models on Crazyrouter that support **native `POST /v1/responses`** and can be properly consumed by Codex CLI, are currently only recommended as follows:

| Model | Current Status | Remark |
|------|----------|------|
| `kimi-k2.5` | Recommended | `/v1/responses` SSE can fully return `response.completed`, Codex simple replies and file reading both pass |
| `kimi-k2.6` | Recommended | Same level as `kimi-k2.5`, currently a main domestic model candidate |
| `MiniMax-M2.7` | Not recommended for now | Min Responses probe already gets `convert_request_failed`, file reading tasks still break before `response.completed` |
| `deepseek-v4-pro` | Not recommended for now | Claude Code is usable, but there are still 500 / high demand / reconnection failures on this Codex Responses route |
| `glm-5.1` | Not recommended for now | The current production Responses native route falls onto an upstream not supporting this model, and Codex reports `stream closed before response.completed` |

If you want to try domestic models in Codex, it is recommended to first narrow the token whitelist to:

- `gpt-5.5`
- `kimi-k2.5`
- `kimi-k2.6`

It is not recommended to add `MiniMax-M2.7`, `deepseek-v4-pro`, `glm-5.1` directly to Codex's default whitelist unless you clearly accept experimental behavior and stream reconnection attempts.

### Switching to Domestic Models

Keep `base_url = "https://api.crazyrouter.com/v1"` and `wire_api = "responses"` unchanged, only replace the `model` field. For example:

```toml
model = "kimi-k2.5"
model_provider = "crazyrouter"

[model_providers.crazyrouter]
name = "Crazyrouter"
base_url = "https://api.crazyrouter.com/v1"
env_key = "OPENAI_API_KEY"
wire_api = "responses"

[profiles.crazyrouter]
model = "kimi-k2.5"
model_provider = "crazyrouter"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

When switching to a domestic model for the first time, it’s recommended to still verify in this order:

1. `Reply only OK`
2. `Read the repository structure only. Do not edit files.`
3. `Read agent.md and reply with exactly the first Markdown heading text.`

## Token Best Practices

| Setting | Recommendation | Note |
|---------|---------------|------|
| Dedicated token | Required | Codex should not share tokens with Cursor or Claude Code |
| Model allowlist | Highly recommended | Only open models that will actually be called by Codex |
| IP restriction | Recommended for fixed egress environments | Use with caution if personal devices change networks frequently |
| Quota limit | Highly recommended | Codex proxy-like operations can quickly use up quota |
| Environment isolation | Recommended | Use different tokens for local development, remote servers, and CI |
| Leak handling | Rotate immediately | If the token is exposed via shell history, configuration backup, or shared screens, replace it right away |

## Common Errors and Fixes

| Symptom | Common Cause | Solution |
|---------|-------------|----------|
| `codex: command not found` | CLI not installed correctly, or global npm dir not in PATH | Reinstall Codex and ensure npm global bin is in PATH |
| 401 unauthorized | `OPENAI_API_KEY` incorrect, expired, or copied with spaces | Regenerate token and reset environment variable |
| 403 / model not allowed | Token does not permit current model | Allow the corresponding model in Crazyrouter token settings |
| 404 | `base_url` written incorrectly, or `/v1` missing | Change to `https://api.crazyrouter.com/v1` |
| Request structure error | `wire_api` is not `responses` | Change to `wire_api = "responses"` |
| CLI starts but requests do not go via Crazyrouter | `model_provider` did not switch to `crazyrouter` | Check provider configuration of `config.toml` |
| Git changes are hard to review | Did not take a repo snapshot first | Commit an initial snapshot, then let Codex make real changes |
| Cost increases too quickly | Long context, multiple tool calls, or several repos sharing one token | Split tokens, set limits, and reduce model allowlists |

## Performance and Cost Recommendations

- Initially verify with a small repository, do not start by running full tasks in a huge repository
- Main recommendation: `gpt-5.5`, run the GPT / Responses main path first
- Separate accounting for Codex and IDE tools to identify sources of high consumption
- Set stricter token quota for high-risk repositories or CI scenarios
- On encountering unusually high usage, first check Crazyrouter logs to see if it was caused by multi-turn proxy actions

## FAQ

### What Base URL should Codex CLI use?

Use `https://api.crazyrouter.com/v1`.

### On Windows, is PowerShell or Git Bash recommended?

For initial setup, prioritize the PowerShell approach in the documentation, as it easiest keeps user environment variables and `$HOME/.codex/config.toml` consistent.

### Why configure `wire_api = "responses"` here?

Because Codex CLI’s custom provider is currently recommended to work through the Responses API, which Crazyrouter supports `/v1/responses`.

### Why is Claude no longer recommended here?

Because Claude currently only supports `POST /v1/messages` and `POST /v1/chat/completions`, not `POST /v1/responses`. This Codex integration goes through `wire_api = "responses"` by default, so Claude should not be used as the recommended model for this route.

### Why is it recommended to take a Git snapshot first?

Because Codex, as a proxy, can modify files and run commands. Taking a snapshot first makes review and rollback much easier.

### If I have already done `codex login`, do I still need to set up an API Key?

Yes. When connecting to Crazyrouter, you should still use `OPENAI_API_KEY` and custom provider settings.

### What is the first recommended model?

Start with `gpt-5.5`.

<Note>
If you want the smoothest terminal agent experience using the OpenAI / Responses API, configure Codex as per GPT / Responses. If you want to use Claude first, refer to the Claude Code or Claude native interface documentation.
</Note>
