LobeChat is suitable for use as a team chat entry point, a personal multi-model workstation, and a self-hosted AI chat frontend. When connecting to Crazyrouter, the most stable method is to use LobeChat’s `OpenAI` path and point the proxy address to Crazyrouter’s OpenAI-compatible base address.

## Overview

By using the OpenAI configuration options in LobeChat, you can route chat requests to Crazyrouter:

- Recommended protocol: `OpenAI-compatible API`
- Recommended integration: LobeChat `OpenAI` provider
- Base URL: `https://api.crazyrouter.com/v1`
- Authentication: `sk-...` token
- Recommended initial test model: `gpt-5.5`

If you are self-hosting LobeChat, you can also preset the default OpenAI path to Crazyrouter using environment variables.

## Who is this suitable for?

- Anyone wanting to self-host a stable chat frontend
- Anyone wanting to use Crazyrouter in a personal or team chat workstation
- Anyone wanting to manage multiple models centrally and retain chat history
- Anyone wanting to assign default models and configurations to internal members

## Usage Protocol

Recommended protocol: `OpenAI-compatible API`

When connecting Crazyrouter in LobeChat, you should use the OpenAI-compatible base address:

```text
https://api.crazyrouter.com/v1
```

Do not use:

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

<Note>
The LobeChat documentation describes `OPENAI_PROXY_URL` as the “OpenAI API request address,” and the common default values and examples also follow the `/v1` style; at the same time, the official example link given locally for `http://127.0.0.1:4000/api/status` is also `{address}/v1`. Therefore, when interfacing with Crazyrouter, prioritize entering `https://api.crazyrouter.com/v1`. If your own reverse proxy has already appended another layer of `/v1`, adjust it separately to avoid duplicate suffixes.
</Note>

## Prerequisites

| Item | Description |
|------|------|

| Crazyrouter token | Suggest creating a dedicated `sk-...` token for LobeChat |
| LobeChat | Either the online or self-hosted version works; the latest stable version is recommended |
| Available model | At least release one OpenAI-compatible chat model that has been tested successfully on the day, such as `gpt-5.5` |

Recommended initial whitelist:

- `gpt-5.5`
- `claude-opus-4-8`
- `gemini-3.1-pro`

<Tip>
If you also plan to connect Crazyrouter to Cursor, Codex, and Claude Code, it’s best for LobeChat to use a separate token, making it easier to track chat frontend consumption.
</Tip>

## 5-Minute Quick Start

<Steps>
  <Step title="Create a Dedicated Token for LobeChat">
    In the Crazyrouter backend, create a token named `lobechat`, and for the initial setup only allow models like `gpt-5.5` and `claude-opus-4-8` that have been successfully tested that day.
  </Step>
  <Step title="Open Language Model Settings">
    Enter LobeChat, click on the avatar in the bottom left or the settings entry, and open `Settings` → `Language Model`.
  </Step>
  <Step title="Configure OpenAI Path">
    In the `OpenAI` related configuration, fill in:
    - `API Key`: your `sk-...`
    - `API Proxy Address / API Proxy URL`: `https://api.crazyrouter.com/v1`

    At the same time, enable `Use Custom API Proxy Address` or an equivalent option.
  </Step>
  <Step title="Select a Baseline Model">
    After saving, first select `gpt-5.5` as the default model—do not enable many models at once.
  </Step>
  <Step title="Perform Initial Verification">
    Open a new conversation and send: `Reply only OK`. If there is a normal return and at the same time you can see logs in the Crazyrouter backend, the connection is successful.
  </Step>
</Steps>

## Quick Self-Host Configuration

If you deploy LobeChat yourself via Docker, you can first write the default OpenAI settings into environment variables:

```yaml
services:
  lobechat:
    image: lobehub/lobe-chat
    ports:
      - "3210:3210"
    environment:
      - OPENAI_API_KEY=sk-xxx
      - OPENAI_PROXY_URL=https://api.crazyrouter.com/v1
      - OPENAI_MODEL_LIST=gpt-5.5,claude-opus-4-8,gemini-3.1-pro
```

If you don’t want frontend users to arbitrarily change the Key, you can combine the hidden or managed configuration options supported by your current version to fix the default Key on the server environment variables.

## Token Setup Best Practices

| Setting | Suggestion | Description |
|------|------|------|
| Dedicated token | Required | LobeChat should not share tokens with IDE/CLI |
| Model whitelist | Highly recommended | Only open models needed on the chat end |
| IP restriction | Recommended when self-hosting with a fixed exit | Use with caution for public network or home networks with frequent changes |
| Quota limit | Highly recommended | It’s easy for the team chat frontend to have multiple users sharing the same token |
| Environment isolation | Suggestion | Use different tokens for test and production environments |
| Default model control | Suggestion | Remove high-cost models from the default list at first, enable as needed |

## Common Errors and Fixes

| Phenomenon | Common Cause | Fix |
|------|----------|----------|
| Cannot save or validation failed | Wrong API Key or incorrect proxy address | Double check `sk-...` and `https://api.crazyrouter.com/v1` |
| 401 unauthorized | Token expired, invalid, or deleted by mistake | Regenerate token and replace |
| 403 / model not allowed | The current model is not whitelisted for the token | Allow the model in Crazyrouter backend |
| 404 | Proxy address is set to the root domain or to a specific endpoint path | Change to `https://api.crazyrouter.com/v1` |
| Config looks correct but still 404 | Your own gateway, reverse proxy, or deployment layer has automatically appended an extra `/v1` | Check for duplicate suffix; if the upstream chain automatically appends `/v1`, do not repeat append |
| Model appears selectable but errors in use | LobeChat frontend cached old model or default model does not exist | Switch back to `gpt-5.5`, refresh, and reselect |
| Can send chat but streaming not working | Client version or model compatibility issue | First baseline test with `gpt-5.5`, then upgrade LobeChat |
| Rapid consumption with multiple users | Multiple users share the same token without a quota limit | Set quota for the team frontend, split tokens if necessary |
| Users can change upstream after self-hosting | Only the default is set, no restriction on frontend custom endpoints | Add managed config at deployment or disable frontend custom ability |

## Performance and Cost Suggestions

- Only keep `gpt-5.5` in the first phase
- For team chat, choose a low-cost default model; reserve high-cost models for advanced users or specific scenarios
- If you enable knowledge base, plugins, or long context chat, be sure to set a separate LobeChat quota
- In self-hosted environments, separate production and test tokens to prevent internal tests from affecting official quotas
- In case of excessive consumption, first check Crazyrouter logs to confirm if it’s caused by multiuser long dialogues

## FAQ

### Which Base URL should I enter in LobeChat?

Enter `https://api.crazyrouter.com/v1`.

### Why not just enter the root domain?

Because LobeChat’s OpenAI proxy config is better suited for entering the OpenAI-compatible base address, not just the root domain.

### What if my reverse proxy already adds `/v1` automatically?

Then don’t repeat write `/v1` in the address exposed to LobeChat. First check your proxy chain to avoid double suffixes.

### What is the first recommended model?

Start with `gpt-5.5`.

### Can LobeChat connect to multiple models at the same time?

Yes, but it’s best to verify with one model first and expand step by step.

### Should I hard-code the token in the environment variable when self-hosting?

If you want centralized upstream control and cost management, it’s recommended; if you need each user to use their own key, then open frontend customization.

<Note>
If your goal is a stable chat frontend and a team-shared workstation, LobeChat is a great choice; if your goal is code proxying and automation, tools like Cursor, Claude Code, Codex, and Cline should take precedence.
</Note>
