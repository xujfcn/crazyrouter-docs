Coze (Kouzi) is an intelligent agent and workflow platform launched by ByteDance, suitable for creating bots, orchestrating workflows, calling plugins, and publishing across multiple channels. When integrating with Crazyrouter, the most reliable and documentation-friendly approach is not to simply assume 'all versions support custom models,' but to prioritize using HTTP / API plugins or workflow HTTP request nodes.

## Conclusion First

For the vast majority of Crazyrouter users, Coze currently recommends these two avenues:

- Scheme 1: Use a `Create Based on API` plugin to call Crazyrouter
- Scheme 2: Use an HTTP request node within workflows to call Crazyrouter

It is not advised to write tutorials that make 'direct connection to Crazyrouter custom models within Coze model management' the main approach in public documentation because:

- There are significant differences in capabilities in Coze across various versions, regions, and plans
- Coze official plan documentation clearly states that `Custom Model` is one of the flagship enterprise edition capabilities
- Therefore, for public documentation, the safer main line should be the HTTP / API plugin route

<Warning>
The most important accuracy principle for this page is: write Coze’s public main line as 'HTTP / API plugin call Crazyrouter,' instead of assuming all users can directly register a custom upstream within model management.
</Warning>

## Who is this for?

- Users who want to integrate Crazyrouter into Coze bots or workflows
- People who want to use Crazyrouter as an external model call node
- Those who want to verify the minimum viable chain first, instead of immediately using enterprise edition custom model capability
- Those who want to let bots access multi-model capabilities via plugins or workflows

## Recommended Connection Methods

### Public Main Line: HTTP / API Plugin Route

Recommended parameters:

- Request method: `POST`
- URL: `https://api.crazyrouter.com/v1/chat/completions`
- Header:
  - `Authorization: Bearer sk-xxx`
  - `Content-Type: application/json`
- First verification model: `gpt-5.5`

### Why recommend this route first?

Because it:

- Least depends on Coze plan differences
- Easiest to determine whether it's a 'Coze configuration issue' or a 'Crazyrouter token/model issue'
- Most suitable for providing stable explanations in public documentation

## Scheme 1: Connect Crazyrouter via API Plugin

<Steps>
  <Step title="Step 1: Create a Coze-specific token in Crazyrouter">
    For the first attempt, only authorize:

    - `gpt-5.5`
    - `claude-opus-4-8`

    Don’t open up too many models right at the start; troubleshooting will be easier.
  </Step>

  <Step title="Step 2: Create an API plugin in Coze">
    After entering the Coze dashboard, navigate according to your current version’s interface:

    - `Plugin`
    - `Create Plugin`
    - Select `Create Based on API` or a similarly named entry

    <Note>
    Coze’s interface names may vary slightly by version, region, or product line, but the core idea is: create a plugin for external HTTP API.
    </Note>
  </Step>

  <Step title="Step 3: Configure the request method and URL">
    Fill in:

    - `Method`: `POST`
    - `URL`: `https://api.crazyrouter.com/v1/chat/completions`
  </Step>

  <Step title="Step 4: Configure request headers">
    Fill in:

    ```text
    Authorization: Bearer sk-xxx
    Content-Type: application/json
    ```
  </Step>

  <Step title="Step 5: Configure the minimum request body">
    For the first time, use the minimum request body:

    ```json
    {
      "model": "gpt-5.5",
      "messages": [
        {
          "role": "user",
          "content": "{{input}}"
        }
      ]
    }
    ```

    If your plugin interface supports parameter mapping, you can map user input to placeholders like `{{input}}`.
  </Step>

  <Step title="Step 6: First, perform connection verification in the plugin">
    If the current version supports debugging plugins, first try sending:

    ```text
    Reply only OK
    ```

    Confirm the interface can return results stably; then continue with adding it to bots or workflows.
  </Step>

  <Step title="Step 7: Call the plugin in the Bot or Workflow">
    Once the plugin passes standalone testing, add it to:

    - Bot plugin capabilities
    - Or workflow nodes

    For the first attempt, let the plugin handle only a simple task, such as summarizing, rewriting, or fixed Q&A.
  </Step>
</Steps>

## Scheme 2: Connect Crazyrouter via Workflow HTTP Request Node

If you do not want to maintain a plugin separately, you can directly call an HTTP request node within a workflow.

### Recommended Configuration

- Request method: `POST`
- URL: `https://api.crazyrouter.com/v1/chat/completions`
- Headers:
  - `Authorization: Bearer sk-xxx`
  - `Content-Type: application/json`
- Body:

```json
{
  "model": "gpt-5.5",
  "messages": [
    {
      "role": "user",
      "content": "{{input}}"
    }
  ]
}
```

### Recommended Verification Sequence

1. First, pass a fixed string `Reply only OK` in the node
2. Then change to variable input
3. Finally, map the output to subsequent nodes

## How to Understand "Custom Model Integration"

Some versions or plans of Coze may indeed support custom model integration, but this should not be the default main line in publicly available Crazyrouter documentation.

Reasons:

- Coze official plan FAQ currently lists `Custom Model` as one of the flagship enterprise edition capabilities
- For most ordinary users, the public, reproducible, and most easily validated route remains the HTTP / API plugin route
- Therefore this page only regards custom model capability as supplementary background, not as the main public tutorial

## Token Setup Best Practices

| Setting | Recommendation | Description |
|------|------|------|
| Dedicated token | Required | Coze should not share token with desktop clients or IDE tools |
| Model whitelist | Strongly recommended | First only authorize 1 to 2 models |
| Quota limit | Strongly recommended | Workflow loops and plugin retries amplify consumption |
| Environment isolation | Recommended | Separate tokens for dev / test / production environments |
| Leak handling | Swap immediately | Switch keys immediately if plugin screenshots or shared workspaces expose the token |

## Common Errors and Fixes

| Symptom | Common Causes | Fixes |
|------|----------|----------|
| 401 unauthorized | Token error, expired, or incomplete copy | Regenerate token and refill `Authorization` header |
| 404 | Incorrect URL, or missing `/v1/chat/completions` | Use complete URL |
| 403 / model not allowed | Token not authorizing current model | Authorize model in Crazyrouter token settings |
| `model not found` | Wrong model name | Revert to `gpt-5.5` for verification |
| Plugin creation succeeds but bot call fails | Plugin input/output mapping inconsistency | Revert to fixed string for debugging first |
| Workflow node occasionally fails | Node input too long, excessive retries or high concurrency | Reduce input size, lower complexity for minimum verification |
| Can't find 'model management integration' from someone else's tutorial | Version or plan differences | Return to HTTP / API plugin main line, don't first rely on enterprise edition capabilities |
