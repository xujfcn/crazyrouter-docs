Cline is a powerful proxy-based coding extension in VS Code, suitable for file reading/writing, terminal execution, step-by-step planning, and multi-turn code modification. When integrating with Crazyrouter, it is recommended to use the `OpenAI Compatible` provider officially provided by Cline.

## Overview

With Cline's OpenAI Compatible provider, you can send proxy requests to Crazyrouter:

- Recommended protocol: `OpenAI-compatible API`
- Base URL: `https://api.crazyrouter.com/v1`
- Authentication method: `sk-...` token
- Recommended default models: `claude-opus-4-8` or `gpt-5.5`

<Warning>
Cline has the capability to read and write files and execute terminal commands. After successful integration, the real risk is not "whether you can connect or not," but "whether you have granted it excessive execution permissions." It is recommended to start with a small repository that you are familiar with.
</Warning>

## Who Should Use This

- Those who want a proxy-based programming experience in VS Code
- Those who want to use Crazyrouter's multi-model abilities for code modification
- Those who want to separate IDE proxy traffic and CLI traffic for statistics
- Those who want to route models like Claude, GPT, etc., through a unified gateway

## Usage Protocol

Recommended protocol: `OpenAI-compatible API`

In the Cline settings, choose:

- `API Provider`: `OpenAI Compatible`
- `Base URL`: `https://api.crazyrouter.com/v1`
- `API Key`: your `sk-...`
- `Model ID`: the model name you want to use

Do not write your Base URL as:

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

<Note>
Unlike Claude Code, Codex, or Aider, Cline's standard VS Code integration usually does not require you to set environment variables manually. In most cases, simply fill in `Base URL`, `API Key`, and `Model ID` in the Cline settings interface.
</Note>

## Complete Installation Steps by Operating System

### Recommended Path on Windows

The most reliable installation path for Cline on Windows is: `Git` + `VS Code` + `Install Cline from the extension marketplace` + `Directly enter Crazyrouter parameters in the Cline settings`.

Recommended order:

1. Install Git
2. Install VS Code
3. Install Cline from the VS Code extension marketplace
4. Create a Cline-dedicated token in Crazyrouter
5. Open your repository and make a Git snapshot first
6. Fill in `OpenAI Compatible`, `Base URL`, `API Key`, `Model ID` in Cline's settings

Recommended verification command:

```powershell
git --version
where.exe git
code --version
where.exe code
```

If `code --version` cannot find the command but the VS Code app can open normally, it won't affect Cline's use; you just won't be able to open the folder directly from the terminal with `code` for now.

### Recommended Path on macOS

The most convenient path for Cline on macOS is usually: `Xcode Command Line Tools` + `Homebrew` + `Git` + `VS Code` + `Install Cline from the extension marketplace`.

Recommended order:

1. Install Xcode Command Line Tools
2. Install Homebrew (if you don't already have it)
3. Install Git
4. Install VS Code
5. Install Cline in VS Code
6. Fill in Crazyrouter parameters directly in Cline settings

Recommended verification command:

```bash
git --version
which git
open -a "Visual Studio Code"
```

If you want to use the `code` command directly from the terminal, execute `Shell Command: Install 'code' command in PATH` in the VS Code command palette, then check:

```bash
code --version
which code
```

### Note for Linux

Linux users can generally follow the approach used for Windows/macOS: install Git and VS Code first, then install Cline from the extension marketplace. Common commands for Ubuntu/Debian are as follows:

```bash
sudo apt update
sudo apt install -y git
sudo snap install code --classic
git --version
code --version
```

## Complete Installation from Scratch

<Steps>
  <Step title="Step 1: Install Git">
    If your machine does not have Git yet, install Git first.

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install --id Git.Git -e --source winget
        git --version
        where.exe git
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        xcode-select --install
        git --version
        ```
        Or:
        ```bash
        brew install git
        git --version
        which git
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo apt update
        sudo apt install -y git
        git --version
        which git
        ```
      </Tab>
    </Tabs>

    After installation, it is recommended to run:

    ```bash
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
    git config --global init.defaultBranch main
    ```
  </Step>

  <Step title="Step 2: Install VS Code">
    The most common way to use Cline is currently as a VS Code extension.

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install Microsoft.VisualStudioCode
        code --version
        where.exe code
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        brew install --cask visual-studio-code
        open -a "Visual Studio Code"
        ```

        If you want to run `code` directly from the terminal, then in the VS Code command palette execute:

        ```text
        Shell Command: Install 'code' command in PATH
        ```

        Then verify:

        ```bash
        code --version
        which code
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo snap install code --classic
        code --version
        which code
        ```
      </Tab>
    </Tabs>

    After installation, open VS Code normally at least once.
  </Step>

  <Step title="Step 3: Install the Cline extension">
    After opening VS Code:

    1. Press `Ctrl/Cmd + Shift + X` to open the extension marketplace
    2. Search for `Cline`
    3. Click Install
    4. After installation, click the Cline icon in the sidebar, or press `Ctrl/Cmd + Shift + P` and then run `Cline: Open In New Tab`

    If you see a message in VS Code similar to `Running extensions might...`, just choose Allow.

    If you don't see the icon, try restarting VS Code first and check again.
  </Step>

  <Step title="Step 4: Create a dedicated Cline token in Crazyrouter">
    Create a token named `cline` in the Crazyrouter dashboard; on your first attempt, only allow:

    - `claude-opus-4-8`
    - `gpt-5.5`
    - `gemini-3.1-pro`

    <Note>
    With Cline's standard VS Code approach, the API Key is usually filled in via the UI, rather than mainly relying on environment variables like Claude Code/Codex. So what's most important here is a dedicated token and a minimal model whitelist.
    </Note>
  </Step>

  <Step title="Step 5: Prepare the Git repository and make the first snapshot">
    Cline will change files and execute commands. Before connecting for the first time, it is recommended to make a repo snapshot first.

    If your directory is not yet a Git repo:

    ```bash
    git init
    git add .
    git commit -m "chore: initial snapshot before Cline"
    ```

    If it's already an existing repo, at least check:

    ```bash
    git status
    ```
  </Step>

  <Step title="Step 6: Enter the Crazyrouter configuration in Cline">
    After entering Cline's settings, fill in:

    - `API Provider`: `OpenAI Compatible`
    - `Base URL`: `https://api.crazyrouter.com/v1`
    - `API Key`: your `sk-...`
    - `Model ID`: initially use `claude-opus-4-8`

    If your current version of Cline UI has a `Verify` button, recommend clicking it once to confirm the connection is usable; if not, you can simply send a read-only test request to verify.

    For your first test, use just one model -- don't try switching between many models at once.
  </Step>

  <Step title="Step 7: Complete the first verification">
    For your first verification, suggest this order:

    1. Have Cline perform a read-only task: `Only read the current workspace README and summarize the main points, without modifying any files`
    2. Then let it do a low-risk analysis: `Point out the top 3 files in the current repository that are most worth checking first`
    3. Finally try a small-scope modification: `Modify only one obvious typo in the README and show the diff`

    When all three steps work normally, and you can see the corresponding request logs in Crazyrouter's backend, it means the main connection is stable.
  </Step>

  <Step title="Step 8: Gradually enable stronger permissions step by step">
    Once read-only and small-scope changes are stable, then gradually try:

    1. Multi-file small-scope modifications
    2. Allowing it to execute low-risk commands
    3. Finally have it perform more complex proxy-based refactoring

    It is not recommended to have Cline perform large-scale automatic operations in a big repository right from the start.
  </Step>
</Steps>

## Recommended Model Configuration

| Usage Scenario | Recommended Model | Reason |
|----------|----------|------|
| Default main proxy | `claude-opus-4-8` | Stable in multi-step planning, code explanation, long-context performance |
| OpenAI compatible baseline | `gpt-5.5` | Successfully tested in production on March 23, 2026; suitable for OpenAI-compatible baseline |
| Gemini backup | `gemini-3.1-pro` | Suitable as a secondary compatibility verification path |

It is suggested to first use `claude-opus-4-8` to validate the proxy workflow; if you want to add an OpenAI-compatible baseline, switch to `gpt-5.5`.

## Best Practices for Token Setup

| Setting | Suggested | Description |
|------|------|------|
| Dedicated token | Required | Cline should not share tokens with Cursor, Claude Code, or Aider |
| Model whitelist | Highly recommended | Cline is a high-consumption tool; the narrower the whitelist, the safer |
| IP restriction | Enable in fixed office environment | Be careful when using mobile networks on a laptop |
| Quota limit | Highly recommended | Multi-turn proxying can quickly use up quotas |
| Environment isolation | Recommended | Separate tokens for personal VS Code, remote development machines, and team-shared environments |
| Permission isolation | Highly recommended | For high-risk repos, set up a separate token with smaller quota |

- [ ] `git --version` is working properly

## Common Errors and Fixes

| Issue | Common Cause | Solution |
|-------|-------------|---------|
| Extension installed but Cline icon not visible | VS Code hasn't refreshed, or the extension hasn't activated correctly | Restart VS Code, then open Cline from the command palette |
| `code` command not available | VS Code core installed, but shell command not added to PATH | Restart terminal on Windows and try again; on macOS, run `Shell Command: Install 'code' command in PATH` from the command palette |
| 401 unauthorized | API Key is incorrect, expired or copied incorrectly | Regenerate the token and paste it again |
| 403 / model not allowed | Token doesn't permit the current model | Allow the model in Crazyrouter token settings |
| 404 | Base URL filled with root domain or specific API endpoint | Change it to `https://api.crazyrouter.com/v1` |
| `model not found` | `Model ID` name written incorrectly, or current model unavailable | Revert to `claude-opus-4-8` or another permitted model |
| Can't connect under enterprise network | Proxy or firewall blocking connections | Check VS Code's own proxy settings first; the Cline extension will reuse VS Code's network proxy configuration |
| Writing files that shouldn't be written | Granted overly broad write permissions at the start | Start by verifying only read tasks and small-scope diffs |
| Rapid increase in costs | Multistep workflows + large context + automatic execution | Reduce task scope and set a separate budget for Cline |

## Performance and Cost Recommendations

- When integrating for the first time, only perform read-only tasks and small-scope modifications
- Prioritize `claude-opus-4-8` or `gpt-5.5` for complex refactoring
- For high-frequency, lightweight tasks, don't expand to too many models at first; focus on keeping the whitelist concise
- It's recommended to use different tokens for different workspaces or project types
- After executing each large task, check the Crazyrouter log to confirm actual consumption

## FAQ

### Which Provider should I choose for Cline?

Choose `OpenAI Compatible`.

### What should be entered for Base URL?

Enter `https://api.crazyrouter.com/v1`.

### Do I have to write environment variables for this Cline integration method?

Usually not. The standard VS Code integration generally only requires entering `Base URL`, `API Key`, and `Model ID` in the Cline settings interface.

### Why should I create a Git snapshot the first time?

Because Cline can truly read and write files and execute commands as an agent. Creating a snapshot first makes reviewing and reverting changes much easier.

### What is the first recommended model?

Start with `claude-opus-4-8`.

### Why is it not recommended to grant large permissions at first?

Because Cline actually operates in your workspace. It's most reliable to verify with read-only or small-scope tasks at first before going live.

<Note>
If you value integrated agent experience within VS Code more, Cline is more suitable for being a "true code agent" compared to Cursor's BYOK approach.
</Note>
