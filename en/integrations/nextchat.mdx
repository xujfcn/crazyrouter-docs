NextChat (formerly ChatGPT Next Web) is suitable for quickly building a lightweight, fast-responding, and easy-to-self-host chat frontend. When connecting with Crazyrouter, it is recommended to continue using its default OpenAI-compatible route, setting the service address to Crazyrouter's root domain.

## Overview

Using NextChat's OpenAI configuration options, you can send requests to Crazyrouter:

- Recommended protocol: `OpenAI-compatible API`
- Recommended integration method: NextChat's default OpenAI approach
- Base URL: `https://api.crazyrouter.com`
- Authentication method: `sk-...` token
- Recommended initial model for verification: `gpt-5.5`

<Note>
The NextChat official README defines `BASE_URL` as the OpenAI API request base URL, with the example also being the root domain type; meanwhile, the local `http://127.0.0.1:4000/api/status` exposes `server_address` as the root address. Therefore, when connecting Crazyrouter, we prioritize filling in `https://api.crazyrouter.com` for initial verification; if your custom version clearly requires a more specific path, adjust accordingly following your version's instructions.
</Note>

## Who is it suitable for

- Those who want to quickly deploy a lightweight chat frontend
- Those who want to use Crazyrouter for personal or small team web chat
- Those who want to distribute default models and upstream with environment variables
- Those who want to get the OpenAI-compatible route running with the minimum configuration

## Usage Protocol

Recommended protocol: `OpenAI-compatible API`

When integrating Crazyrouter with NextChat, fill in first:

```text
https://api.crazyrouter.com
```

Do not fill in:

- `https://api.crazyrouter.com/v1/chat/completions`
- `https://api.crazyrouter.com/v1/models`

If your particular NextChat historical version requires manually specifying a more concrete API host, adjust it as instructed in that version; for the first connection, use the root domain for baseline verification.

<Tip>
In different NextChat deployment forms, entry positions may differ: for online use, it's usually filled in the settings page; for self-hosted, it's more common to distribute it directly via environment variables. Regardless of UI changes, always stick to the minimal configuration on the first round: `API Key` + root domain `BASE_URL` + single model `gpt-5.5`.
</Tip>

## 5-Minute Quick Start

<Steps>
  <Step title="Create a dedicated NextChat token">
    In the Crazyrouter backend, create a new token; suggested name is `nextchat`. Initially only whitelist baseline models like `gpt-5.5` and `claude-opus-4-8`.
  </Step>
  <Step title="Open NextChat settings">
    Enter NextChat, click the `Settings` icon in the lower left or the `Settings` entry.
  </Step>
  <Step title="Enter API address and Key">
    In the OpenAI-related settings, fill in:
    - `API Key`: your `sk-...`
    - `API address / Base URL`: `https://api.crazyrouter.com`
  </Step>
  <Step title="Specify model">
    In `Model`, manually enter or choose `gpt-5.5` first. If the current version supports custom model lists, add other models you need.
  </Step>
  <Step title="Complete first verification">
    Create a new conversation, send `Reply only OK`. After you receive a normal response, add more models step by step.
  </Step>
</Steps>

## Fast Configuration for Self-Hosting

Common Docker setup as follows:

```yaml
services:
  nextchat:
    image: yidadaa/chatgpt-next-web
    ports:
      - "3000:3000"
    environment:
      - OPENAI_API_KEY=sk-xxx
      - BASE_URL=https://api.crazyrouter.com
      - CUSTOM_MODELS=+gpt-5.5,+claude-opus-4-8,+gemini-3.1-pro
      - HIDE_USER_API_KEY=1
```

Common environment variable explanations:

| Variable            | Suggested Value       | Description                           |
|---------------------|---------------------|---------------------------------------|
| `OPENAI_API_KEY`     | `sk-xxx`     | Default Crazyrouter token              |
| `BASE_URL`     | `https://api.crazyrouter.com`     | Following official `BASE_URL` usage, fill in the root domain first as the baseline for initial verification |
| `CUSTOM_MODELS`     | `+gpt-5.5,+claude-opus-4-8,+gemini-3.1-pro`     | Add optional models for the frontend   |
| `HIDE_USER_API_KEY`     | `1`     | Prevent end users from entering other keys |

## Recommended Model Configuration

| Use Case                      | Recommended Model | Reason                              |
|------------------------------|-------------------|-------------------------------------|
| Default main chat model       | `gpt-5.5`   | Successfully tested today, suitable as NextChat's main baseline |
| High-quality long text/explanation | `claude-opus-4-8`   | More suitable for long text and complex explanations |
| Gemini backup                 | `gemini-3.1-pro`   | Good for supplementary compatibility verification path |

Recommended order: Run with `gpt-5.5` first, then extend the model list using `CUSTOM_MODELS`.

## Token Best Practices

| Setting           | Recommendation       | Explanation                           |
|-------------------|---------------------|---------------------------------------|
| Dedicated token   | Must                | NextChat should not share tokens with LobeChat, Cursor, Codex |
| Model whitelist   | Strongly recommended| Only allow the models that the frontend will actually display |
| IP Restriction    | Consider for fixed exit in self-hosting | Be cautious in personal environments with frequent network changes |
| Quota limit       | Strongly recommended| Web chat can quickly use up consumption when multi-user |
| Environment isolation | Recommended      | Use different tokens for demo, test, and production sites |
| User custom key   | Default off recommended | If you want unified upstream and billing, set `HIDE_USER_API_KEY=1` |

## Common Errors & Fixes

| Phenomenon             | Common Cause                                       | Fix                                     |
|------------------------|----------------------------------------------------|-----------------------------------------|
| 401 unauthorized       | Token wrong, expired, or extra spaces when copying | Regenerate token and replace            |
| 403 / model not allowed| Model not in whitelist                             | Allow corresponding model in Crazyrouter token settings |
| 404                    | Address set to full API path, or wrong version variable name | Change back to `https://api.crazyrouter.com` first and check if your version uses `BASE_URL` or another variable name |
| Cannot see relevant settings in frontend after self-hosted | Config is fixed in environment variables, not settings page | Directly check `OPENAI_API_KEY`, `BASE_URL`, `CUSTOM_MODELS` in deployment configs |
| Cannot see models in page | `CUSTOM_MODELS` not configured, or cached old config | Manually enter `gpt-5.5` first to verify, then refresh and check environment variables |
| Request sent but model error | Default model set wrong or unavailable | Roll back to `gpt-5.5` for baseline verification |
| Users can still use their own key | `HIDE_USER_API_KEY=1` not enabled | Add that variable in the deployment environment |
| Costs rise rapidly | Multiple users sharing a high-privilege token | Split tokens, shrink whitelist, set limits |

## Performance & Cost Recommendations

- By default, only enable `gpt-5.5`
- Remove high-cost models from default list and add as needed
- If deployed publicly or semi-publicly, try to hide user custom key entry
- Separate billing for demo and production sites to avoid test traffic affecting production quota
- If you experience abnormal consumption, first check Crazyrouter logs to determine if it's caused by long conversations or multi-user sharing

## FAQ

### Which address should NextChat fill in?

Prioritize `https://api.crazyrouter.com`.

### Why is directly filling in `/v1` not recommended here?

Because the NextChat official documentation example for `BASE_URL` is root domain style; combined with the local `4000` environment's return value of `server_address`, using the root domain for first verification is more stable.

### What is the first recommended model?

Start with `gpt-5.5`.

### Do I have to configure `CUSTOM_MODELS`?

It's not required. You can manually enter `gpt-5.5` to verify, and after confirming availability, add more models to the list.

### Why can some deployments only change environment variables and not settings on the page?

Because different NextChat deployment methods expose settings entry differently. Some self-hosted instances fix upstream, models, and keys in environment variables, with the frontend only for use, not editing.

### Should user custom key entry be hidden during self-hosting?

If you want unified upstream control and cost management, it's recommended to hide.

<Note>
If you want the lowest deployment cost for a lightweight chat frontend, NextChat is very suitable; if you need more team collaboration and advanced features, LobeChat or Dify are often more suitable for further expansion.
</Note>
