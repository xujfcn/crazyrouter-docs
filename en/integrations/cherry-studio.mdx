Cherry Studio is an AI client suitable for desktop multi-model chat, knowledge organization, and MCP tool integration. When integrating with Crazyrouter, it's recommended to use Cherry Studio's `OpenAI` custom provider mode for the best compatibility with model lists, streaming output, and common chat features.

## Overview

Using the custom provider feature in Cherry Studio, you can integrate Crazyrouter as an OpenAI-compatible upstream:

- Recommended protocol: `OpenAI-compatible API`
- Recommended provider type: `OpenAI`
- API address: `https://api.crazyrouter.com`
- Authentication method: `sk-...` token
- Recommended model for initial verification: `gpt-5.5`

<Note>
According to the official Cherry Studio documentation: if your upstream provides an interface in the format `https://xxx.com/v1/chat/completions`, you usually only need to fill in the root address in `API address`. In other words, when connecting Crazyrouter, you should prioritize filling in `https://api.crazyrouter.com`, not `https://api.crazyrouter.com/v1`.
</Note>

<Tip>
Cherry Studio will also automatically join the standard remaining path; only if your upstream is not a usual `.../v1/chat/completions` route do you need to manually fill in the complete address in `API address` ending with `#`. For regular Crazyrouter chat integration, this is not necessary.
</Tip>

## Who Is This For

- Those who want to manage multiple models on their desktop in a unified way
- Those who want to use Crazyrouter for daily chat, writing, translation, and data organization
- Those who want to connect MCP tools to a local chat client
- Those who want to quickly switch between low-cost and high-performance models in one interface

## Usage Protocol

Recommended protocol: `OpenAI-compatible API`

The recommended approach is to add a new custom provider of type `OpenAI`, then enter Crazyrouter's root domain in `API address`:

```text
https://api.crazyrouter.com
```

Do not fill in these at the start:

- `https://api.crazyrouter.com/v1/chat/completions`
- `https://api.crazyrouter.com/v1/models`

You only need to manually fill in the complete address ending with `#` in Cherry Studio if you are using a special non-standard route; this is not necessary for regular Crazyrouter chat integration.

## Prerequisites

| Item                  | Description                                                      |
|-----------------------|------------------------------------------------------------------|
| Crazyrouter account   | Register first at [crazyrouter.com](https://crazyrouter.com)              |
| Crazyrouter token     | It's recommended to create a separate `sk-...` token for Cherry Studio |
| Cherry Studio         | It's recommended to use the current stable desktop client         |
| Available models      | Allow at least one chat model successfully tested that day, such as `gpt-5.5` |

## 5-Minute Quick Start

<Steps>
  <Step title="Create a dedicated Cherry Studio token">
    In Crazyrouter's dashboard, create a new token. It's suggested to name it `cherry-studio`. For the first run, only allow 2 to 4 models you are certain you will use; do not open access to all models at once.
  </Step>
  <Step title="Add a custom provider">
    Open Cherry Studio, go to `Settings` → `Model service`, and click either the `Add` or `+ Add` button at the bottom. Choose the provider type `OpenAI`; it's suggested to name it `Crazyrouter`.
  </Step>
  <Step title="Fill in connection information">
    On the provider configuration page, fill in:
    - `API Key`: your `sk-...`
    - `API address`: `https://api.crazyrouter.com`

    After filling in, click `Check` to check if the token and address are valid.
  </Step>
  <Step title="Fetch and add model">
    Click `Manage` or `Manage` to pull the model list, then manually add the models you need into this provider. Note: the models showing up in the dialog doesn’t mean they are on the available list yet; normally you need to click `+` once more. For the first time, it’s recommended to only add one baseline model: `gpt-5.5`.
  </Step>
  <Step title="Activate provider and start the first conversation">
    Turn on the enable switch in the upper right, return to the chat interface and select `gpt-5.5`, send a simple request message, for example: `Reply only OK`. Once you receive a normal reply, you can start adding other models.
  </Step>
</Steps>

## Token Setting Best Practices

| Setting             | Recommendation   | Description                                                                  |
|---------------------|------------------|------------------------------------------------------------------------------|
| Dedicated token     | Required         | Cherry Studio should not share tokens with Cursor, Claude Code, Codex         |
| Model whitelist     | Strongly advised | Only allow models Cherry Studio will actually use                             |
| IP restriction      | Depends on device| May enable for fixed office networks; use cautiously for laptops frequently switching networks |
| Quota limit         | Strongly advised | Desktop chat clients can call frequently in multi-turn, recommend separate quota|
| Dev/production split| Advised          | Create separate tokens for personal, shared, or demo machines                 |
| Multi-key rotation  | Use cautiously   | Cherry Studio supports multi-key rotation, but troubleshooting is more complex; get single key working first |

## MCP Usage Tips

Cherry Studio supports MCP services, but it's recommended to do this in two steps:

1. First, only verify that the Crazyrouter chat model can work stably
2. Then add MCP service separately and test the tools one by one

This avoids mixing model integration problems with MCP tool issues during troubleshooting.

If you enable MCP:

- Choose a model that stably supports tool calls first
- Attach only one MCP service for verification at first
- When calling a tool for the first time, test the simplest read or query operation first

## Common Errors & Fixes

| Symptom                       | Common Cause                         | Fix                                                                  |
|-------------------------------|--------------------------------------|-----------------------------------------------------------------------|
| `Check` failed        | `API Key` error or token copied with spaces | Generate a new token, make sure only the pure `sk-...` is pasted|
| 401 unauthorized              | Token expired, invalid, or deleted   | Re-create and replace the token in Crazyrouter's dashboard             |
| 403 / model not allowed       | Model not on token whitelist         | Allow the corresponding model in the token settings                    |
| 404                           | `API address` filled in as full interface path or provider type incorrect | Change back to `OpenAI` type and write the address as `https://api.crazyrouter.com` |
| `Check` still fails but address and key look correct | Cherry Studio by default uses the last chat model in the current list for connectivity check—that model may be invalid | Keep only `gpt-5.5`, delete suspicious models and click `Check` again |
| Model list does not load      | Incorrect address, network issue, or provider not enabled | First click `Check`, then check enable switch and network connectivity |
| Connects but chat errors      | Added unsupported or unusable model  | Keep only `gpt-5.5` as baseline for verification                 |
| Streaming output abnormal     | Model or client version compatibility issue | Switch back to `gpt-5.5` and upgrade Cherry Studio                 |
| MCP tool calls fail           | Not a model issue but incomplete MCP service configuration | Disable MCP and only verify models; then fix MCP service separately  |

## Performance & Cost Suggestions

- For initial connection, keep only 1 or 2 models to avoid confusion from too many options
- Use `gpt-5.5` by default, switch to `claude-opus-4-8` for complex long text and code explanation
- If you frequently have long conversations, set a separate quota limit for Cherry Studio
- Cherry Studio supports multi-model switching; reserve expensive models for heavy tasks
- If you notice abnormal consumption, first check Crazyrouter logs to confirm if there are frequent retries or long context multi-turn conversations

## FAQ

### Which address should I fill in Cherry Studio?

Fill in `https://api.crazyrouter.com` first.

### Why isn’t it recommended to fill in `/v1` at first?

Because, according to Cherry Studio's official explanation, many OpenAI-compatible upstreams only require the root address, as the client will automatically join the standard path. The same approach is suggested for Crazyrouter.

### When do you need to provide the full interface address ending with `#`?

Only if your upstream is not a standard OpenAI route. For Crazyrouter’s regular chat integration, just use the root domain first.

### What’s the first recommended model?

Start with `gpt-5.5`.

### Can I configure many models at once?

You can, but it’s not recommended for the first time. First get one model working, then add the rest gradually.

### Can Cherry Studio and Crazyrouter be used with MCP?

Yes, but it’s best to verify the chat model works first, then enable MCP. This way, it’s easier to troubleshoot problems.

<Note>
If your main goal is desktop multi-model chat and lightweight MCP collaboration, Cherry Studio is a suitable entry point; if you prioritize IDE coding assistant experience, it’s still recommended to use tools like Cursor, Claude Code, Codex, or Cline first.
</Note>
