# Official Model Pricing Methods

This page only explains the official billing standards set by upstream manufacturers, which are not the same as Crazyrouter's actual sale prices.

- Upstream official standard: Charging methods such as `input`, `output`, `cached input`, `tool call`, `search grounding`, `prompt caching` as defined by the manufacturer
- Crazyrouter standard: Crazyrouter's own sale prices, rates, discounts, channel differences, and settlement methods

<Note>
  This page is organized according to the manufacturer's official documentation found via `2026-04-27`. Manufacturers may change prices, adjust preview models, long contexts, search tools, and cache rules; before launching, please check the official links again.
</Note>

## Sample Table of Official Unit Prices

The following examples only show the most common types from each manufacturer, which are easiest for direct business budgeting:

- Anthropic: Standard API price, does not include `Fast mode`, `US-only inference` multipliers and batch discounts
- OpenAI: `Standard` price, does not include batch, priority, regional processing surcharges
- Gemini: `Standard` price, defaults to text / image / video input, and selects `<= 200K prompt` tier for `Gemini 3*`
- xAI: If the internal routing name does not have a published static price, this table will state "not listed as a separate price"
- Z.AI: Uses official `Text Models` price
- MiniMax: Main table uses `Pay as You Go`, subscription plans are listed separately as `Token Plan`

<Note>
  Unless otherwise specified, all amounts below are in `USD / 1M tokens`.
</Note>

## Anthropic

The official billing method for this group of Anthropic models is not simply divided into two `input / output` columns, but rather split into:

- `Base Input Tokens`
- `5m Cache Writes`
- `1h Cache Writes`
- `Cache Hits & Refreshes`
- `Output Tokens`

There are also two general rules:

- `Batch API` Input and output are usually billed at standard price `50% off`
- The published multiplier rules for prompt caching are: `5 minute write cache = 1.25x input`, `1 hour write cache = 2x input`, `Read cache = 0.1x input`

| Internal Model Name | Official Equivalent | Official Billing Method | Special Notes |
| --- | --- | --- | --- |
| `claude-opus-4-8` | Anthropic `claude-opus-4-8` | Billed according to `base input / 5m cache write / 1h cache write / cache hit / output` | Anthropic's official documentation clearly states `Sonnet 4.6` supports `1M context`, and long contexts are billed at standard unit price with no extra surcharge |
| `claude-opus-4-8` | Anthropic `claude-opus-4-8` | Billed according to `base input / 5m cache write / 1h cache write / cache hit / output` | `Opus 4.6` also supports `1M context` standard billing; additionally, official documentation provides `Fast mode` separately, price is standard `6x` |
| `claude-opus-4-8` | Anthropic `claude-opus-4-8` | Billed according to `base input / 5m cache write / 1h cache write / cache hit / output` | `Opus 4.7` is currently a unique model publicly priced by Anthropic; if `US-only inference` is enabled, official documentation specifies `1.1x` multiplier |
| `claude-opus-4-8` | Anthropic snapshot ID `claude-opus-4-8`, public alias usually written as `claude-opus-4-8` | Still billed according to `Sonnet 4.5`'s `base input / cache write / cache hit / output` | This is a date-stamped API snapshot name, not a separate pricing scheme; budgeting should follow `Claude Sonnet 4.5` official standard understanding |

## OpenAI

The official public lines for this group of OpenAI text models are the most consistent, and the core points are:

- `Input`
- `Cached input`
- `Output`

Additional rules are usually:

- `Responses API` itself does not have a separate charge; it is still billed according to the token unit price of the selected model
- `Web search`, container/code execution, Computer Use and other tools are charged by the tool, not included in the pure token unit price
- `Batch API` input and output are usually billed at standard rate `50% off`

| Model Name On Site | Official Equivalent | Official Billing Method | Special Notes |
| --- | --- | --- | --- |
| `gpt-5.5` | Site alias, usually mapped to OpenAI `gpt-5.5` | Billed by `input / cached input / output` | The public listed price for `gpt-5.5` applies to `270K` contexts; regional processing endpoints have a different `+10%` |
| `gpt-4o` | OpenAI `gpt-4o` | Billed by `input / cached input / output` | `gpt-4o` is a classic unified statement. There is no separate cache write field like Claude, nor a separate Search grounding table like Gemini |
| `gpt-5` | OpenAI `gpt-5` | Billed by `input / cached input / output` | If you enable tools in the Responses API, tool costs are charged separately; there is no separately listed 'thinking token unit price' on the public pricing page |
| `gpt-5.5` | Should correspond to OpenAI `gpt-5.1-codex-max` on site | Billed by `input / cached input / output` | This is a Codex-oriented model, but the public price structure is still the same as the regular GPT-5.1 text model; more suitable for agentic coding / Codex workflow understanding |
| `gpt-5-mini` | OpenAI `gpt-5-mini` | Billed by `input / cached input / output` | Small model version. Structure is unchanged, but the unit price is lower |

| `gpt-5.5` | OpenAI `gpt-5.5` | Billed by `input / cached input / output` | Currently, OpenAI lists it as the flagship model; the public price page indicates that the standard price applies to `270K` token context, and for ultra-long contexts, please refer to the latest detailed price list |

## Google Gemini

Gemini's official billing method is most different from the other two companies; usually there is not just one standard price, but rather:

- `Standard`
- `Batch`
- `Flex`
- `Priority`

And specifically lists:

- `Input`
- `Output (including thinking tokens)`
- `Context caching price`
- `Context caching storage`
- `Grounding with Google Search`
- `Grounding with Google Maps`

| Model Name On Site | Official Equivalent | Official Billing Method | Special Notes |
| --- | --- | --- | --- |
| `gemini-3.1-pro` | Google `gemini-3.1-pro`, usually displayed on site as `gemini-3.1-pro` | Officially billed separately for the four `Standard / Batch / Flex / Priority` processing modes, and breaks out `input / output / caching / search grounding / maps grounding` for each mode | This is a preview model; and `<= 200K` and `> 200K` prompt have two price levels, not a single price |
| `gemini-2.5-flash-lite` | Google `gemini-2.5-flash-lite` | Billed separately by `Standard / Batch / Flex / Priority`, and lists `input / output / context caching / storage / Google Search / Google Maps` separately | This is a stable model, not preview; its `output` is clearly stated officially as “includes thinking tokens” |

## xAI Grok

xAI's official rules do not focus on whether the 'thinking model' has a separate price table, but instead separate out tokens and tools:

- `Prompt tokens`
- `Cached prompt tokens`
- `Completion tokens`
- `Reasoning tokens`

xAI further specifically states:

- `Reasoning tokens` is charged by `completion token price`
- `Web Search`, `X Search`, `Code Execution`, `Collections Search` and other server-side tools are charged separately according to `Per 1000 calls`
- `Batch API` token costs are usually `50% off`

| Model Name On Site | Official Equivalent | Official Billing Method | Special Notes |
| --- | --- | --- | --- |
| `grok-4.1-fast` | On-site reasoning route; officially mapped to Grok 4.1's `Thinking` configuration | The official statement is `prompt / cached prompt / completion / reasoning`'s four types of tokens, plus tool invocation fees as needed | xAI’s current public API price listings mainly cover the SKU like `grok-4-1-fast-reasoning`; therefore, a more accurate understanding here is “settle according to xAI reasoning model official billing structure”, and not treating the on-site name as an independent official SKU |
| `grok-4.1` | Main route for Grok 4.1 on site; officially closer to Grok 4.1’s non-thinking configuration | Official line is still `prompt / cached prompt / completion`; if you use search, code execution, or attachment search tools, the tool fee is charged separately | The xAI current public API page emphasizes `grok-4.1-fast` and `grok-4-1-fast-*`; so for budgeting, refer to the currently public xAI token and tool charging rules |

## MiniMax

MiniMax models need to differentiate between two official sales methods:

- `Pay as You Go`
- `Token Plan`

Among them:

- `Pay as You Go` is standard API pay-per-use billing
- `Token Plan` is on a subscription basis, and `M2.7` is billed by `5 hour rolling window request quota` instead of by tokens alone

| Model Name On Site | Official Equivalent | Official Billing Method | Special Notes |
| --- | --- | --- | --- |
| `MiniMax-M2.7` | Should correspond to `MiniMax-M2.7` on site | If you use `Pay as You Go`, bill according to `input / output / prompt caching read / prompt caching write`; if you use `Token Plan`, then use `requests / 5hrs` subscription quota to bill | This is the most unique out of all the companies on this page. When budgeting for production, first look at `Pay as You Go`; for developers with heavy coding usage, then see if `Token Plan` is more cost-effective |

## Conclusion

If you just want to quickly know “how does the official site actually bill”, just remember these categories:

- Anthropic: `base input + cache write/read + output`
- OpenAI: `input + cached input + output`, tools billed separately
- Gemini: `Multi-processing mode + input/output + caching + search/maps grounding`
- xAI: `prompt/cached/completion/reasoning`, server-side tools billed separately
- Z.AI: `input + cached input + cached storage + output`
- MiniMax: `Pay-as-you-go tokens` or `Subscription quota`, both exist together

<Warning>
  This page explains the “upstream official pricing method”, not Crazyrouter’s external selling price. For actual top-up, billing, multiplier, and discounts, please refer to the pricing, console, and `/api/pricing` returns within Crazyrouter.
</Warning>
