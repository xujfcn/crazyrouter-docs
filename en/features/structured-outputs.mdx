# Structured Outputs

This documentation only includes **Structured Outputs usage verified successfully through actual requests in the Crazyrouter production environment**.

Verification date:

- `2026-03-22`

Models that have been strictly verified successfully:

- `gpt-5.5`
- `gemini-3.1-pro`

Models currently not included as strictly successful examples:

- `claude-opus-4-8`

Reason:

- In the production revalidation, `claude-opus-4-8` did not display stable "strict pure JSON" behavior with the current OpenAI compatible `response_format=json_schema` request format
- Previous tests have resulted in fenced code blocks
- During the revalidation of `2026-03-22`, there was empty `content`
- Therefore, it is currently not marked as "strictly structured output verified successfully"

## GPT-5.4

```bash cURL
curl https://api.crazyrouter.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-5.5",
    "messages": [
      {
        "role": "user",
        "content": "Return a JSON object with keys city and country for Tokyo."
      }
    ],
    "response_format": {
      "type": "json_schema",
      "json_schema": {
        "name": "city_country",
        "strict": true,
        "schema": {
          "type": "object",
          "properties": {
            "city": {"type": "string"},
            "country": {"type": "string"}
          },
          "required": ["city", "country"],
          "additionalProperties": false
        }
      }
    }
  }'
```

Production validation return:

```json
{"city":"Tokyo","country":"Japan"}
```

## Gemini 3 Pro

```bash cURL
curl "https://api.crazyrouter.com/v1beta/models/gemini-3.1-pro:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "Return a JSON object with keys city and country for Tokyo."
          }
        ]
      }
    ],
    "generationConfig": {
      "responseMimeType": "application/json",
      "responseSchema": {
        "type": "object",
        "properties": {
          "city": {"type": "string"},
          "country": {"type": "string"}
        },
        "required": ["city", "country"]
      }
    }
  }'
```

Production validation return:

```json
{"city":"Tokyo","country":"Japan"}
```

## Claude 4.6 Current Conclusion

In the production test of `2026-03-22`:

- `claude-opus-4-8` did not produce stable, reproducible, strict JSON output with this request format
- Across different test runs, there have been both fenced code blocks and empty `content`
- Therefore, it is currently not recommended to mark Claude 4.6 as "strict schema output successfully verified"

If Claude 4.6 is to be included here in the future, it is recommended to perform another, more detailed round of production validation and confirm:

- Whether there is a more suitable native protocol approach
- Whether extra system prompts are needed
- Whether code fences can be stably removed
