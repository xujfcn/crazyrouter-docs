> Content updated: 2026-09-28

Crazyrouter provides a temporary public image upload interface, which allows you to convert a local reference image into a publicly accessible URL for models. It is suitable for interfaces such as Kling, Veo, Seedance, Runway, Luma, MiniMax, Nano Banana Pro, Doubao Seedream that require `image_url`, `image_urls`, `image_list`, `images`, or `image_input`.

<Note>
  Temporary images are kept for 48 hours by default and will be automatically deleted after expiration. No separate charges are incurred per day within the storage period; currently, abuse prevention is managed through user upload quota and rate limits.
</Note>

<Note>
  The returned `id` is the file record ID of this site. In the model request, `image_input` should use the returned `url` and cannot directly submit `id`. The Base64 / multipart upload option (`nano-banana-pro`) is restricted to specific accounts.
</Note>

## Interface Overview

| Scenario             | Interface         |
|----------------------|------------------|
| Local File Upload    | `POST /v1/files/uploads`  |
| Base64 Image Upload  | `POST /v1/files/uploads/base64`  |
| Remote Image Import  | `POST /v1/files/uploads/url`  |
| Pre-signed Direct R2 Upload | `POST /v1/files/uploads/presign` |

General Restrictions:

| Item                | Current Rule      |
|---------------------|------------------|
| Authentication      | `Authorization: Bearer YOUR_API_KEY`  |
| Supported Formats   | `image/png`, `image/jpeg`, `image/webp`, `image/gif` |
| Single File Size    | 20MB             |
| User Upload Quota   | 200MB / rolling 24-hour window |
| Default Valid Time  | 48 hours         |
| Returned URL        | `https://media.crazyrouter.com/task-artifacts/tmp-inputs/...`  |

## Local File Upload

```bash cURL
curl -X POST https://api.crazyrouter.com/v1/files/uploads \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@./reference.png" \
  -F "purpose=model_input"
```

Response Example:

```json
{
  "id": "file_e5bbce820b5941409682a9c5e9ba79f1",
  "url": "https://media.crazyrouter.com/task-artifacts/tmp-inputs/2026/05/13/user-1/file_e5bbce820b5941409682a9c5e9ba79f1.png",
  "mime_type": "image/png",
  "size": 2025,
  "expires_at": "2026-05-16T04:41:35.0131789Z"
}
```

## Base64 Upload

```bash cURL
curl -X POST https://api.crazyrouter.com/v1/files/uploads/base64 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "data": "data:image/png;base64,iVBORw0KGgoAAA...",
    "filename": "reference.png",
    "purpose": "model_input"
  }'
```

## Remote URL Import

```bash cURL
curl -X POST https://api.crazyrouter.com/v1/files/uploads/url \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "url": "https://example.com/reference.png",
    "filename": "reference.png",
    "purpose": "model_input"
  }'
```

The remote URL must be an image address (`http` or `https`) that is accessible to the Crazyrouter server. The system performs checks on file size, MIME type, and SSRF protection.

## Pre-signed Direct R2 Upload

For scenarios with high upload volumes, you can first request a pre-signed upload URL, then have the client directly `PUT` the image to the storage endpoint. Thus, the image binary does not pass through the Crazyrouter application server. This workflow is suitable for handling large numbers of image uploads every day.

Step 1: Request a direct upload URL:

```bash cURL
curl -X POST https://api.crazyrouter.com/v1/files/uploads/presign \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "filename": "reference.jpg",
    "content_type": "image/jpeg",
    "size": 12345,
    "purpose": "model_input"
  }'
```

Response Example:

```json
{
  "id": "file_e5bbce820b5941409682a9c5e9ba79f1",
  "upload_url": "https://...r2.cloudflarestorage.com/...?...",
  "url": "https://media.crazyrouter.com/task-artifacts/tmp-inputs/2026/06/21/user-1/file_e5bbce820b5941409682a9c5e9ba79f1.jpg",
  "method": "PUT",
  "headers": {
    "Content-Type": "image/jpeg",
    "Content-Length": "12345"
  },
  "mime_type": "image/jpeg",
  "size": 12345,
  "expires_at": "2026-06-22T04:41:35Z",
  "upload_expires_at": "2026-06-21T04:56:35Z"
}
```

Step 2: The client uploads directly to `upload_url`:

```bash cURL
curl -X PUT "$UPLOAD_URL" \
  -H "Content-Type: image/jpeg" \
  -H "Content-Length: 12345" \
  --data-binary @./reference.jpg
```

After uploading is complete, use the `url` returned as the image URL in the model request.

<Warning>
  `upload_url` is a short-lived write address, typically valid for about 15 minutes. `Content-Type` and `Content-Length` must match the ones from the application; do not send `upload_url` to the model, in model requests you should use the returned `url`.
</Warning>

## Practical Example: Local Reference Image for Kling Image-to-Video

Step 1: Upload the local reference image:

```bash cURL
UPLOAD_RESPONSE=$(curl -sS -X POST https://api.crazyrouter.com/v1/files/uploads \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@./portrait.png" \
  -F "purpose=model_input")

IMAGE_URL=$(python -c "import json,sys; print(json.load(sys.stdin)['url'])" <<< "$UPLOAD_RESPONSE")
echo "$IMAGE_URL"
```

Step 2: Submit the returned `IMAGE_URL` to Kling image-to-video:

```bash cURL
curl -X POST https://api.crazyrouter.com/kling/v1/videos/image2video \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d "{
    \"model_name\": \"kling-v3\",
    \"prompt\": \"图片中的人物缓缓转头并微笑，镜头轻微推进，电影级光影\",
    \"image_urls\": [\"$IMAGE_URL\"],
    \"duration\": \"5\",
    \"mode\": \"std\"
  }"
```

Upon successful submission, a task ID will be returned. Retrieve the final video result via [Kling Task Query](/en/video/kling/query).

<Warning>
  The temporary URL is not a permanent asset library. Please ensure the URL has not expired before submitting the task and do not use it as a long-term business image address.
</Warning>
