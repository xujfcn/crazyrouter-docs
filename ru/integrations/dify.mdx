Dify подходит для создания рабочих процессов, агентов, баз знаний и внутренних платформ ИИ-приложений. При интеграции с Crazyrouter рекомендуется сначала использовать путь OpenAI-совместимого поставщика моделей Dify — убедиться в успешной работе модели чата, затем постепенно добавить возможности Embedding и другие.

## Обзор

С помощью настройки поставщика моделей Dify вы можете подключить Crazyrouter как OpenAI-совместимый upstream:

- Рекомендуемый протокол: `OpenAI-compatible API`
- Рекомендуемый вход: `Настройки / Settings` → `Поставщик модели / Model Provider`
- Base URL: `https://api.crazyrouter.com/v1`
- Способ аутентификации: `sk-...` token
- Рекомендуемая модель для первой валидации: `gpt-5.5`

<Tip>
В разных версиях Dify или модульных релизах название поставщика может отображаться как `OpenAI`, `OpenAI-API-compatible`, `OpenAI Compatible` или подобное. Приоритет — выбрать OpenAI-совместимый вход с поддержкой пользовательского `API Base URL`.
</Tip>

<Note>
Официальная документация Dify рассматривает пользовательский `API Base URL` как опциональный для сценариев proxy или совместимых upstream; при интеграции с Crazyrouter следует указать Crazyrouter в качестве такого upstream в `https://api.crazyrouter.com/v1`. Кроме того, настройка поставщика моделей требует прав администратора рабочего пространства или владельца; если не видно входа, проверьте роль текущей учетной записи.
</Note>

## Для кого подходит

- Для тех, кто хочет построить рабочие процессы, агента или приложения базы знаний
- Для команд, которым нужно подключить модели чата и Embedding к Crazyrouter
- Для тех, кто предоставляет бизнес-отделам платформу визуальной оркестрации ИИ
- Для тех, кто хочет разделять тестовые и производственные модели по средам

## Протокол использования

Рекомендованный протокол: `OpenAI-compatible API`

При интеграции Crazyrouter в Dify OpenAI-совместимый базовый адрес обычно указывается как:

```text
https://api.crazyrouter.com/v1
```

Не используйте такие значения:

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

<Tip>
В разных версиях Dify интерфейс может переключаться между `Model Provider`, `Поставщик модели`, `Providers` или входом через маркетплейс плагинов, но путь первой валидации должен оставаться прежним: сначала сохранить поставщика, затем добавить только одну модель `LLM` `gpt-5.5`, и только потом создать минимальное Chat-приложение для проверки.
</Tip>

## Предварительные условия

| Проект | Описание |
|------|------|
| Аккаунт Crazyrouter | Сначала зарегистрируйтесь на [crazyrouter.com](https://crazyrouter.com) |
| Crazyrouter token | Для Dify рекомендуется создать отдельный `sk-...` token |
| Dify | Используйте актуальную стабильную версию; название входа может немного отличаться в разных версиях |
| Доступная модель | Должна быть хотя бы одна проверенная сегодня чат-модель, например `gpt-5.5` |

Рекомендуемые модели для первичного белого списка:

- `gpt-5.5`
- `claude-opus-4-8`
- `text-embedding-3-large`
- `text-embedding-3-small`

Если вы создаёте базу знаний, рекомендуется подготовить как минимум одну чат-модель и одну модель Embedding.

## Быстрый старт за 5 минут

<Steps>
  <Step title="Создать специализированный токен Dify">
    В панели Crazyrouter создайте новый token, в названии лучше указать `dify`. Для первой настройки откройте только `gpt-5.5` и одну модель Embedding, например `text-embedding-3-large`.
  </Step>
  <Step title="Войти в настройки поставщика модели">
    Войдите в Dify с учетной записью, имеющей права управления рабочей зоной, перейдите в `Настройки / Settings` → `Поставщик модели / Model Provider`.
  </Step>
  <Step title="Добавить поставщика, совместимого с OpenAI">
    Выберите вход для поставщика типа `OpenAI` или `OpenAI-compatible` и заполните:
    - `API Key`: ваш `sk-...`
    - `API Base URL`: `https://api.crazyrouter.com/v1`
  </Step>
  <Step title="Сначала настройте только одну модель для чата">
    Для первой настройки добавьте одну LLM, например:
    - `Название модели / Model`: `gpt-5.5`
    - `Тип модели / Type`: `LLM`

    После сохранения создайте самое простое Chat-приложение или Workflow-приложение для проверки. Не добавляйте одновременно чат, embedding, rerank и workflow-инструменты — иначе диагностику будет сложно разделить.
  </Step>
  <Step title="Завершить первую проверку">
    Отправьте в приложении фразу: `Reply only OK`. Если ответ вернулся и в Crazyrouter есть лог, значит канал чата работает. После этого добавляйте embedding и другие модели.
  </Step>
</Steps>

## Рекомендации по Embedding и базе знаний

Если вы используете базу знаний, RAG или поиск по документам в Dify, второй шаг — добавить модель Embedding:

| Назначение | Рекомендуемая модель | Примечание |
|------|----------|------|
| Embedding по умолчанию | `text-embedding-3-large` | Стабильное качество, подходит для начала работы с базой знаний |
| Embedding с низкой стоимостью | `text-embedding-3-small` | Экономно, подходит для больших объемов документов |

Рекомендуемая последовательность:

1. Сначала проверить чат-модель
2. Потом проверить Embedding
3. После этого импортировать базу знаний и настраивать возврат данных

Так диагностику проводить проще.

## Лучшие практики настройки token

| Настройка | Рекомендация | Примечание |
|------|------|------|
| Отдельный token | Обязательно | Не используйте один token для Dify, чат-фронта и CLI |
| Белый список моделей | Очень рекомендуется | Откройте только те модели, которые реально нужны Dify workflow |
| IP-ограничение | Включайте при фиксированной развернутой точке | Для локальной разработки используйте осторожно |
| Лимит квоты | Очень рекомендуется | Workflow, пакетная обработка и импорт базы знаний могут быстро расходовать квоту |
| Разделение сред | Обязательно | Для разработки, теста и творчества используйте разные token |
| Разделение чата / embedding | Рекомендация | В высоконагруженных случаях разбейте на разные token для удобства тарификации и лимитов |

## Чек-лист проверки

- [ ] Crazyrouter настроен и сохранен в `Поставщик модели / Model Provider`
- [ ] `API Base URL` установлен в `https://api.crazyrouter.com/v1`
- [ ] Как минимум одна LLM добавлена успешно
- [ ] Первый запрос от Dify-приложения успешно возвращает ответ
- [ ] В Crazyrouter есть соответствующий лог запроса

- [ ] Для dev, test, prod сред выполнено разделение token

## Частые ошибки и решения

| Проявление | Типичная причина | Решение |
|------|----------|----------|
| Нет входа `Поставщик модели / Model Provider` | Учетная запись не admin или owner рабочего пространства | Используйте аккаунт с правами или попросите admin выполнить настройку |
| Есть вход поставщика, но нет OpenAI-совместимого варианта | В этой версии реализовано как плагин или другое название, либо сначала нужно включить этого поставщика | Ищите входы типа `OpenAI`, `OpenAI Compatible`, `OpenAI-API-compatible`, по необходимости проверяйте настройки плагинов и версии |
| Поставщик не сохраняется | Неверный API Key или выбран неподдерживаемый тип с кастомным Base URL | Выберите OpenAI-совместимый вход и заполните `sk-...` |
| 401 unauthorized | Token истёк, ошибочно скопирован или удален | Сгенерируйте новый token и обновите |
| 403 / model not allowed | Модель, выбранная в Dify, отсутствует в белом списке token | Разрешите модель в панели Crazyrouter |
| 404 | `API Base URL` записан как доменное имя или полный путь | Исправьте на `https://api.crazyrouter.com/v1` |
| Чат-модель настроена, но приложение выдает ошибку | Название модели ошибочно или параметры контекста не подходят | Вернитесь на `gpt-5.5` для проверки основной линии |
| Импорт базы знаний не работает | Чат-модель работает, но embedding не настроен | Сначала проверьте embedding отдельно, после этого повторите импорт |
| Быстрый рост затрат workflow | Пакетная обработка, длинный контекст или несколько приложений используют один token | Разделите token, ограничьте квоту и сократите число моделей |
| Непоследовательное поведение продвинутых моделей в Dify | Совместимость параметров у разных моделей не одинакова | Используйте `gpt-5.5` для проверки линии, после чего постепенно заменяйте модели |

## Рекомендации по производительности и стоимости

- Для workflow по умолчанию протестируйте с `gpt-5.5`, после стабилизации дополняйте другими моделями
- При первом запуске базы знаний — загружайте документы небольшими партиями и проверяйте качество результирующего поиска, после этого переходите к массовому импорту
- Разделяйте учет затрат между чат-моделями и embedding-моделями — так легче анализировать источники расходов
- Для пакетных, периодических задач и внутренней тестовой среды устанавливайте более строгие лимиты квоты
- При высоком расходе сначала в Crazyrouter проверяйте лог — причина может быть в повторных workflow, импорте базы знаний или использовании одного token многими приложениями

## FAQ

### Какой Base URL надо указать в Dify?

Укажите `https://api.crazyrouter.com/v1`.

### Почему не рекомендуется указывать корневой домен?

Потому что OpenAI-совместимые поставщики Dify обычно требуют указания базового адреса OpenAI, а не домена.

### Сначала завести chat-модель или embedding?

Сначала завести chat-модель, убедиться, что приложение возвращает результат, потом добавить embedding.

### Можно сразу подключить модель Rerank?

Зависит от вашей версии Dify и доступных плагинов. Рекомендуется для начала проверить чат и embedding, затем оценить необходимость подключения Rerank отдельно.

### Почему рекомендуется сначала добавить только одну чат-модель?

Потому что ошибки Dify часто бывают одновременно в поставщике, типе модели, параметрах приложения и базе знаний. На первом этапе добавьте только `gpt-5.5` для чата — это облегчит диагностику.

### Нужно ли разбивать token в Dify?

Рекомендуется. Хотя бы разделить dev и prod; при высоком потоке отдельно выделить chat и embedding.

<Note>
Dify лучше всего размещать как "платформа приложений" или "платформа workflow". По сравнению с чат-фронтом, её основная особенность — это оркестрация процессов, работа с базами знаний и управление многими средами, а значит важны отдельный token, белый список моделей и стратегия квот.
</Note>
