Cline — это мощное агентное расширение для кодирования в VS Code, подходящее для чтения и записи файлов, выполнения команд терминала, пошагового планирования и многократного рефакторинга кода. Для интеграции с Crazyrouter рекомендуется официально поддерживаемый провайдер `OpenAI Compatible` от Cline.

## Обзор

С помощью OpenAI Compatible provider для Cline вы можете перенаправлять агентные запросы в Crazyrouter:

- Рекомендуемый протокол: `OpenAI-compatible API`
- Base URL: `https://api.crazyrouter.com/v1`
- Метод аутентификации: `sk-...` token
- Рекомендуемые модели по умолчанию: `claude-opus-4-8` или `gpt-5.5`

<Warning>
Cline может читать/записывать файлы и исполнять команды терминала. После успешного подключения основная угроза — не "смогу ли я подключиться", а "не предоставил ли я чрезмерные права на выполнение". Рекомендуется сначала использовать на маленьких, хорошо знакомых репозиториях.
</Warning>

## Кому подходит

- Тем, кто хочет получить агентный опыт программирования в VS Code
- Тем, кто хочет использовать мульти-модельные возможности Crazyrouter для изменения кода
- Тем, кто хочет разделить статистику потоков между IDE и CLI
- Тем, кто хочет перенаправить модели Claude, GPT и др. через единый шлюз

## Используемый протокол

Рекомендуемый протокол: `OpenAI-compatible API`

В настройках Cline выберите:

- `API Provider`: `OpenAI Compatible`
- `Base URL`: `https://api.crazyrouter.com/v1`
- `API Key`: ваш `sk-...`
- `Model ID`: имя используемой вами модели

Не указывайте Base URL как:

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

<Note>
В отличие от Claude Code, Codex или Aider, стандартное подключение Cline в VS Code обычно не требует ручной прописки переменных окружения. В большинстве случаев достаточно просто заполнить `Base URL`, `API Key` и `Model ID` в настройках Cline.
</Note>

## Полный путь установки по операционным системам

### Рекомендуемый путь для Windows

Наиболее надежный путь для Cline на Windows: `Git` + `VS Code` + `Установить Cline через магазин расширений` + `Просто заполните параметры Crazyrouter в настройках Cline`.

Рекомендуемый порядок:

1. Установите Git
2. Установите VS Code
3. Установите Cline из маркета расширений VS Code
4. Создайте отдельный токен для Cline в Crazyrouter
5. Откройте репозиторий и сделайте снапшот (коммит) в Git
6. В настройках Cline заполните `OpenAI Compatible`, `Base URL`, `API Key`, `Model ID`

Рекомендуемая команда для проверки:

```powershell
git --version
where.exe git
code --version
where.exe code
```

Если `code --version` не найден, но сам VS Code запускается нормально, это не мешает работе Cline; просто вы временно не сможете открывать директорию с помощью `code` напрямую из терминала.

### Рекомендуемый путь для macOS

Наиболее удобный путь для Cline на macOS обычно такой: `Xcode Command Line Tools` + `Homebrew` + `Git` + `VS Code` + `Установить Cline через магазин расширений`.

Рекомендуемый порядок:

1. Установите Xcode Command Line Tools
2. Установите Homebrew (если еще не установлен)
3. Установите Git
4. Установите VS Code
5. Установите Cline в VS Code
6. В настройках Cline напрямую введите параметры Crazyrouter

Команда для проверки:

```bash
git --version
which git
open -a "Visual Studio Code"
```

Если вы хотите запускать `code` прямо из терминала, выполните команду `Shell Command: Install 'code' command in PATH` в командной панели VS Code, затем проверьте:

```bash
code --version
which code
```

### Описание для Linux

Пользователи Linux могут руководствоваться той же логикой, что и для Windows/macOS: сначала установить Git и VS Code, потом через маркет установить расширение Cline. Для Ubuntu/Debian основные команды:

```bash
sudo apt update
sudo apt install -y git
sudo snap install code --classic
git --version
code --version
```

## Полная установка с нуля

<Steps>
  <Step title="Шаг 1: Установите Git">
    Если на компьютере ещё нет Git, сначала установите Git.

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install --id Git.Git -e --source winget
        git --version
        where.exe git
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        xcode-select --install
        git --version
        ```
        Или:
        ```bash
        brew install git
        git --version
        which git
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo apt update
        sudo apt install -y git
        git --version
        which git
        ```
      </Tab>
    </Tabs>

    После установки рекомендуется выполнить:

    ```bash
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
    git config --global init.defaultBranch main
    ```
  </Step>

  <Step title="Шаг 2: Установите VS Code">
    Сейчас наиболее популярный способ использования Cline — это расширение для VS Code.

    <Tabs>
      <Tab title="Windows PowerShell">
        ```powershell
        winget install Microsoft.VisualStudioCode
        code --version
        where.exe code
        ```
      </Tab>
      <Tab title="macOS">
        ```bash
        brew install --cask visual-studio-code
        open -a "Visual Studio Code"
        ```

        Если хотите запускать `code` из терминала, выполните в командной панели VS Code:

        ```text
        Shell Command: Install 'code' command in PATH
        ```

        Затем проверьте:

        ```bash
        code --version
        which code
        ```
      </Tab>
      <Tab title="Ubuntu / Debian">
        ```bash
        sudo snap install code --classic
        code --version
        which code
        ```
      </Tab>
    </Tabs>

    После завершения установки сначала один раз откройте VS Code.
  </Step>

  <Step title="Шаг 3: Установите расширение Cline">
    После открытия VS Code:

    1. Откройте маркет расширений по `Ctrl/Cmd + Shift + X`
    2. Найдите `Cline`
    3. Нажмите «Установить»
    4. После установки нажмите на иконку Cline на боковой панели, либо запустите `Ctrl/Cmd + Shift + P` и затем `Cline: Open In New Tab`

    Если появится окно с предупреждением вроде `Running extensions might...`, выберите «разрешить».

    Если иконка не видна — перезапустите VS Code и проверьте снова.
  </Step>

  <Step title="Шаг 4: Создайте специальный токен Cline в Crazyrouter">
    На сервере Crazyrouter создайте токен с названием `cline`, для начала объявите доступ только к:

    - `claude-opus-4-8`
    - `gpt-5.5`
    - `gemini-3.1-pro`

    <Note>
    Стандартное подключение Cline через интерфейс VS Code подразумевает ввод API Key через интерфейс, а не через переменные окружения, как в Claude Code/Codex. Поэтому важнее всего — выделенный токен и минимальный белый список моделей.
    </Note>
  </Step>

  <Step title="Шаг 5: Подготовьте репозиторий Git и сделайте первый снимок">
    Cline может изменять файлы и исполнять команды. Перед первым подключением рекомендуется сделать снапшот репозитория.

    Если папка еще не под Git:

    ```bash
    git init
    git add .
    git commit -m "chore: initial snapshot before Cline"
    ```

    Если это существующий репозиторий, хотя бы проверьте:

    ```bash
    git status
    ```
  </Step>

  <Step title="Шаг 6: Введите настройки Crazyrouter в Cline">
    После входа в настройки Cline заполните:

    - `API Provider`: `OpenAI Compatible`
    - `Base URL`: `https://api.crazyrouter.com/v1`
    - `API Key`: ваш `sk-...`
    - `Model ID`: введите сначала `claude-opus-4-8`

    Если в версии Cline есть кнопка `Verify`, сначала нажмите на нее и убедитесь, что соединение работает; если нет — для проверки отправьте только чтение-тестовый запрос.

    Для первой проверки используйте одну модель, не переключайтесь между моделями одновременно.
  </Step>

  <Step title="Шаг 7: Завершите первую проверку">
    Для первой проверки выполните действия в этом порядке:

    1. Сначала дайте Cline выполнить только чтение: `Только прочитать текущий рабочий README и подвести итоги, не изменяя никакие файлы`
    2. Затем разрешите ему сделать безопасный анализ: `Укажите 3 файла в этом репозитории, которые стоит проверить в первую очередь`
    3. В конце попробуйте разрешить небольшое изменение: `Изменить только одну очевидную орфографическую ошибку в README и показать diff`

    Если все три шага работают и в журнале запросов Crazyrouter отображаются соответствующие данные — основное соединение установлено.
  </Step>

  <Step title="Шаг 8: Затем постепенно откройте более сильные разрешения">
    Когда задачи только на чтение и небольшие изменения выполняются стабильно, начинайте постепенно:

    1. Изменение нескольких файлов малыми партиями
    2. Позвольте выполнение безопасных команд
    3. Самое последнее — крупные агентные рефакторинги

    Не рекомендуется сразу разрешать Cline выполнять массовые изменения в больших репозиториях.
  </Step>
</Steps>

## Лучшие практики настройки токенов

| Параметр | Рекомендация | Описание |
|----------|--------------|----------|
| Выделенный токен | Обязательно | Не используйте один токен для Cline, Cursor, Claude Code или Aider |
| Белый список моделей | Настоятельно рекомендуется | Cline — высокозатратный инструмент, чем уже список — тем безопаснее |
| Ограничение IP | Включить для фиксированных офисных сетей | Будьте осторожны в мобильных сетях |
| Лимиты | Настоятельно рекомендуется | Многошаговое агентное исполнение быстро исчерпывает лимиты |
| Изоляция окружения | Рекомендуется | Для личного VS Code, удаленного сервера и командных сред используйте отдельные токены |
| Изоляция по разрешениям | Настоятельно рекомендуется | Для критичных репозиториев создайте отдельный токен с меньшим лимитом |

## Типичные ошибки и их исправление

| Явление | Частая причина | Способ исправления |
|------|----------|----------|
| Расширение установлено, но не видно значка Cline | VS Code не обновился или расширение не правильно активировано | Перезапустите VS Code и откройте Cline через командную панель |
| `code` команда недоступна | VS Code установлен, но shell-команда не добавлена в PATH | На Windows попробуйте снова после открытия нового терминала; на macOS выполните `Shell Command: Install 'code' command in PATH` в командной палитре |
| 401 unauthorized | Неправильный, просроченный или ошибочно скопированный API Key | Сгенерируйте новый token и вставьте его заново |
| 403 / model not allowed | token не разрешает текущую модель | Разрешите модель в настройках token Crazyrouter |
| 404 | Base URL указан как корневой домен или путь к конкретному интерфейсу | Измените на `https://api.crazyrouter.com/v1` |
| `model not found` | `Model ID` имя написано неверно или текущая модель недоступна | Верните назад `claude-opus-4-8` или другую разрешённую модель |
| Нет подключения в корпоративной сети | Прокси или firewall блокируют соединение | Сначала проверьте собственные настройки прокси VS Code; расширение Cline использует настройки сетевого прокси из VS Code |
| Запись не тех файлов | Изначально предоставлены слишком большие права записи | Начните с только чтения задач и небольших diff для проверки |
| Стоимость быстро растёт | Многораундовые действия + обширный контекст + автоматическое выполнение | Сужайте задачи и отдельно устанавливайте бюджет для Cline |

## Советы по производительности и экономии

- При первом подключении используйте только задачи для чтения и небольшие изменения
- Для сложной переработки предпочитайте `claude-opus-4-8` или `gpt-5.5`
- Для частых лёгких задач не расширяйте список моделей — ограничьте белый список
- Для разных рабочих пространств и типов проектов используйте разные token
- После каждой большой задачи просматривайте логи Crazyrouter для уточнения реального расхода

## Часто задаваемые вопросы (FAQ)

### Какой Provider выбрать для Cline?

Выберите `OpenAI Compatible`.

### Что указывать в Base URL?

Укажите `https://api.crazyrouter.com/v1`.

### Обязательно ли прописывать переменные среды для данного подключения Cline?

Обычно нет необходимости. Стандартная интеграция с VS Code допускает прямое заполнение `Base URL`, `API Key` и `Model ID` в настройках Cline.

### Почему первое действие — создать Git-снимок?

Поскольку Cline реально читает и пишет файлы, а также выполняет команды. Снимок упрощает review и откат изменений.

### Какую модель рекомендовано выбрать первой?

Используйте сперва `claude-opus-4-8`.

### Почему не стоит сразу предоставлять большие права?

Cline по-настоящему взаимодействует с вашим workspace. Начните с задач только для чтения и небольших изменений — так запуск будет наиболее надёжным.

<Note>
Если вы отдаёте предпочтение интегрированному опыту агента внутри VS Code, Cline лучше подходит в качестве "настоящего кодового агента", чем BYOK-подход Cursor.
</Note>
