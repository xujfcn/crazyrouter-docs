> Обновление содержания: 2026-06-09

Coze (Коуцзы) — платформа ByteDance для ботов и workflow, подходит для бота, оркестрации процессов, вызова плагинов и мультиканального размещения. Для интеграции с Crazyrouter наиболее безопасный и публично документируемый путь — не предполагать, что "все версии поддерживают кастомные модели", а использовать HTTP/API плагин или HTTP-запрос workflow.

## Сразу к выводам

Для большинства пользователей Crazyrouter Coze сейчас рекомендует два подхода:

- Вариант 1: вызвать Crazyrouter через плагин `Создание на основе API`
- Вариант 2: вызвать Crazyrouter через HTTP-запросный узел в workflow

Не стоит публиковать руководство по прямому подключению кастомных моделей Crazyrouter в менеджер моделей Coze, поскольку:

- В разных версиях/регионах/тарифах Coze функционал сильно отличается
- В официальной документации тарифов Coze упоминается, что способность `Пользовательская модель` относится к корпоративному флагманскому варианту
- Поэтому для публичных документов более надёжной основной веткой будет HTTP/API-плагин

<Warning>
Главный принцип точности на этой странице: писать в публичной документации Coze "HTTP/API-плагин вызывает Crazyrouter" — не считать, что все могут сразу подключать кастомные upstream в управлении моделями.
</Warning>

## Кому подходит

- Пользователям, которые хотят интегрировать Crazyrouter в Coze Bot или workflow
- Тем, кто хочет использовать Crazyrouter как внешний вызов модели
- Тем, кто хочет сначала собрать минимально верифицируемую цепочку, а не сразу использовать кастомную корпоративную модель
- Тем, кто хочет, чтобы Bot через плагин или workflow обращался к нескольким моделям

## Рекомендованный способ подключения

### Основная ветка: HTTP/API-плагин

Рекомендуем параметры:

- Метод запроса: `POST`
- URL: `https://api.crazyrouter.com/v1/chat/completions`
- Header:
  - `Authorization: Bearer sk-xxx`
  - `Content-Type: application/json`
- Первая модель для проверки: `gpt-5.5`

### Почему это рекомендуем сначала

Потому что:

- Минимально зависит от различий в тарифах Coze
- Легко понять — "проблема конфигурации Coze" или "проблема Crazyrouter token/model"
- Наиболее стабильно описывать в публичной документации

## Системные требования и условия

| Пункт | Описание |
|------|------|
| Аккаунт Crazyrouter | Предварительно зарегистрируйтесь на [crazyrouter.com](https://crazyrouter.com) |
| Crazyrouter token | Рекомендуется создать отдельный token для Coze |
| Аккаунт Coze | Должен позволять создавать Bot/workflow/plugin |
| Возможность публикации | Как минимум возможность тестировать Bot или workflow |
| Доступные модели | Как минимум разрешите 1 чат-модель |

Рекомендуется начальный whitelist:

- `gpt-5.5`
- `claude-opus-4-8`
- `gemini-3.1-pro`

## Вариант 1: подключение Crazyrouter через API-плагин

<Steps>
  <Step title="Шаг 1: Создайте специальный токен Coze в Crazyrouter">
    Первый раз рекомендуется разрешить только:

    - `gpt-5.5`
    - `claude-opus-4-8`

    Не открывайте много моделей сразу, так легче диагностировать ошибки.
  </Step>

  <Step title="Шаг 2: Создайте API-плагин в Coze">
    После входа в рабочий стол Coze, переходите к:

    - `Плагин`
    - `Создать плагин`
    - Выберите `Создание на основе API` или похожее название

    <Note>
    Названия элементов интерфейса Coze могут варьироваться в зависимости от версии/региона/продуктовой линии, но принцип одинаковый: создать внешний HTTP API плагин.
    </Note>
  </Step>

  <Step title="Шаг 3: Настройте метод запроса и URL">
    Заполните:

    - `Method`: `POST`
    - `URL`: `https://api.crazyrouter.com/v1/chat/completions`
  </Step>

  <Step title="Шаг 4: Настройте заголовки запроса">
    Заполните:

    ```text
    Authorization: Bearer sk-xxx
    Content-Type: application/json
    ```
  </Step>

  <Step title="Шаг 5: Настройте минимальное тело запроса">
    Сначала используйте минимальное тело запроса:

    ```json
    {
      "model": "gpt-5.5",
      "messages": [
        {
          "role": "user",
          "content": "{{input}}"
        }
      ]
    }
    ```

    Если в интерфейсе плагина доступны сопоставление параметров, можно назначить ввод пользователя на такие placeholder переменные, как `{{input}}`.
  </Step>

  <Step title="Шаг 6: Сначала выполните проверку соединения в плагине">
    Если текущая версия поддерживает тестирование плагинов, передайте одну строку:

    ```text
    Reply only OK
    ```

    Убедитесь, что интерфейс стабильно возвращает ответ. После этого добавляйте плагин в Bot или workflow.
  </Step>

  <Step title="Шаг 7: Вызовите плагин в боте или в рабочем процессе">
    Когда плагин прошёл самостоятельную проверку, добавьте его:

    - К Bot как плагин
    - Или к workflow как узел

    В первый раз пусть плагин решает одну простую задачу, например, реферат, переписывание или фиксированный вопрос-ответ.
  </Step>
</Steps>

## Вариант 2: подключение Crazyrouter через HTTP-запрос workflow

Если не хотите обслуживать отдельный плагин, можно вызывать HTTP-запрос непосредственно из workflow.

### Рекомендуемые настройки

- Метод запроса: `POST`
- URL: `https://api.crazyrouter.com/v1/chat/completions`
- Headers:
  - `Authorization: Bearer sk-xxx`
  - `Content-Type: application/json`
- Body:

```json
{
  "model": "gpt-5.5",
  "messages": [
    {
      "role": "user",
      "content": "{{input}}"
    }
  ]
}
```

### Рекомендованная последовательность проверки

1. Сначала передайте фиксированную строку `Reply only OK` в узел
2. Затем меняйте на переменный ввод
3. В конце сопоставьте вывод с последующими workflow-узлами

## Как относиться к "интеграции кастомной модели"

Некоторые версии или тарифы Coze действительно поддерживают подключение кастомных моделей — но это не должно быть основной линией публичной документации Crazyrouter.

Причины:

- В FAQ официальных тарифов Coze функция `Пользовательская модель` относится к корпоративному флагманскому пакету
- Для большинства обычных пользователей наиболее публично воспроизводимый и лёгкий путь — HTTP/API-плагин
- Поэтому кастомные модели здесь только фон — не основное руководство

## Рекомендуемые модели для конфигурации

| Сценарий | Рекомендуемая модель | Обоснование |
|----------|----------|------|
| Первая проверка цепочки | `gpt-5.5` | 23 марта 2026 успешный прод-тест; лучше всего для проверки связки Coze -> Crazyrouter |
| Качественный вывод | `claude-opus-4-8` | Подходит для сильного объяснения и генерации контента |
| Gemini резерв | `gemini-3.1-pro` | Вторая резервная совместимая цепочка |

## Лучшие практики настройки token

| Настройка | Рекомендация | Описание |
|------|------|------|
| Специализированный token | Обязательно | Coze не должен использовать token совместно с десктоп-клиентом или IDE |
| Whitelist моделей | Очень рекомендуется | Сначала разрешайте 1-2 модели |
| Лимит квоты | Очень рекомендуется | workflow-циклы, повторные вызовы плагинов расходуют quota |
| Изоляция по окружениям | Рекомендуется | dev/test/prod — разные token |
| Лечение утечек | Немедленная замена | Если плагин и workspace "утекли", сразу меняйте ключ |

## Чек-лист проверки

- [ ] Создан отдельный Crazyrouter token для Coze
- [ ] Выбрана HTTP/API-плагин или workflow HTTP-запросная линия
- [ ] В URL запроса установлен `https://api.crazyrouter.com/v1/chat/completions`
- [ ] Заголовок `Authorization` правильно заполнен `Bearer sk-xxx`
- [ ] `Content-Type` — установлен `application/json`
- [ ] Минимальное тело запроса успешно проверено через `gpt-5.5`
- [ ] Плагин или workflow node успешно протестированы по отдельности
- [ ] После подключения к Bot/workflow также успешно работают
- [ ] В логах Crazyrouter видны соответствующие запросы

## Частые ошибки и решения

| Симптом | Возможная причина | Решение |
|------|----------|----------|
| 401 unauthorized | Token неверный, истёк или некорректно скопирован | Сгенерируйте новый token и снова впишите в заголовок `Authorization` |
| 404 | Неправильный URL или отсутствует `/v1/chat/completions` | Используйте полный URL |
| 403 / model not allowed | Token не разрешил текущую модель | Разрешите модель в настройках Crazyrouter token |
| `model not found` | Неправильное имя модели | Сначала проверьте с `gpt-5.5` |
| Плагин можно создать, но Bot не вызывает | Несовпадение input/output в плагине | Для проверки используйте фиксированную строку |
| Сбой workflow узла | Длинный input, слишком много retry или высокая concurrency | Сначала уменьшите input и упростите задачу |
| В чужом руководстве нет "менеджера моделей" | Версия или тариф другой | Возвращайтесь к HTTP/API-плагину, не используйте корпоративные функции сразу |

## FAQ

### Какой вариант подключения Crazyrouter в Coze самый рекомендованный?

В публичной документации рекомендуем HTTP/API-плагин или HTTP-запрос workflow.

### Почему не делать кастомные модели основной веткой?

Поскольку функционал Coze очень зависит от версии и тарифа, а FAQ официальных тарифов относит `Пользовательская модель` к корпоративным опциям. Для публичной документации лучше воспроизводимая и более простая HTTP-ветка.

### Какой URL указывается?

`https://api.crazyrouter.com/v1/chat/completions`.

### С чего начинать — какая модель?

`gpt-5.5`.

### Когда расширять whitelist и подключать Claude/другие модели?

Пройдите минимум: одна модель, один workflow node, одна задача, затем постепенно расширяйте whitelist.

<Note>
Если ваша цель — "чтобы Coze стабильно вызывал Crazyrouter", важно не усложнять конфигурацию, а сначала провести минимальную проверку через HTTP/API-плагин.
</Note>
