> Обновление содержания: 2026-06-09

Codex CLI — это терминальный агент программирования от OpenAI, который подходит для внесения изменений в локальный репозиторий, ревью кода, массового рефакторинга и командной работы с кодом. Для подключения Crazyrouter рекомендуется использовать официальный поддерживаемый способ через кастомный провайдер `config.toml` вместо устаревшей схемы конфигурации.

## Обзор

С помощью настройки `~/.codex/config.toml` кастомного провайдера Codex CLI может отправлять запросы на Crazyrouter:

- Рекомендуемый протокол: `OpenAI-compatible API`
- Тип используемого API: `Responses API`
- Базовый URL: `https://api.crazyrouter.com/v1`
- Переменные для авторизации: `OPENAI_API_KEY`
- Рекомендуемая модель по умолчанию: `gpt-5.5`

<Tip>
Если вы раньше использовали только вход через ChatGPT, при подключении Crazyrouter перейдите на конфигурацию с API-ключом и кастомным провайдером. Так вы сможете лучше контролировать модель, логи, лимиты и оплату.
</Tip>

## Для кого подходит

- Для тех, кто хочет добавить Crazyrouter в терминальный агент разработки кода
- Для тех, кто хочет делать массовые изменения, автоматизированное ревью и запускать задачи в локальном репозитории
- Для тех, кто желает раздельно учитывать трафик Codex, Cursor, Claude Code
- Для тех, кто хочет использовать проверенные и актуальные модели OpenAI для терминального программирования

## Протоколы работы

Рекомендуемый протокол: `OpenAI-compatible API`

На данный момент Codex CLI рекомендует использовать OpenAI-совместимый провайдер через кастомный `model_provider` с явной настройкой:

- `base_url = "https://api.crazyrouter.com/v1"`
- `wire_api = "responses"`

<Note>
Crazyrouter поддерживает `/v1/responses`, поэтому интеграция Codex CLI может напрямую работать с Responses API. Однако эта схема работает только с моделями GPT, Claude не поддерживает `POST /v1/responses`.
</Note>

## Полная установка по операционным системам

### Рекомендуемый путь для Windows

Самый простой способ начать работу на Windows: `Git` + `Node.js` + `Глобальная установка Codex через npm` + `PowerShell: настройка переменной среды`.

Рекомендуемая последовательность:

1. Установите Git
2. Установите Node.js LTS
3. Установите Codex CLI через npm
4. Запишите `OPENAI_API_KEY` через PowerShell
5. Запишите `$HOME/.codex/config.toml` через PowerShell

Рекомендуемая команда для проверки:

```powershell
git --version
node -v
npm -v
codex --version
where.exe git
where.exe node
where.exe codex
```

Если `codex --version` сообщает, что команда не найдена, сначала закройте и снова откройте PowerShell, затем повторите попытку.

### Рекомендуемый путь для macOS

На macOS удобнее всего: `Homebrew` + `Git` + `Node.js` + `brew` или `npm` для установки Codex CLI + `~/.zshrc` для сохранения переменных окружения.

Рекомендуемая последовательность:

1. Установите Xcode Command Line Tools
2. Установите Homebrew (если его нет)
3. Установите Git и Node.js
4. Установите Codex CLI
5. Запишите `~/.zshrc`
6. Запишите `~/.codex/config.toml`

Рекомендуемая команда для проверки:

```bash
git --version
node -v
npm -v
codex --version
which git
which node
which codex
```

### Альтернативные пути установки Codex CLI

Помимо менеджеров пакетов, официальный репозиторий Codex также публикует бинарники в GitHub Releases. Но большинству пользователей по-прежнему рекомендуется:

- Для Windows: `npm install -g @openai/codex`
- Для macOS: `brew install --cask codex` или `npm install -g @openai/codex`

Если вам удобно автоматически записывать все настройки Crazyrouter скриптами, обратитесь к [crazyrouter-codex-cli](https://github.com/xujfcn/crazyrouter-codex-cli). Там есть автоскрипты для Windows, macOS и Linux; здесь же изложен полный ручной путь, чтобы вы могли проверить каждую настройку самостоятельно.

## Рекомендуемые модели

| Сценарий применения | Рекомендованная модель | Причина |
|----------|----------|------|
| Основная программная работа | `gpt-5.5` | В промышленной среде подтверждена работа на 23 марта 2026 года, отличная база для Codex / Responses API |

Если вам нужен Claude, пользуйтесь нативным `POST /v1/messages` либо OpenAI-совместимым `POST /v1/chat/completions`, не указывайте Claude в маршруте `wire_api = "responses"` для Codex.

### Поддержка отечественных моделей

По результатам проверки `2026-05-15`, на Crazyrouter через **родной `POST /v1/responses`** и успешно используемые в Codex CLI отечественные модели на данный момент можно публично рекомендовать только следующие:

| Модель | Вывод | Описание |
|------|----------|------|
| `kimi-k2.5` | Рекомендуется | `/v1/responses` SSE полностью поддерживает вывод `response.completed`, Codex корректно отвечает и читает файлы |
| `kimi-k2.6` | Рекомендуется | Равнозначна `kimi-k2.5`, может быть основной отечественной моделью |
| `MiniMax-M2.7` | Пока не рекомендуется | Минимальный probe по Responses даёт `convert_request_failed`, задачи на чтение файлов прерываются до `response.completed` |
| `deepseek-v4-pro` | Пока не рекомендуется | Claude Code работает, но по Responses для Codex вновь могут быть ошибки 500, лимиты, проблемы с восстановлением |
| `glm-5.1` | Пока не рекомендуется | В продакшене Responses не поддерживает эту модель, Codex выдаёт `stream closed before response.completed` |

Если хотите попробовать отечественные модели в Codex, сначала урежьте белый список токена до:

- `gpt-5.5`
- `kimi-k2.5`
- `kimi-k2.6`

Не включайте `MiniMax-M2.7`, `deepseek-v4-pro`, `glm-5.1` в дефолтный белый список Codex, если вы не согласны на экспериментальные функции и возможные сбои.

### Переключение на отечественную модель

Сохраняйте `base_url = "https://api.crazyrouter.com/v1"` и `wire_api = "responses"` — меняйте только поле `model`. Пример:

```toml
model = "kimi-k2.5"
model_provider = "crazyrouter"

[model_providers.crazyrouter]
name = "Crazyrouter"
base_url = "https://api.crazyrouter.com/v1"
env_key = "OPENAI_API_KEY"
wire_api = "responses"

[profiles.crazyrouter]
model = "kimi-k2.5"
model_provider = "crazyrouter"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

При первом переключении на отечественную модель рекомендуется по-прежнему проверять в следующем порядке:

1. `Reply only OK`
2. `Read the repository structure only. Do not edit files.`
3. `Read agent.md and reply with exactly the first Markdown heading text.`

## Рекомендации по настройке Token

| Настройка         | Рекомендация         | Описание |
|-------------------|---------------------|----------|
| Специальный token | Обязательно         | Codex не должен использовать один token с Cursor, Claude Code |
| Белый список моделей | Настоятельно рекомендуется | Разрешайте только те модели, которые действительно будут вызываться Codex |
| Ограничение IP    | В фиксированной среде рекомендуется включить | Будьте осторожны, если используете устройство, часто меняющее сеть |
| Лимит квоты       | Настоятельно рекомендуется | При проксировании Codex лимит быстро расходуется |
| Изоляция среды    | Рекомендуется        | Используйте разные token для локальной разработки, удалённого сервера и CI |
| Реагирование на утечку | Моментально сменить | При попадании token в историю shell, бэкап конфигов или на общий экран немедленно меняйте его |

## Типичные ошибки и способы их исправления

| Симптом | Причина | Решение |
|---------|---------|---------|
| `codex: command not found` | CLI не установлен или глобальная папка npm не в PATH | Переустановите Codex и убедитесь, что глобальный bin npm добавлен в PATH |
| 401 unauthorized | Ошибка `OPENAI_API_KEY`, token просрочен или скопирован с пробелом | Создайте новый token и настройте переменные окружения снова |
| 403 / model not allowed | Token не разрешает работу с данной моделью | Разрешите нужную модель в настройках tokens Crazyrouter |
| 404 | Ошибка в `base_url` или пропущен `/v1` | Исправьте на `https://api.crazyrouter.com/v1` |
| Ошибка структуры запроса | `wire_api` не является `responses` | Исправьте на `wire_api = "responses"` |
| CLI запускается, но запросы не проходят через Crazyrouter | `model_provider` не переключился на `crazyrouter` | Проверьте настройки provider для `config.toml` |
| Сложно ревьюить изменения в Git | Не сделан снимок репозитория до изменений | Сначала зафиксируйте снимок до правок, затем вносите реальные изменения с Codex |
| Слишком быстрый рост расходов | Длинный контекст, многоцикловое использование инструментов или один token на несколько репозиториев | Разделите token, установите лимиты и сузьте белый список моделей |

## Рекомендации по производительности и расходам

- Для первого запуска используйте небольшой репозиторий, не запускайте сразу полные задачи на крупном репозитории
- В качестве основного варианта сначала рекомендуйте `gpt-5.5`, проведите основную цепочку GPT / Responses
- Разделяйте учёт расходов Codex и IDE-инструментов для выявления источников большого потребления
- Для рисковых репозиториев или CI-сценариев делайте более строгие лимиты по token
- При обнаружении аномально высокого потребления сначала проверьте логи Crazyrouter — не вызвано ли это повторной проксирующей логикой

## FAQ

### Какой Base URL указывать для Codex CLI?

Указывайте `https://api.crazyrouter.com/v1`.

### В Windows рекомендуется использовать PowerShell или Git Bash?

При первой настройке сначала следуйте инструкции для PowerShell — это проще всего для согласованности с пользовательскими переменными окружения и `$HOME/.codex/config.toml`.

### Почему здесь нужно настраивать `wire_api = "responses"`?

Потому что в Codex CLI текущий кастомный provider рекомендуется подключать через Responses API, а Crazyrouter поддерживает `/v1/responses`.

### Почему Claude здесь больше не рекомендуется?

Потому что Claude поддерживает только `POST /v1/messages` и `POST /v1/chat/completions`, но не поддерживает `POST /v1/responses`. Codex всегда работает через `wire_api = "responses"`, поэтому не стоит рекомендовать Claude как модель для этой интеграции.

### Почему в первый раз рекомендуется сделать снимок Git?

Потому что Codex — это агент, меняющий файлы и выполняющий команды. Снимок упростит review и откат изменений.

### Если я уже `codex login`, нужно ли отдельно настраивать API Key?

Да, нужно. Для интеграции с Crazyrouter по-прежнему требуются `OPENAI_API_KEY` и кастомный provider.

### Какую модель рекомендуется указывать первой?

Сначала используйте `gpt-5.5`.
