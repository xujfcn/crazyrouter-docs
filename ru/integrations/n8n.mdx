n8n отлично подходит для интеграции вызовов LLM в автоматические процессы, узлы Agent, approval-flows и бизнес-системы. При интеграции Crazyrouter рекомендуется сначала использовать путь учетных данных OpenAI в n8n для запуска минимального рабочего процесса, а затем решать, переходить ли к более гибкому узлу HTTP Request.

## Обзор

Благодаря учетным данным OpenAI или AI-узлам в n8n вы можете перенаправлять запросы моделей в рабочем процессе на Crazyrouter:

- Рекомендуемый протокол: `OpenAI-compatible API`
- Рекомендуемый способ подключения: n8n `OpenAI API` учетные данные + настройка на уровне узла `Base URL`
- Base URL: `https://api.crazyrouter.com/v1`
- Способ аутентификации: `sk-...` token
- Рекомендованная модель для первой проверки: `gpt-5.5`

Если какие-то узлы не поддерживают необходимые параметры или новые функции моделей, используйте fallback к узлу `HTTP Request` для прямых вызовов Crazyrouter.

## Кому подойдет

- Тем, кто хочет интегрировать ИИ в автоматические рабочие процессы
- Тем, кто хочет связать формы, базы данных, approval-flow, webhook и модели
- Тем, кто хочет вызывать через инструменты оркестровки AI Agent
- Тем, кто хочет визуально интегрировать Crazyrouter во внутренние бизнес-процессы

## Используемый протокол

Рекомендуемый протокол: `OpenAI-compatible API`

При интеграции Crazyrouter в n8n, рекомендуется указать:

```text
https://api.crazyrouter.com/v1
```

Не указывайте:

- `https://api.crazyrouter.com`
- `https://api.crazyrouter.com/v1/chat/completions`

## Предварительные условия

| Компонент | Описание |
|------|------|
| Аккаунт Crazyrouter | Сначала зарегистрируйтесь на [crazyrouter.com](https://crazyrouter.com) |
| Crazyrouter token | Рекомендуется создать отдельный `sk-...` token для n8n |
| n8n | Желательно использовать текущую стабильную версию и убедиться, что AI-узлы доступны |
| Доступные модели | Минимум одна из актуально работающих в этот день моделей чата, например, `gpt-5.5` |

Список рекомендованных для белого списка (на первый запуск):

- `gpt-5.5`
- `claude-opus-4-8`

- `text-embedding-3-large` (если вы работаете с векторными или поисковыми узлами)

## Быстрый старт за 5 минут

<Steps>
  <Step title="Создать специализированный токен для n8n">
    В админ панели Crazyrouter создайте токен с названием `n8n`. Для первого раза откройте только `gpt-5.5` и `claude-opus-4-8`.
  </Step>
  <Step title="Добавить учетные данные OpenAI">
    В n8n перейдите в `Settings` → `Credentials` → `Add Credential`, выберите `OpenAI API` или соответствующий вашему релизу тип учетной записи OpenAI.
  </Step>
  <Step title="Заполнить информацию о учетных данных и узле">
    Сначала укажите в учетных данных:
    - `API Key`: ваш `sk-...`

    Затем в `OpenAI`, `OpenAI Chat Model` или настройках модели в соответствующем AI-узле `Options` установите:
    - `Base URL`: `https://api.crazyrouter.com/v1`
  </Step>
  <Step title="Создать минимальный рабочий процесс">
    Создайте новый workflow, используйте: `Manual Trigger` → `OpenAI Chat Model` → `Output`, модель заполните как `gpt-5.5`.
  </Step>
  <Step title="Завершить первую проверку">
    В узле `OpenAI Chat Model` задайте простой вход, например, `Reply only OK`, выполните вручную рабочий процесс. После успешного ответа переходите к настройке AI Agent или более сложных цепочек.
  </Step>
</Steps>

## Пример минимального рабочего процесса

### Узел OpenAI Chat Model

```json
{
  "node": "OpenAI Chat Model",
  "parameters": {
    "model": "gpt-5.5",
    "messages": [
      { "role": "user", "content": "{{ $json.input }}" }
    ]
  }
}
```

### Workflow AI Agent

Рекомендуется начать с самой простой схемы:

1. `Manual Trigger`
2. `AI Agent`
3. `Output`

В `AI Agent` выберите только что созданные учетные данные Crazyrouter и временно добавьте только один простой узел-инструмент, чтобы не смешивать проблемы модели и инструмента.

## Fallback-схема HTTP Request

Если вам нужно:

- Какой-либо AI-узел в n8n временно не поддерживает новые параметры
- Необходим гибкий контроль тела запроса
- Требуется более явная отладка headers, body, параметра stream

Можно напрямую вызывать Crazyrouter через узел `HTTP Request`:

```http
Method: POST
URL: https://api.crazyrouter.com/v1/chat/completions
Headers:
  Authorization: Bearer sk-xxx
  Content-Type: application/json
Body:
  {
    "model": "gpt-5.5",
    "messages": [
      {"role": "user", "content": "{{ $json.input }}"}
    ]
  }
```

<Tip>
Рекомендуемый порядок: сначала проходите процесс с OpenAI credentials + нативным AI-узлом. Только если пропускной способности узлов не хватает, переходите на `HTTP Request`.
</Tip>

<Note>
В разных версиях n8n поле `Base URL` может быть либо на странице credentials, либо на самом AI/Chat Model узле `Options`. В текущей официальной документации подчёркнуто наличие параметра `Base URL` на уровне узла, поэтому для Crazyrouter сначала придерживайтесь схемы "в credentials — ключ, в узле — Base URL".
</Note>

## Рекомендуемые настройки моделей

| Сценарий использования | Рекомендуемая модель | Причина |
|----------|----------|------|
| Модель для workflow по умолчанию | `gpt-5.5` | В этот день реально протестирована, подходит как основная линия в n8n |
| Сложные Agent-сценарии высокого качества | `claude-opus-4-8` | Лучше для сложной интерпретации и длинных текстов |
| Запасной для Gemini | `gemini-3.1-pro` | Удобно как вторая трасса проверки совместимости |
| Поиск/Векторные операции | `text-embedding-3-large` | В дальнейшем удобно для векторной работы или поиска |

Рекомендуемый порядок: сначала пройти минимальный workflow с `gpt-5.5`, потом масштабировать Agent, инструменты и массовые задачи.

## Лучшие практики настройки token

| Настройка | Совет | Описание |
|------|------|------|
| Отдельный token | Обязательно | Не используйте один и тот же token для n8n, чат-фронта, CLI или SDK |
| Белый список моделей | Настоятельно рекомендуется | Оставляйте только те модели, которые нужны workflow |
| Ограничение по IP | Рекомендуется для фиксированного серверного выхода | Будьте осторожны при локальной отладке или миксе облака и локали |
| Ограничение квоты | Настоятельно рекомендуется | Авто задачи могут быстро “сьедать” лимит из-за ретраев, циклов, массовой обработки |
| Изоляция окружения | Обязательно | Для разработки, теста и продакшена используйте разные token |
| Разделение по узлам | Рекомендуется | Для частых задач дешевле модели, для критичных — более производительные |

## Чек-лист для проверки

- [ ] Узел `OpenAI Chat Model` успешно запускается
- [ ] Минимальный рабочий процесс выполнен успешно
- [ ] Если нужен Agent, узел `AI Agent` также умеет вызывать модель

- [ ] Для разработки/теста/продакшена токены разделены

## Частые ошибки и решения

| Симптом | Частая причина | Способ исправления |
|------|----------|----------|
| Ошибка при проверке credentials | Неверный API Key или Base URL в неверном поле | Перепроверьте `sk-...` и убедитесь, что `Base URL` заполнено в подходящем поле вашей версии |
| 401 unauthorized | token недействителен, удален или скопирован с пробелом | Сгенерируйте токен заново и замените |
| 403 / model not allowed | Модель не в белом списке Crazyrouter | Добавьте нужную модель в админ-панели Crazyrouter |
| 404 | `Base URL` задан как root domain либо полный путь | Исправьте на `https://api.crazyrouter.com/v1` |
| Workflow непрерывно повторяется, расходы быстро растут | Ошибка в узле приводит к автоматическому повтору, некорректная настройка цикла | Ограничьте число попыток, разбейте workflow и установите лимиты |
| AI Agent стартует, но инструмент вызывает ошибки | Дело не в credentials, а в сложной цепи инструментов | Для отладки временно оставьте только один простой инструмент |
| Не хватает параметров в AI-узле | Оболочка узла n8n пока не покрывает фичу | Используйте узел `HTTP Request` для прямого вызова Crazyrouter |
| Нестабильная производительность при пакетной обработке | Модель и коннектор не сочетаются | Сначала проверьте минимальный цепочку на `gpt-5.5`, затем переходите к остальным моделям |

## Советы по производительности и затратам

- Для автоматизации по умолчанию используйте `gpt-5.5` как baseline
- Для циклов, массовых и регулярных задач задайте строгие лимиты и уведомления об ошибках
- Разделяйте токены для продакшена и отладки
- В AI Agent сначала тестируйте с меньшим количеством инструментов и короткой цепочкой, затем усложняйте
- При резком увеличении расходов проверьте сначала логи Crazyrouter и историю запусков n8n — возможно дело в ретраях/циклах

## FAQ

### Какой Base URL нужно указывать в n8n?

Укажите `https://api.crazyrouter.com/v1`.

### Base URL добавлять в credentials или прямо в узле?

Ориентируйтесь на актуальную версию интерфейса n8n. В официальной документации рекомендуется опция `Base URL` на уровне узла; если в credentials есть соответствующее поле, допускается заполнение там, но первый раз лучше прописать на уровне узла.

### Что выбрать: нативный AI-узел или HTTP Request?

Сначала используйте родные credentials OpenAI и AI-узлы; переходите на `HTTP Request` только если не хватает параметров или нужна глубокая отладка.

### Какую первую модель выбрать?

Используйте `gpt-5.5`.

### Почему резко выросли расходы workflow?

Обычно виноваты не разовые запросы, а циклы, массовая обработка, автоматические повторы или workflow, которые запускает сразу несколько человек.

### Нужно ли обязательно создавать отдельные token под каждый сценарий?

Настоятельно рекомендуется отделять по крайней мере разработку и production; для частых задач желательно дополнительно выделить отдельные.

<Note>
После подключения Crazyrouter в n8n ценность не только в том, что модель запускается, а в том, что она интегрируется в сквозные автоматизированные цепочки. Поэтому критично не столько разово получить ответ, сколько правильно настроить ретраи, циклы, массовое выполнение и квоты по token.
</Note>
