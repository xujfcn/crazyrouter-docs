> Обновление содержания: 2026-06-09

LangChain — один из самых популярных фреймворков для разработки приложений с LLM. Он отлично подходит для чат-интерфейсов, цепочек подсказок, вызова инструментов, RAG, рабочих процессов с агентами и программного оркестрирования. Самый надёжный способ интеграции Crazyrouter — через компонент OpenAI, поддерживаемый официально в LangChain.

## Обзор

Используя компонент OpenAI в LangChain, вы можете отправлять запросы в Crazyrouter:

- Рекомендуемый протокол: `OpenAI-compatible API`
- Base URL: `https://api.crazyrouter.com/v1`
- Переменная аутентификации: `OPENAI_API_KEY`
- Основной пакет для Python: `langchain-openai`
- Основной пакет для JavaScript / TypeScript: `@langchain/openai`

<Tip>
Если вы планируете интегрировать Crazyrouter непосредственно в свой код приложения, а не только использовать его для общения в настольном клиенте, LangChain обычно является самым естественным путём для инженерной интеграции.
</Tip>

## Кому подходит

- Разработчики, которые хотят официально интегрировать Crazyrouter в проекты Python или Node.js
- Те, кто создаёт цепочки подсказок, RAG, вызов инструментов, оркестрацию рабочих процессов
- Тех, кто хочет унифицировать логику вызова моделей и не писать HTTP запросы вручную
- Тех, кто хочет сохранить гибкость смены моделей или провайдера в будущем

## Протокол использования

Рекомендуемый протокол: `OpenAI-compatible API`

Основные настройки Crazyrouter:

```text
OPENAI_API_KEY=sk-xxx
BASE_URL=https://api.crazyrouter.com/v1
```

В LangChain внедрение обычно выглядит так:

- Python: `api_key` + `base_url`
- JavaScript / TypeScript: `apiKey` + `configuration.baseURL`

## Системные требования и предпосылки

| Проект | Описание |
|-------|----------|
| Аккаунт Crazyrouter | Сначала зарегистрируйтесь на [crazyrouter.com](https://crazyrouter.com) |
| Crazyrouter token | Рекомендуется создать отдельный token для LangChain-проекта |
| Python | Рекомендуется `Python 3.10+` |
| Node.js | Рекомендуется `Node.js 18+` |
| Пакет LangChain | Для Python — `langchain-openai`; для JS / TS — `@langchain/openai` |

- `gpt-5.5`
- `claude-opus-4-8`

## Полная настройка с нуля

<Steps>
  <Step title="Шаг 1: Создайте специальный токен LangChain в Crazyrouter">
    В первый раз рекомендуется разрешить:

    - `gpt-5.5`
    - `claude-opus-4-8`
    - `text-embedding-3-large`

    Если потребуется больше моделей позже, расширяйте по необходимости, но сначала используйте минимальный белый список.
  </Step>

  <Step title="Шаг 2: Сначала установите переменные среды">
    <Tabs>
      <Tab title="macOS / Linux">

      </Tab>

        ```powershell
        $env:OPENAI_API_KEY = "sk-xxx"
        echo $env:OPENAI_API_KEY
        ```
      </Tab>
    </Tabs>

    Если планируете длительную разработку, сделайте персистентность:

    <Tabs>
      <Tab title="Linux Bash">

        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.bashrc
        source ~/.bashrc
        ```

      </Tab>
      <Tab title="macOS / Zsh">
        ```bash
        echo 'export OPENAI_API_KEY=sk-xxx' >> ~/.zshrc
        source ~/.zshrc
        ```
      </Tab>
      <Tab title="Windows PowerShell">
        ```powershell
        [System.Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "sk-xxx", "User")
        $env:OPENAI_API_KEY = "sk-xxx"
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Шаг 3: Завершите минимальную проверку чата на Python">
    Создайте `test_langchain_chat.py`:

    ```python

    llm = ChatOpenAI(
        model="gpt-5.5",
        api_key="sk-xxx",
        base_url="https://api.crazyrouter.com/v1",
        temperature=0,
    )

    response = llm.invoke("Reply only OK")
    print(response.content)
    ```

    Запустите:

    ```bash
    python test_langchain_chat.py
    ```
  </Step>

  <Step title="Шаг 4: Измените на версию с переменными среды">
    После успешного запуска не храните ключ жёстко в коде:

    ```python
    import os
    from langchain_openai import ChatOpenAI

    llm = ChatOpenAI(
        model="gpt-5.5",
        api_key=os.environ["OPENAI_API_KEY"],
        base_url="https://api.crazyrouter.com/v1",
        temperature=0,
    )
    ```
  </Step>

  <Step title="Шаг 5: Завершите минимальную проверку чата на JavaScript / TypeScript">
    Создайте `test-langchain-chat.mjs`:

    ```javascript
    import { ChatOpenAI } from "@langchain/openai";

    const llm = new ChatOpenAI({
      model: "gpt-5.5",
      apiKey: process.env.OPENAI_API_KEY,
      configuration: {
        baseURL: "https://api.crazyrouter.com/v1",
      },
      temperature: 0,
    });

    const response = await llm.invoke("Reply only OK");
    console.log(response.content);
    ```

    Запустите:

    ```bash
    node test-langchain-chat.mjs
    ```
  </Step>

  <Step title="Шаг 6: Затем постепенно добавьте Embeddings, Prompt, RAG">
    Не стоит сразу подключать сложные цепочки. Рекомендуемая последовательность:

    1. Сначала запуск одиночного чата
    2. Затем Prompt + Output Parser
    3. Далее подключайте Embeddings
    4. В конце реализуйте RAG или Agent
  </Step>
</Steps>

## Пример Python

### Минимальный пример чата

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="gpt-5.5",
    api_key="sk-xxx",
    base_url="https://api.crazyrouter.com/v1",
    temperature=0.7,
)

response = llm.invoke("什么是 LangChain？")
print(response.content)
```

### Пример Embeddings

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-large",
    api_key="sk-xxx",
    base_url="https://api.crazyrouter.com/v1",
)

vectors = embeddings.embed_documents(["文本一", "文本二"])
print(len(vectors), len(vectors[0]))
```

### Пример цепочки подсказок

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatOpenAI(
    model="gpt-5.5",
    api_key="sk-xxx",
    base_url="https://api.crazyrouter.com/v1",
)

prompt = ChatPromptTemplate.from_template("用简单的语言解释 {topic}")
chain = prompt | llm | StrOutputParser()

result = chain.invoke({"topic": "量子计算"})
print(result)
```

### Минимальный пример RAG

```python
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough

llm = ChatOpenAI(
    model="gpt-5.5",
    api_key="sk-xxx",
    base_url="https://api.crazyrouter.com/v1",
)

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-large",
    api_key="sk-xxx",
    base_url="https://api.crazyrouter.com/v1",
)

texts = [
    "Crazyrouter 支持多种 AI 模型协议",
    "Crazyrouter 支持 OpenAI 兼容调用方式",
]

vectorstore = FAISS.from_texts(texts, embeddings)
retriever = vectorstore.as_retriever()

prompt = ChatPromptTemplate.from_template(
    "根据以下上下文回答问题：\n{context}\n\n问题：{question}"
)

chain = {"context": retriever, "question": RunnablePassthrough()} | prompt | llm

result = chain.invoke("Crazyrouter 适合用什么协议接 LangChain？")
print(result.content)
```

## Рекомендуемые настройки моделей

| Сценарий использования | Рекомендуемая модель | Причина |
|----------------------|--------------------|----------|
| Проверка первой цепочки | `gpt-5.5` | 23 марта 2026 успешно протестирована в продакшн, лучший вариант для начальной проверки связи LangChain с Crazyrouter |
| Сложные длинные тексты и цепочки | `claude-opus-4-8` | Подходит для сложных объяснений, суммаризации и тяжёлых задач рассуждения |
| Gemini запасной | `gemini-3.1-pro` | Второй путь для проверки совместимости |
| Векторный поиск | `text-embedding-3-large` | Используйте для базовой проверки embedding |

## Лучшие практики настройки Token

| Настройка | Рекомендация | Описание |
|-----------|-------------|----------|
| Специальный token | Обязательно | Не используйте один token для LangChain и настольного клиента |
| Белый список моделей | Очень рекомендуется | Сначала разрешайте только чат-модель + embedding-модель |
| Лимит квоты | Очень рекомендуется | Цепочки, RAG, Agent увеличивают расход |
| Разделение окружений | Рекомендуется | dev / staging / production должны иметь отдельные token |
| Утечка секретов | Сразу сменить | Не выкладывайте ключи в Git; при утечке сразу смените ключ |

## Чек-лист валидации

- [ ] Настроено окружение Python или Node.js
- [ ] `OPENAI_API_KEY` корректно установлен
- [ ] `langchain-openai` или `@langchain/openai` установлены
- [ ] Для чат-модели задан `base_url` / `baseURL` как `https://api.crazyrouter.com/v1`
- [ ] Первый запрос `Reply only OK` успешно возвращён
- [ ] В логах Crazyrouter видно соответствующий запрос
- [ ] При использовании embeddings embedding-модель разрешена
- [ ] При использовании RAG пройдена валидация на минимальном наборе текста

## Частые ошибки и их исправление

| Симптом | Причина | Исправление |
|---------|---------|-------------|
| 401 unauthorized | `OPENAI_API_KEY` некорректен, истёк или скопирован с ошибкой | Сгенерируйте новый token и настройте переменные среды заново |
| 404 | Ошибка в `base_url` / `baseURL` или отсутствует `/v1` | Замените на `https://api.crazyrouter.com/v1` |
| `model not found` | Неправильное имя модели или token не разрешён | Используйте подтверждённую модель `gpt-5.5` и проверьте белый список |
| Ошибка embeddings | Не разрешена embedding-модель | Добавьте `text-embedding-3-large` к token |
| RAG не запускается | Использовано слишком много компонентов сразу | Сначала используйте одиночный чат, затем добавляйте по слоям |
| Быстрый расход | Цепочки, поиск, многократные Agent | Сократите цепочку и контролируйте лимит token отдельно |

## FAQ

### Какой протокол использовать для интеграции LangChain с Crazyrouter?

Используйте преимущественно совместимый с OpenAI протокол.

### Что указать в Base URL?

Укажите `https://api.crazyrouter.com/v1`.

### Какой пакет использовать в Python?

Предпочтительно `langchain-openai`.

### Какой пакет использовать в JavaScript / TypeScript?

Предпочтительно `@langchain/openai`.

### Почему не рекомендуется сразу подключать Agent или масштабный RAG?

Потому что сложные цепочки в LangChain значительно увеличивают стоимость диагностики ошибок. Сначала наладьте минимальный чат, дальше постепенно расширяйте, это самый надёжный подход.

</Note>
