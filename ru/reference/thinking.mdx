# AI поле мышления

На этой странице приведены только те способы раскрытия thinking / reasoning, которые `2026-03-22` уже прошел проверку в производственной среде Crazyrouter.

Ключевой момент: различные протоколы раскрывают "мышление" по-разному.

- Ответы OpenAI скорее возвращают отдельный элемент `reasoning`
- Сообщения Claude нативно возвращают блок `thinking`
- В Gemini Native сейчас проще судить об активности мышления через `usageMetadata.thoughtsTokenCount`

## Проверенные поля

| Модель | Протокол | Проверенное поле или признак | Описание |
|--------|----------|-----------------------------|----------|
| `gpt-5.5` | Ответы | `output[].type = "reasoning"` | Можно использовать вместе с `summary` для получения показываемого резюме |
| `claude-opus-4-8` | Anthropic Messages | `content[].type = "thinking"` | Возвращается совместно с блоком `text` |
| `gemini-3.1-pro` | Gemini Native | `usageMetadata.thoughtsTokenCount` | Означает, что thinking budget реально израсходован |

<Note>
  В ходе текущей проверки, `gpt-5.5` Chat Completions с `message.reasoning_content` не возвращал стабильное и надежное содержимое, поэтому это поле не считается наблюдаемым в данном списке.
</Note>

## GPT: Ответы, элемент `reasoning`

```json
{
  "output": [
    {
      "id": "rs_xxx",
      "type": "reasoning",
      "encrypted_content": "...",
      "summary": [
        {
          "type": "summary_text",
          "text": "..."
        }
      ]
    },
    {
      "type": "message",
      "content": [
        {
          "type": "output_text",
          "text": "最终回答"
        }
      ]
    }
  ]
}
```

Способ извлечения:

```python
response = client.responses.create(
    model="gpt-5.5",
    input="Which is larger, 9.11 or 9.9?",
    reasoning={"effort": "high", "summary": "detailed"}
)

for item in response.output:
    if item.type == "reasoning":
        for part in item.summary:
            if part.type == "summary_text":
                print("思考摘要:", part.text)
```

## Claude: блок `thinking`

```json
{
  "content": [
    {
      "type": "thinking",
      "thinking": "..."
    },
    {
      "type": "text",
      "text": "最终回答"
    }
  ]
}
```

Способ извлечения:

```python
message = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=320,
    thinking={
        "type": "enabled",
        "budget_tokens": 128
    },
    messages=[
        {"role": "user", "content": "Which is larger, 9.11 or 9.9?"}
    ]
)

for block in message.content:
    if block.type == "thinking":
        print("思考内容:", block.thinking)
    elif block.type == "text":
        print("回答:", block.text)
```

## Gemini: `thoughtsTokenCount`

В текущей проверке для Gemini Native наиболее стабильной точкой наблюдения является не видимый текст мышления в основном ответе, а поле расхода:

```json
{
  "usageMetadata": {
    "thoughtsTokenCount": 120
  }
}
```

Это показывает:

- Thinking budget действительно участвовал в генерации
- Запрос действительно привел к расходу thinking Token

Способ извлечения:

```python
data = response.json()
thoughts = data.get("usageMetadata", {}).get("thoughtsTokenCount", 0)
print("思考 Token:", thoughts)
```

## Важно при использовании

- Не предполагайте, что все модели возвращают весь процесс мышления в явном виде
- Не смешивайте поля thinking из разных протоколов
- Если требуется аудит, логирование или фронтэнд отображение, первоначально определите, следует ли читать `reasoning`, `thinking` или `thoughtsTokenCount` в зависимости от протокола
