## HTTP коды состояния

| Код состояния | Описание | Рекомендации по обработке |
|--------------|----------|--------------------------|
| 200 | Запрос выполнен успешно | - |
| 400 | Ошибка в параметрах запроса | Проверьте формат тела запроса и параметры |
| 401 | Аутентификация не пройдена | Проверьте корректность API Key |
| 403 | Недостаточно прав | Проверьте, имеет ли токен доступ к данной модели |
| 404 | Ресурс не найден | Проверьте путь URL |
| 429 | Превышена частота запросов | Понизьте частоту запросов или обратитесь к администратору |
| 500 | Ошибка сервера 5xx | Можно повторить попытку; возможна внутренняя ошибка сервера или ошибка 5xx от вышестоящего сервиса возвращается через наш сайт |
| 502 | Не удалось получить результат от шлюза или вышестоящего сервиса | Обычно означает, что запрос дошёл до этапа обращения к вышестоящему сервису, но не удалось получить корректный ответ или результат; можно повторить попытку |
| 503 | Сервис недоступен | Ведутся технические работы |

## Различия между 500 и 502

- `500` — более широкий тип ошибки на стороне сервера. В CrazyRouter это может означать как внутреннюю ошибку на нашем сайте, так и прямой возврат `5xx` от вышестоящего сервиса, который передается через наш сайт клиенту.
- `502` — более конкретный код, обычно означает, что запрос дошел до шлюза CrazyRouter или этапа обращения к вышестоящему сервису, но CrazyRouter не смог получить корректный ответ, например, вышестоящий сервис недоступен, возвращён некорректный шлюзовый ответ или не удалось получить результат по адресу задачи.
- Если проблемы подобного рода возникают регулярно:
  - При массовых `502` рекомендуется в первую очередь проверить доступность вышестоящих каналов, сетевую связность и доступность URL с результатами.
  - Массовые `500` требуют дополнительного анализа ошибок и логов; только при явном указании на внутренние `site_internal` или ошибках типа panic это следует считать исключительно проблемой самого CrazyRouter.

## Общие рекомендации по обработке ошибок

<Warning>
  При получении ошибки 429 не выполняйте повторные попытки немедленно. Рекомендуется использовать стратегию экспоненциального отката (Exponential Backoff): начать с ожидания 1 секунды, при каждом повторе увеличивать время ожидания вдвое.
</Warning>

```python
import time
import requests

def request_with_retry(url, headers, json_data, max_retries=3):
    for i in range(max_retries):
        response = requests.post(url, headers=headers, json=json_data)
        if response.status_code == 429:
            wait = 2 ** i
            print(f"频率限制，等待 {wait} 秒后重试...")
            time.sleep(wait)
            continue
        return response
    return response
```
