## Сценарии использования

Когда клиенту необходимо мониторить каждый API Key, рекомендуется использовать связанные административные интерфейсы Crazyrouter, а не напрямую обращаться к `sk-xxx` на стороне приложений:

- Получение списка API Key текущего аккаунта
- Запрос логов с фильтрацией по диапазону дат, названию Key, названию модели
- Получение суммарного расхода по отдельному Key
- Пересчёт расходов в доллара США на основе системного курса

<Note>
  Для административного интерфейса используется аутентификация пользователя, а не бизнес-токен для вызова моделей.
</Note>

<Warning>
  Все представленные аккаунты и административные интерфейсы (включая `/api/token/*`, `/api/log/*` и `/api/user/self`) должны обращаться к `https://crazyrouter.com`. `https://api.crazyrouter.com` предназначен только для API моделей/медиа, некорректное использование приведёт к `404 api_only_endpoint`.
</Warning>

## Способы аутентификации

Административный интерфейс обязательно требует следующие два заголовка запроса:

```text
Authorization: Bearer {access_token}
New-Api-User: {user_id}
```

- `access_token`: токен доступа, сгенерированный после входа пользователя, используется для консоли/админ-интерфейса
- `New-Api-User`: ID текущего пользователя, должен совпадать с пользователем `access_token`
- `sk-xxx`: бизнес-токен вызова, используется только для работы с моделями, не применяется для административных интерфейсов, таких как `/api/token/*`, `/api/log/*`

## Рекомендуемый порядок подключения

Рекомендуется использовать следующий порядок:

1. Вызвать `/api/token/` для получения списка Key текущего аккаунта
2. По инструкции `token_name` запросить подробные логи Key через `/api/log/self`
3. Вызвать `/api/log/self/stat` для получения суммарного лимита по тем же условиям
4. Вызвать `/api/status` для получения `quota_per_unit`
5. Использовать `quota / quota_per_unit` для пересчёта расходов в долларах США

## 1. Получение списка API Key

```bash cURL
curl "https://crazyrouter.com/api/token/?p=1&page_size=100" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 485"
```

Пример ответа:

```json
{
  "success": true,
  "message": "",
  "data": {
    "page": 1,
    "page_size": 100,
    "total": 1,
    "items": [
      {
        "id": 409,
        "name": "gptai",
        "key": "sk-xxxxxxxxxxxxxxxx",
        "status": 2,
        "used_quota": 16605808,
        "model_limits_enabled": true,
        "model_limits": "kimi-k2.5"
      }
    ]
  }
}
```

Рекомендуется сохранять следующие поля для дальнейшего мониторинга:

- `id`
- `name`
- `status`
- `used_quota`
- `model_limits_enabled`
- `model_limits`

## 2. Запрос логов по отдельному Key

Через `/api/log/self` можно получить свои логи расходов; рекомендуется указывать минимум:

- `type`
- `token_name`
- `start_timestamp`
- `end_timestamp`
- `p`
- `page_size`

Пример:

```bash cURL
curl "https://crazyrouter.com/api/log/self?type=2&token_name=gptai&start_timestamp=1771334901&end_timestamp=1772309095&p=1&page_size=5" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 485"
```

Пример ответа:

```json
{
  "success": true,
  "message": "",
  "data": {
    "page": 1,
    "page_size": 5,
    "total": 4988,
    "items": [
      {
        "created_at": 1772308747,
        "token_name": "gptai",
        "model_name": "deepseek-chat",
        "quota": 3188,
        "cost_usd": 0.006376,
        "prompt_tokens": 884,
        "completion_tokens": 397,
        "use_time": 16.48,
        "is_stream": true,
        "ip": "203.0.113.10",
        "other": {
          "client": "openai-python",
          "request_id": "req_xxx",
          "request_method": "POST",
          "request_path": "/v1/chat/completions",
          "http_status": 200,
          "discount": 0
        }
      }
    ]
  }
}
```

### Описание ключевых полей

| Поле               | Описание                              |
|--------------------|---------------------------------------|
| `token_name`    | Какой бизнес-ключ сработал             |
| `model_name`    | Фактическая тарифная модель            |
| `quota`    | Размер снятого за запрос системного лимита |
| `cost_usd`    | Пересчитанная сумма в долларах США за запрос |
| `prompt_tokens`    | Токены на вводе                        |
| `completion_tokens`    | Токены на выводе                       |
| `use_time`    | Время выполнения запроса (в секундах)  |
| `other.request_id`    | ID запроса, подходит для трекинга      |
| `other.client`    | Идентификатор клиентского вызова       |
| `other.request_path`    | Конкретный путь вызванного интерфейса  |
| `other.http_status`    | Код статуса ответа от верхнего уровня  |

<Note>
  `cost_usd` показывает расходы в долларах США согласно системному курсу, формула пересчёта — `quota / quota_per_unit`. Если в вашей продакшн-среде это поле пока не поддерживается, можно сделать пересчёт вручную по суммарному лимиту.
</Note>

<Warning>
Неудавшиеся одиночные запросы не расходуют средства — `quota` / `cost_usd` в логах должны быть равны 0. Но в режиме Agent, workflow, цепочке вызовов или автопрограммировании через IDE одна операция пользователя может разбиваться на несколько вызовов моделей: если предыдущий запрос завершился успешно и только один из последующих потерпел неудачу, успешные запросы всё равно засчитывают расход токенов. Для поиска необычных затрат необходимо сверять по каждому отдельному запросу лога, а не только по тому, завершилась ли задача ошибкой.
</Warning>

## 3. Суммарный расход

Если не требуется построчное логирование, а нужно только мониторинговая панель или ежедневный отчёт, используйте интерфейс суммирования:

```bash cURL
curl "https://crazyrouter.com/api/log/self/stat?type=2&token_name=gptai&start_timestamp=1771334901&end_timestamp=1772309095" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 485"
```

Пример ответа:

```json
{
  "success": true,
  "message": "",
  "data": {
    "quota": 16605808,
    "rpm": 0,
    "tpm": 0
  }
}
```

Где:

- `quota`: суммарный расход по заданным условиям
- `rpm`, `tpm`: зарезервированные поля для мониторинга

## 4. Баланс текущего аккаунта

Если клиенту нужно не только мониторить отдельные бизнес-ключи, но и отображать текущий баланс Crazyrouter в своей админ-панели — используйте `/api/user/self`.

Заголовки запроса совпадают с другими административными интерфейсами:

```bash cURL
curl "https://crazyrouter.com/api/user/self" \
  -H "Authorization: Bearer your_access_token" \
  -H "New-Api-User: 4004"
```

Пример ответа:

```json
{
  "success": true,
  "message": "",
  "data": {
    "id": 4004,
    "username": "google_4004",
    "quota": 11000000,
    "used_quota": 0,
    "request_count": 0,
    "group": "default"
  }
}
```

Ключевые поля:

| Поле               | Описание                                         |
|--------------------|--------------------------------------------------|
| `quota`    | Текущий остаток лимита (внутренняя система quota) |
| `used_quota`    | Всего использовано лимита (quota)                 |
| `request_count`    | Количество запросов                              |
| `group`    | Группа текущего аккаунта                         |

Метод пересчёта:

```text
balance_usd = quota / quota_per_unit
used_usd = used_quota / quota_per_unit
```

Пример:

```text
quota = 11000000
quota_per_unit = 500000

balance_usd = 11000000 / 500000 = 22
```

То есть, баланс из примера равен:

```text
$22.00
```

<Note>
  `/api/user/self` лучше подходит для «текущего общего баланса», а `/api/log/self` и `/api/log/self/stat` — для аналитики по расходам: по времени, ключам или моделям.
</Note>

## 5. Пересчёт расходов в доллары США

Параметры для пересчёта доступны через публичный интерфейс `/api/status`:

```bash cURL
curl "https://api.crazyrouter.com/api/status"
```

В ответе смотрите:

```json
{
  "success": true,
  "message": "",
  "data": {
    "quota_per_unit": 500000,
    "quota_display_type": "USD",
    "usd_exchange_rate": 7.3
  }
}
```

Формула пересчёта:

```text
cost_usd = quota / quota_per_unit
```

Пример:

```text
16605808 / 500000 = 33.211616 USD
```

## Пример интеграции на Python

```python
import requests

BASE_URL = "https://crazyrouter.com"
ACCESS_TOKEN = "your_access_token"
USER_ID = "485"
TOKEN_NAME = "gptai"

headers = {
    "Authorization": f"Bearer {ACCESS_TOKEN}",
    "New-Api-User": USER_ID,
    "User-Agent": "Mozilla/5.0",
}

token_resp = requests.get(
    f"{BASE_URL}/api/token/",
    params={"p": 1, "page_size": 100},
    headers=headers,
    timeout=30,
)
token_resp.raise_for_status()
tokens = token_resp.json()["data"]["items"]

log_resp = requests.get(
    f"{BASE_URL}/api/log/self/stat",
    params={
        "type": 2,
        "token_name": TOKEN_NAME,
        "start_timestamp": 1771334901,
        "end_timestamp": 1772309095,
    },
    headers=headers,
    timeout=30,
)
log_resp.raise_for_status()
quota = log_resp.json()["data"]["quota"]

status_resp = requests.get(f"{BASE_URL}/api/status", timeout=30)
status_resp.raise_for_status()
quota_per_unit = status_resp.json()["data"]["quota_per_unit"]

cost_usd = quota / quota_per_unit

print("tokens:", [item["name"] for item in tokens])
print("quota:", quota)
print("cost_usd:", round(cost_usd, 6))
```

## Рекомендации по мониторингу

Для мониторинга на стороне клиента рекомендуется строить отчёты как минимум по следующим срезам:

- По `token_name`: число вызовов, суммарный лимит, суммарные расходы
- По `model_name`: распределение по моделям
- По `other.request_path`: разделение по типам интерфейсов `/v1/chat/completions`, `/v1/responses` и др.
- По `other.http_status`: процент успешных и неудачных вызовов
- По `other.request_id`: отслеживание цепочки для диагностики

## Часто задаваемые вопросы

### Почему административные интерфейсы нельзя вызывать напрямую через `sk-xxx`?

Потому что `sk-xxx` — это бизнес-токен, проверяемый в middleware `TokenAuth`. Административные интерфейсы вроде `/api/token/*`, `/api/log/self*` требуют аутентификации пользователя: заголовки `access_token` и `New-Api-User`.

### Можно ли получить свои логи по конкретному Key?

Да. Рекомендуется фильтрация по `token_name` для отбора `/api/log/self` и `/api/log/self/stat`.

### Можно ли получить сумму расходов через API?

Если на сервере поддерживается поле `cost_usd`, то траты по каждому запросу сразу доступны в логах. Для суммарных значений рекомендуется пересчитывать с помощью `quota / quota_per_unit` — результат совпадает с консолью.
