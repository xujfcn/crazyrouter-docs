# Псевдоним для запроса видео-задачи

```
GET /v1/video/generations/{task_id}
```

Используется для запроса статуса задачи, отправленной через совместимый видео-маршрут. Это сопряжённый маршрут для запроса к `/v1/video/generations`.

## Аутентификация

```http
Authorization: Bearer YOUR_API_KEY
```

## Пример запроса

```bash cURL
curl https://api.crazyrouter.com/v1/video/generations/video_task_abc123   -H "Authorization: Bearer YOUR_API_KEY"
```

## Типичный успешный ответ

```json
{
  "code": "success",
  "message": "",
  "data": {
    "id": "video_task_abc123",
    "task_id": "video_task_abc123",
    "status": "SUCCESS",
    "result_url": "https://media.crazyrouter.com/task-artifacts/example.mp4",
    "artifact_url": "https://media.crazyrouter.com/task-artifacts/example.mp4"
  }
}
```

## Ответ о несуществующей задаче, проверенный локально

В локальной среде `http://127.0.0.1:4000` при запросе несуществующей задачи будет возвращено:

```json
{
  "code": "task_not_exist",
  "message": "task_not_exist",
  "data": null
}
```

## Часто встречающиеся статусы

| Статус | Описание |
|--------|----------|
| `queued` | Задача отправлена или находится в очереди |
| `processing` | Задача в обработке |
| `SUCCESS` | Задача выполнена |
| `failed` | Задача не выполнена |

<Note>
Поля результата окончательного выполнения могут немного отличаться для разных видео-моделей и разных источников. Самый надёжный способ: создание и запрос лучше всего держать в одном совместимом маршруте и по возможности сначала читать `data.artifact_url` или `data.result_url`.
</Note>
