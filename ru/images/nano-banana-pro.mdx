# Nano Banana Pro

```
POST /v1/images/generations
```

Используйте `nano-banana-pro` для генерации изображений и редактирования на основе референсов; вся работа по открытому протоколу в стиле `OpenAI Images API`.

<Warning>
  Запросы на генерацию изображений, редактирование картинок, работу с несколькими референсами обычно занимают больше времени. Для интеграций в продакшене рекомендуем использовать основной маршрут `https://api.crazyrouter.com/v1`, полный endpoint для генерации — `https://api.crazyrouter.com/v1/images/generations`. Вход в аккаунт, пополнение и консоль — всё как прежде через `https://crazyrouter.com`.
</Warning>

## Что охватывает эта страница

- Эта страница покрывает только `nano-banana-pro` / `nano-banana-pro`
- Вход для пользовательских запросов всегда `POST /v1/images/generations`
- Поле входного изображения — всегда `image_input`
- По умолчанию советуем использовать URL по открытому протоколу `image_input`; для указанных серых аккаунтов дополнительно поддерживаются dataURL, raw Base64 и трёхкартинный multipart-редактор
- `data:` / Base64 / multipart — расширение Crazyrouter, не означает, что все провайдеры наверху его поддерживают
- На бекенде может стоять Gemini, Vertex или другой провайдер, но технические детали провайдера не являются частью клиентского протокола
- Не передавайте с пользовательской стороны параметры `generationConfig`, `imageConfig`, `imageOutputOptions`, `image_output_options` — Crazyrouter сам конвертирует их из общих параметров

## Статус возможностей

| Возможность / спецификация | Статус | Описание |
|------|------|------|
| `T2I` | `Beta` | В прошлом покрывалось, но сейчас артефакты доступны только для редактирования и по референсным путям |
| `I2I + 1K` | `Verified` | Редактирование одной картинки в live закрыто |
| `I2I + 4K` | `Verified` | `4K + 21:9 + png/jpeg/jpg` live закрыто |
| `Reference + 1..2 refs` | `Verified` | `2` — картинки в live закрыто |
| `11257` (серый режим): dataURL / raw Base64 | `Verified` | В продакшене канал 304 проверен для одной и трёх картинок `image_input` |
| `11257` (серый): трёхкартинный multipart | `Verified` | `/v1/images/edits` поддерживает `image`, `image[]`, `image[n]` |
| `2K` | `Beta` | Публичные артефакты ещё дополняются |
| Более высокий лимит по количеству картинок / точная граница `30 MiB` | `Beta` | В текущем контракте публично не обещается |

<Note>
  Страница цен использует ту же схему статусов: `Verified` означает, что минимальный live-функционал уже есть, `Beta` — что функция доступна, но публично валидация и границы ещё дополняются.
</Note>

## Уже верифицированные возможности

Ниже — выводы на основе исторической live-валидации и продакшен-грей `2026-08-18`:

- Официальный прямой Vertex `channel 318 (vertexsophie)` уже верифицирован:
  - Можно использовать `2` референс-изображений
- Проверены локальный порт `4000` и фиксированный `channel 318`:
  - Одна референсная картинка `WEBP` по URL — работает
  - Одна референсная картинка `JPEG` по URL — работает
  - `2` картинки `PNG` по URL — работают
  - Доступен `resolution: "1K"`
  - Доступен `resolution: "4K"`
  - Доступен `aspect_ratio: "1:1"`
  - Доступен `aspect_ratio: "21:9"`
  - Доступен `output_format: "png"`
  - Доступен `output_format: "jpg"`
- Ответ может напрямую возвращать `data[].url`

Для указанного серого аккаунта `11257` прошёл валидацию на продакшен-канале `304`:

- `/v1/images/generations` — модель `image_input` — поддерживает dataURL, raw Base64 и мультикартинный ввод
- `/v1/images/edits` поддерживает multipart для `image`, `image[]`, `image[n]`
- Исходное изображение, картинка с аннотациями и референсы могут по порядку загрузки объединяться в трёхкартинный редактор

Следующие возможности нельзя считать полностью гарантированными для внешнего клиента:

- Точный лимит по многокартинности — `8` или больше
- `2K`
- Точный лимит URL для больших файлов
- Точные границы `30 MiB`
- Другие комбинации `aspect_ratio`
- Точные семантические границы для `output_compression`

<Note>
  По умолчанию публичный протокол для обычных аккаунтов — только URL. Base64, dataURL и multipart-редактор — только для допущенных серых аккаунтов; чтобы получить доступ, сперва убедитесь, что ваш аккаунт в списке.
</Note>

## Параметры запроса

| Параметр | Тип | Обязателен | Описание |
|------|------|------|------|
| `model` | string | Да | Рекомендуется `nano-banana-pro`; также поддерживается `nano-banana-pro` |
| `prompt` | string | Да | Инструкция генерации или редактирования |
| `image_input` | string или string[] | Нет | По умолчанию используйте URL референса; серый аккаунт может также использовать dataURL / raw Base64, сейчас три картинки уже проверены |
| `resolution` | string | Нет | Официально гарантируется `1K`, `4K` |
| `aspect_ratio` | string | Нет | Официально гарантируется `1:1`, `21:9` |
| `output_format` | string | Нет | Официально гарантируется `png`, `jpeg` / `jpg` |
| `output_compression` | integer | Нет | `0-100`, для управления качеством JPEG |
| `n` | integer | Нет | Количество генерируемых изображений, по умолчанию `1` |

### Актуальный статус многокартинности

- `2` картинок: уже проверено
- `11257` три картинки (серый): уже проверено
- Большее число: максимумы от провайдера уточняются, не гарантируется

### Разъяснение маршрутизации

- Один референс — обычный маршрут
- По умолчанию многокартинный запрос идёт только к официальному carrier `Gemini / Vertex`; серые аккаунты могут выбрать протестированный carrier
- Это внутренняя политика на сервере; клиентский протокол не меняется

### Трёхкартинный multipart для серых

Аккаунт в серой зоне `11257` может использовать `/v1/images/edits`:

```bash
curl -X POST https://api.crazyrouter.com/v1/images/edits \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "model=nano-banana-pro" \
  -F "prompt=以第一张为原图，第二张为批注图，第三张为参考图，仅修改批注区域" \
  -F "image[]=@original.png" \
  -F "image[]=@annotation.png" \
  -F "image[]=@reference.png"
```

Порядок изображений определяется последовательностью в клиентском запросе. Картинка с аннотациями сейчас является лишь визуальным референсом; точная маска по пикселям (GPT-style) не гарантируется.

## Пример ответа

По умолчанию рекомендуется непосредственно использовать `data[].url`:

```json
{
  "created": 1774846705,
  "data": [
    {
      "url": "https://media.crazyrouter.com/task-artifacts/2026/03/30/sync-image/20260331073825672515332JyP6hAcs-1.png"
    }
  ]
}
```

Чтобы получить готовый результат, просто читайте `data[0].url`. Сейчас Crazyrouter архивирует inline-изображения от провайдера по URL и отдаёт их клиенту.

## Известные ограничения

- Для обычных аккаунтов не принимаются `image`, `data:` / Base64 или multipart-изображения
- Для серых аккаунтов максимум три картинки сейчас проверено, больше не гарантируется
- Этот документ не гарантирует точные URL-лимиты по `30 MiB`
- Не гарантируется, что все параметры и соотношения, приведённые в примерах, уже полностью доступны публично
