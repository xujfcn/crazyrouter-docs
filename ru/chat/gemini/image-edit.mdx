# Gemini Image Editing

```
POST /v1/images/generations
```

The customer-facing Gemini / Nano Banana editing contract is the OpenAI-compatible Images API. Use `POST /v1/images/generations` for URL references and, for designated gray accounts, data URLs, raw Base64, or multipart editing through `POST /v1/images/edits`.

<Warning>
  Provider-native `generateContent` details are internal. Use the public Images API contract; gray-only input extensions must not be assumed for non-gray accounts.
</Warning>

<Note>
  See [Nano Banana Pro](/ru/images/nano-banana-pro) for the current gray-release limits and examples.
</Note>

---

## Current Recommendation

1. If your goal is Gemini text-to-image, use [Gemini Image Generation](/ru/chat/gemini/image-gen)
2. If your goal is a currently usable reference-image editing route, start with [Nano Banana 2](/ru/images/nano-banana-2)
3. If you must evaluate `nano-banana`, follow the controlled-test guidance on [Nano Banana](/ru/images/nano-banana)
4. Use `POST /v1/images/generations` as the public Nano Banana entry point; see the model page for gray-only input extensions

---

## Retest Template

For public integration, use the Images API examples on the model page. Native `generateContent` is an internal provider path:

```bash
curl "https://api.crazyrouter.com/v1beta/models/nano-banana-2:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {"text": "Edit this image: change the background to blue and keep the main square visible. Return image output."},
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "iVBORw0KGgoAAA..."
            }
          }
        ]
      }
    ],
    "generationConfig": {
      "responseModalities": ["IMAGE"]
    }
  }'
```
