# Gemini понимание изображений

```
POST /v1beta/models/{model}:generateContent
```

По состоянию на `2026-04-08`, повторное тестирование порта Crazyrouter нашего сайта и локального `4000` показывает:

- `gemini-3.1-pro` может стабильно читать изображение через `inlineData` и возвращать текстовое описание
- Для удалённых изображений в виде URL `fileData.fileUri` на разных каналах часто возникают ошибки захвата и аномалии тела ответа от вышестоящего сервера
- Поэтому для понимания изображений в текущем документе рекомендуем использовать `inlineData` как главный метод

---

## Проверенный минимальный запрос

```bash
curl "https://api.crazyrouter.com/v1beta/models/gemini-3.1-pro:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "BASE64_PNG_DATA"
            }
          },
          {
            "text": "请用一句中文描述这张图片里有什么。"
          }
        ]
      }
    ]
  }'
```

Ключевые формы фактического ответа в рабочей среде:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "这张图片展示了多种鲜艳色彩平滑过渡的渐变效果。"
          }
        ]
      }
    }
  ]
}
```

## Основные моменты запроса

- Для понимания изображений отдавайте предпочтение `inlineData`
- `mimeType` должен точно соответствовать реальному формату изображения, например, `image/png`, `image/jpeg`
- В `data` указывайте только содержимое Base64, не добавляйте префикс `data:image/...;base64,`
- Если у вас есть только URL удалённого изображения, не используйте его как основной маршрут понимания изображений Gemini
