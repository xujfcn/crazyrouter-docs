# Режим мышления GPT-5

На этой странице документируется только поведение рассуждений GPT, прошедшее повторную валидацию против продакшена Crazyrouter на `2026-03-22`.

Текущий основной пример использует:

- `gpt-5.5`
- `POST /v1/responses`

<Note>
  Claude в настоящее время не поддерживает `POST /v1/responses`. Если вы интегрируете Claude, используйте `POST /v1/messages` или `POST /v1/chat/completions` вместо структуры запроса на этой странице.
</Note>

## Проверенная форма ответа

Проверенные значения `output.type`:

```json
["reasoning", "message"]
```

Обычная структура элемента `reasoning`:

```json
{
  "id": "rs_xxx",
  "type": "reasoning",
  "encrypted_content": "...",
  "summary": [
    {
      "type": "summary_text",
      "text": "..."
    }
  ]
}
```

Окончательный ответ возвращается через элемент `message`:

```json
{
  "type": "message",
  "content": [
    {
      "type": "output_text",
      "text": "..."
    }
  ]
}
```

---

## Параметр `reasoning`

| Поле | Тип | Описание |
|-------|------|-------------|
| `effort` | строка | Интенсивность рассуждений. Проверенные значения включают `low`, `medium` и `high` |
| `summary` | строка | Гранулярность сводки. `concise` и `detailed` были повторно проверены |

### Практическое правило

- Если вам нужна только более сильная аргументация, отправьте `effort`
- Если вам нужна контролируемая сводка рассуждений, отправьте оба `effort` и `summary`

В текущей пере проверке:

- только с `effort`, элемент `reasoning` существовал, но `summary` мог быть пустым массивом
- с `summary: "detailed"`, `summary_text` возвращался стабильно

## Извлечение сводки мышления

```python Python
response = client.responses.create(
    model="gpt-5.5",
    input="Design a high-concurrency message queue architecture.",
    reasoning={
        "effort": "high",
        "summary": "detailed"
    }
)

for item in response.output:
    if item.type == "reasoning":
        for part in item.summary:
            if part.type == "summary_text":
                print("Thinking summary:", part.text)
    elif item.type == "message":
        for content in item.content:
            if content.type == "output_text":
                print("Final answer:", content.text)
```

## Потоковое мышление

В производстве были повторно подтверждены следующие имена SSE-событий Responses:

- `response.reasoning_summary_part.added`
- `response.reasoning_summary_text.delta`
- `response.reasoning_summary_text.done`
- `response.output_text.delta`
- `response.output_text.done`
- `response.completed`

Пример:

```python Python
stream = client.responses.create(
    model="gpt-5.5",
    input="Explain briefly why 9.9 is larger than 9.11.",
    reasoning={
        "effort": "high",
        "summary": "detailed"
    },
    stream=True
)

for event in stream:
    if event.type == "response.reasoning_summary_text.delta":
        print(f"[Thinking summary] {event.delta}", end="")
    elif event.type == "response.output_text.delta":
        print(event.delta, end="")
```

## Текущая рекомендация

- Если вам нужно видимое поле рассуждений, используйте предпочтительно `gpt-5.5` с API Responses
- Не рассматривайте `gpt-5.5` Chat Completions `reasoning_content` как основной контракт
- Если вас интересует только окончательный ответ, Chat Completions с `reasoning_effort` тоже подходит

<Warning>
  Режим рассуждений увеличивает как задержку, так и расход токенов. Более высокий `effort`, как правило, стоит дороже.
</Warning>
