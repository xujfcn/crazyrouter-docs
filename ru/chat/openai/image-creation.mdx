# Генерация изображений в чате

```
POST /v1/chat/completions
```

На 23 марта 2026 года производственные проверки с Crazyrouter показали:

- `gpt-4o` возвращает `200`, но `message.content` — это обычный текст, а не стандартное multipart изображение
- `gpt-image-2` также возвращает `200`, но текущий формат ответа всё ещё представляет собой текст или Markdown с блоком параметров, идентификатором и ссылкой на предпросмотр, а не стандартную структуру OpenAI `image_url` типа multipart
- Если вам нужен стабильный машиночитаемый вывод изображения, рекомендуемая ныне схема — [`/v1/images/generations`](/ru/images/gpt-image) с `gpt-image-2`; для моделей изображений Grok смотрите [`Grok Image Models`](/ru/images/grok)
- Если вам нужно редактирование изображений по референсному изображению или ввод нескольких изображений, не продолжайте использовать Nano Banana фамилию в качестве стабильной точки входа `/v1/images/generations`. Начните с нативной Gemini схемы, задокументированной в [`Nano Banana 2`](/ru/images/nano-banana-2); [`Nano Banana`](/ru/images/nano-banana) сейчас доступна только для контролируемого тестирования

<Warning>
  Не парсите текущий ответ генерации изображений в чате в Crazyrouter, как если бы он был стандартным multipart OpenAI `content: [{type: "image_url", ...}]`.
</Warning>

## Текущее воспроизводимое поведение чата

Следующий запрос был отправлен в `gpt-image-2` на проде и вернул `200`:

```bash
curl https://api.crazyrouter.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-image-2",
    "messages": [
      {
        "role": "user",
        "content": "Generate an image of a red square on a white background."
      }
    ],
    "max_tokens": 512
  }'
```

Наблюдаемый `message.content` был строкой примерно такой формы:

```text
{
  "prompt": "Generate an image of a red square on a white background.",
  "ratio": "1:1",
  "n": 1
}

ID: ...
Data Preview: https://...
```

Это значит, что текущий чат путь ведёт себя скорее как вывод задачи по изображению в текстовой обёртке, а не как стандартизированный объект multipart изображения.

## Стабильный путь: Images API

Если вам нужна программная загрузка изображений, используйте:

```bash
curl -X POST https://api.crazyrouter.com/v1/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "A red square on a white background",
    "size": "1024x1024",
    "quality": "low",
    "output_format": "png"
  }'
```

Текущий стабильный путь `gpt-image-2` использует основной маршрут изображений `https://api.crazyrouter.com/v1`. Ответы обычно содержат:

- `data[0].url`

`gpt-image-2` принимает `response_format="url"` и `response_format="b64_json"` как поля для обратной совместимости, но новые интеграции должны использовать `output_format="png"`, `"jpeg"` или `"webp"` для выбора формата файла изображения.

Таким образом, стабильным маршрутом автоматизации всё ещё остаётся Images API, а не совместимость генерации изображений в чате.

<Note>
  Если вы только вручную тестируете, путь чата `gpt-image-2` всё ещё полезен для наблюдений. Если необходимо автоматизация на сервере, хранение или постобработка, используйте [`GPT Image docs`](/ru/images/gpt-image) или [`Grok Image Models`](/ru/images/grok). Если ваша задача зависит от редактирования изображений по референсу или от ввода нескольких изображений, начинайте с нативного Gemini маршрута, описанного в [`Nano Banana 2`](/ru/images/nano-banana-2). Не нужно продолжать рассматривать Nano Banana-фамилию `/v1/images/generations` как стабильную рекомендацию.
</Note>
