# Создать автодополнение чата

```
POST /v1/chat/completions
```

Генерирует ответ модели на основе переданного списка сообщений, поддерживаются как нестриминговые, так и стриминговые ответы.

На этой странице отражено только такое поведение, которое было проверено в производственной среде Crazyrouter — см. `2026-03-23`.

## Аутентификация

```text
Authorization: Bearer YOUR_API_KEY
```

## Основные параметры

| Параметр | Тип | Обязателен | Описание |
|------|------|------|------|
| `model` | string | Да | Имя модели, например `gpt-5.5`, `claude-opus-4-8`, `gemini-3.1-pro` |
| `messages` | array | Да | Список сообщений |
| `stream` | boolean | Нет | Включить стриминговый вывод |
| `max_tokens` | integer | Нет | Максимальное количество выходных токенов |
| `temperature` | number | Нет | Температура сэмплирования |
| `response_format` | object | Нет | Ограничения формата структурированного вывода |
| `tools` | array | Нет | Список инструментов |
| `tool_choice` | string\|object | Нет | Стратегия выбора инструментов |
| `stream_options` | object | Нет | Стриминговые дополнительные опции, например `include_usage` |

<Note>
  У разных моделей разные уровни поддержки опциональных параметров. При написании клиента следует опираться на стандартные поля и не предполагать, что все модели одинаково поддерживают одну и ту же группу расширенных параметров.
</Note>

## Нестрингинговый запрос

```bash cURL
curl https://api.crazyrouter.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-5.5",
    "messages": [
      {
        "role": "system",
        "content": "You are a helpful assistant."
      },
      {
        "role": "user",
        "content": "Explain artificial intelligence in one sentence."
      }
    ],
    "max_tokens": 64
  }'
```

Типичная структура ответа, возвращаемая в производстве на данный момент:

```json
{
  "object": "chat.completion",
  "model": "gpt-5.5",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "...",
        "reasoning_content": null,
        "tool_calls": null
      },
      "finish_reason": "stop"
    }
  ]
}
```

### Особенности и замечания

- `message.content` — самое стабильное финальное текстовое поле
- `message.tool_calls` появляется только при вызове инструмента
- `message.reasoning_content` может присутствовать как ключ, но сейчас его не стоит считать стабильно обязательным содержимым

## Стриминговый запрос

```bash cURL
curl https://api.crazyrouter.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-5.5",
    "messages": [
      {
        "role": "user",
        "content": "Explain AI in one short sentence."
      }
    ],
    "stream": true,
    "stream_options": {
      "include_usage": true
    },
    "max_tokens": 64
  }'
```

На этом этапе производственной проверки подтверждено:

- При стриминге возвращается `chat.completion.chunk`
- SSE отправляется по частям в формате `data: ...`
- Конец потока также — `data: [DONE]`

На данный момент получаемые фрагменты SSE выглядят так:

```text
data: {"object":"chat.completion.chunk","model":"gpt-5.5","choices":[{"delta":{"role":"assistant","content":"AI","reasoning_content":null,"tool_calls":null}}]}
```

```text
data: [DONE]
```

## Пример на Python

```python Python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="https://api.crazyrouter.com/v1"
)

stream = client.chat.completions.create(
    model="gpt-5.5",
    messages=[
        {"role": "user", "content": "Explain AI in one short sentence."}
    ],
    stream=True,
    stream_options={"include_usage": True},
    max_tokens=64
)

for chunk in stream:
    delta = chunk.choices[0].delta
    if delta.content is not None:
        print(delta.content, end="")
```
