# Alias de consulta de tarea de video

```
GET /v1/video/generations/{task_id}
```

Se utiliza para consultar el estado de una tarea enviada a través de la ruta de video compatible. Esta es la ruta de consulta complementaria de `/v1/video/generations`.

## Autenticación

```http
Authorization: Bearer YOUR_API_KEY
```

## Ejemplo de solicitud

```bash cURL
curl https://api.crazyrouter.com/v1/video/generations/video_task_abc123   -H "Authorization: Bearer YOUR_API_KEY"
```

## Respuesta típica exitosa

```json
{
  "code": "success",
  "message": "",
  "data": {
    "id": "video_task_abc123",
    "task_id": "video_task_abc123",
    "status": "SUCCESS",
    "result_url": "https://media.crazyrouter.com/task-artifacts/example.mp4",
    "artifact_url": "https://media.crazyrouter.com/task-artifacts/example.mp4"
  }
}
```

## Respuesta cuando la tarea no existe en la verificación local

En el entorno local `http://127.0.0.1:4000`, consultar una tarea inexistente devolverá:

```json
{
  "code": "task_not_exist",
  "message": "task_not_exist",
  "data": null
}
```

## Estados comunes

| Estado | Descripción |
|------|------|
| `queued` | Tarea enviada o en cola |
| `processing` | Tarea en proceso |
| `SUCCESS` | Tarea finalizada |
| `failed` | Tarea fallida |

<Note>
Los campos de resultados completos pueden variar ligeramente según el modelo de video y el origen. La práctica más estable es: crear y consultar tareas manteniéndose en la misma ruta de compatibilidad y dando prioridad a leer `data.artifact_url` o `data.result_url`.
</Note>
